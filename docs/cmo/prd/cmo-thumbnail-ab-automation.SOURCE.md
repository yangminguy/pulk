# YouTube 썸네일 9개 제작·A/B 테스트·성과 디벨롭 자동화 설계서

작성일: 2026-06-11  
목적: 썸네일을 단순 제작물이 아니라 **클릭 이유를 실험하고, 성과 데이터를 기반으로 계속 진화시키는 자동화 시스템**으로 설계한다.

---

## 0. 먼저 정리해야 할 핵심 결론

### 0-1. YouTube 공식 A/B 테스트의 현재 구조

YouTube Studio에는 제목/썸네일 A/B 테스트 기능이 있다.

공식 기능 기준:

- 한 번에 최대 3개 버전 테스트 가능
- 제목만, 썸네일만, 제목+썸네일 조합 테스트 가능
- 테스트 종료 후 가장 높은 **watch time share**를 만든 버전이 승자로 판단됨
- CTR만으로 승자를 판단하지 않음
- 테스트는 며칠에서 최대 2주 정도 걸릴 수 있음
- Shorts, 예약 라이브, 프리미어 등 일부 형식은 제한됨
- 현재 공식 설명상 Desktop YouTube Studio에서 사용하는 기능으로 안내됨

즉, YouTube 공식 A/B 테스트의 승자 판단 기준은 단순 클릭률이 아니라 **시청 시간이 포함된 품질 기반 성과**다.

---

### 0-2. 썸네일별 CTR을 API로 각각 확인할 수 있는가?

결론부터 말하면, **공식 YouTube API만으로는 YouTube Studio의 A/B 테스트 각 썸네일 버전별 CTR, 노출수, watch time share를 안정적으로 추출하는 공개 엔드포인트가 확인되지 않는다.**

공식 YouTube Analytics / Reporting API에서는 영상 단위의 썸네일 노출수와 썸네일 CTR 계열 지표를 제공한다.

예:

- `video_thumbnail_impressions`
- `video_thumbnail_impressions_ctr`

하지만 이 지표는 기본적으로 **영상 단위 reach 지표**이며, YouTube Studio의 A/B 테스트 내부에 들어간 A안/B안/C안 각각의 개별 실험 지표를 API로 직접 가져오는 구조는 공식 문서에서 확인되지 않는다.

따라서 자동화 가능 범위는 아래처럼 나뉜다.

| 항목 | 공식 API 자동화 가능 여부 | 설명 |
|---|---:|---|
| 썸네일 파일 업로드/교체 | 가능 | YouTube Data API `thumbnails.set` 사용 |
| 영상 단위 노출수/CTR 수집 | 가능 | YouTube Analytics/Reporting API reach 지표 사용 |
| 공식 A/B 테스트 시작 | 공개 API 기준 불확실/제한 | 공식 문서는 Studio UI 기반으로 안내 |
| 공식 A/B 테스트 각 버전별 CTR 추출 | 공개 API 기준 불확실/제한 | Studio 화면에서는 확인 가능하나 공개 API 엔드포인트 확인 어려움 |
| 공식 A/B 테스트 승자 자동 적용 | 공개 API 기준 불확실/제한 | Studio 내부 테스트 로직 의존 |
| 자체 순차 테스트 | 가능 | 썸네일을 일정 기간마다 API로 교체하고 기간별 성과 비교 |
| 완전한 동시 A/B/C 테스트 | 공식 기능은 가능, API 자동화는 제한 | API만으로 공식 테스트 생성·관리 불확실 |

---

### 0-3. 이 시스템의 현실적인 자동화 전략

가장 현실적인 방식은 2트랙이다.

#### Track A. YouTube 공식 A/B 테스트 활용

- 9개 썸네일 중 3개를 사람이 YouTube Studio에 등록
- 1주일 뒤 Studio에서 결과 확인
- 결과값을 자동화 시스템에 입력 또는 반자동 수집
- 승자/패자 분석
- 다음 3개 제작

장점:

- YouTube의 진짜 동시 A/B/C 테스트 사용
- watch time share 기반으로 더 품질 높은 승자 판단 가능

단점:

- 공식 API로 테스트 생성·버전별 지표 수집 자동화가 제한적

---

#### Track B. 자체 순차 테스트 자동화

- 썸네일 A를 2~3일 노출
- 썸네일 B로 API 교체 후 2~3일 노출
- 썸네일 C로 API 교체 후 2~3일 노출
- 각 기간의 영상 단위 CTR, 노출수, 조회수, 시청 지속 시간을 비교

장점:

- API 기반 자동화 가능
- 썸네일 교체와 성과 수집을 자동화할 수 있음

단점:

- 동시 A/B 테스트가 아니라 순차 테스트이므로 노출 환경, 요일, 시간, 알고리즘 흐름의 영향을 받음
- YouTube 공식 A/B 테스트보다 실험 신뢰도가 낮을 수 있음

## 1. 시스템 정의

이 시스템은 썸네일을 예쁘게 만드는 자동화가 아니다.

이 시스템은 다음을 자동화한다.

> **왜 이 영상을 클릭해야 하는가?**  
> 그 이유를 이미지, 문구, 제목에 일관되게 반영하고,  
> 9개 썸네일을 3개씩 테스트하면서,  
> 성과 데이터를 기반으로 클릭 이유를 계속 강화하는 시스템.

---

## 2. 썸네일 전략의 최상위 원칙

### 2-1. 1단계의 주인공은 이미지가 아니다

썸네일 1단계의 주인공은 이미지, 인물, 배경, 디자인이 아니다.

1단계의 주인공은 반드시 이것이다.

> **왜 이 영상을 클릭해야 하는가?**

썸네일에서 가장 먼저 보여야 하는 것은 클릭해야 할 이유다.

그 이유가 명확하다면, 나머지 요소는 없어도 된다.  
그 이유를 흐리게 만드는 요소는 제거해야 한다.

---

### 2-2. 이미지, 문구, 제목은 같은 이유를 말해야 한다

썸네일의 이미지, 썸네일 문구, 영상 제목은 서로 다른 이야기를 하면 안 된다.

세 요소는 모두 같은 클릭 이유를 강화해야 한다.

| 요소 | 역할 |
|---|---|
| 제목 | 클릭 이유를 언어로 제시 |
| 썸네일 문구 | 클릭 이유를 더 짧고 강하게 압축 |
| 썸네일 이미지 | 클릭 이유를 시각적으로 증명하거나 연상시킴 |

좋은 썸네일은 이런 구조다.

```text
제목이 던진 클릭 이유
↓
문구가 그 이유를 압축
↓
이미지가 그 이유를 증거·공감·궁금증으로 보여줌
↓
시청자는 “이건 봐야겠다”고 느낌
```

## 3. 썸네일 구성 요소별 클릭률 기여

| 구성 요소 | 비중 | 역할 |
|---|---:|---|
| 이미지 | 45% | 즉각적인 시각 반응, 공감, 증거, 궁금증 생성 |
| 문구 | 45% | 심리 자극, 이득/손해/궁금증 구조화 |
| 디자인 | 10% | 가독성, 시선 흐름, 모바일 식별성 보조 |

중요한 점:

- 디자인은 중요하지만 최우선이 아니다.
- 초보자는 디자인에 너무 많은 시간을 쓴다.
- 실제로는 이미지와 문구가 클릭 이유를 만든다.
- 디자인은 그 이유가 더 잘 보이게 돕는 역할이다.

## 4. 9개 썸네일 제작 시스템

9개를 만들 때는 단순히 비슷한 썸네일을 9개 만드는 것이 아니다.

9개 각각은 서로 다른 클릭 가설을 가져야 한다.

---

### 4-1. 9개 썸네일 매트릭스

| 번호 | 이미지 전략 | 문구 전략 | 클릭 가설 |
|---:|---|---|---|
| 1 | 확대 이미지 | 이득 문구 | 주인공이 명확하면 클릭한다 |
| 2 | 확대 이미지 | 손해 회피 문구 | 위험을 느끼면 클릭한다 |
| 3 | 확대 이미지 | 궁금증 문구 | 뭔지 궁금하면 클릭한다 |
| 4 | 증거 이미지 | 이득 문구 | 결과가 보이면 클릭한다 |
| 5 | 증거 이미지 | 손해 회피 문구 | 손실의 증거가 보이면 클릭한다 |
| 6 | 증거 이미지 | 궁금증 문구 | 증거 일부만 보이면 확인하려고 클릭한다 |
| 7 | 공감 이미지 | 이득 문구 | 내 상황의 해결책처럼 보이면 클릭한다 |
| 8 | 공감 이미지 | 손해 회피 문구 | 내 문제를 건드리면 클릭한다 |
| 9 | 공감 이미지 | 궁금증 문구 | 내 상황인데 답이 숨겨져 있으면 클릭한다 |

---

### 4-2. 3개씩 테스트하는 운영 방식

처음에는 서로 비슷한 3개가 아니라 **클릭 이유가 다른 3개**를 넣는다.

#### 1차 테스트

| 테스트안 | 유형 | 검증 목적 |
|---|---|---|
| A안 | 확대 이미지형 | 주인공 명확성이 클릭을 만드는지 확인 |
| B안 | 증거 이미지형 | 결과/증거가 클릭을 만드는지 확인 |
| C안 | 공감 이미지형 | 타깃 상황 공감이 클릭을 만드는지 확인 |

---

#### 2차 테스트

1차에서 이긴 방향을 세분화한다.

예:

1차에서 증거 이미지형이 이겼다면:

| 테스트안 | 유형 | 검증 목적 |
|---|---|---|
| D안 | 숫자 증거형 | 숫자가 가장 강한지 확인 |
| E안 | 전후 비교형 | 변화가 가장 강한지 확인 |
| F안 | 실제 화면 캡처형 | 현실감 있는 증거가 가장 강한지 확인 |

---

#### 3차 테스트

최종 승자 주변으로 미세 조정한다.

| 테스트안 | 유형 | 검증 목적 |
|---|---|---|
| G안 | 문구 축약형 | 더 짧은 문구가 잘 먹히는지 확인 |
| H안 | 이미지 확대형 | 더 강한 클로즈업이 먹히는지 확인 |
| I안 | 대비 강화형 | 감정/색/구도 대비가 먹히는지 확인 |

## 5. 클릭 이유 분석 프레임워크

클릭 이유 분석은 표면적인 분석으로 끝내면 안 된다.

반드시 다음 3단계를 거쳐야 한다.

---

### 5-1. 문구 구조 분석

문구가 어떤 심리를 자극하는지 분석한다.

| 문구 구조 | 자극 심리 | 예시 |
|---|---|---|
| 이득 제시 | 얻고 싶은 미래 | “3시간 일을 10분으로” |
| 손해 회피 | 잃고 싶지 않은 두려움 | “이러면 광고비 샙니다” |
| 비밀/은닉 | 모르는 것을 알고 싶은 욕구 | “여기 하나만 바꿨습니다” |
| 반전 | 기존 믿음의 붕괴 | “열심히 할수록 망합니다” |
| 증거 | 믿을 수 있는 결과 | “직접 돌려봤습니다” |
| 비교 | 선택을 쉽게 만드는 차이 | “수작업 vs 자동화” |
| 금지/경고 | 실수 방지 욕구 | “이건 절대 하지 마세요” |
| 숫자 | 구체성·신뢰 | “7일 만에 3배” |

분석 질문:

```text
이 문구는 어떤 욕구를 자극하는가?
이 문구는 어떤 손해를 피하게 만드는가?
이 문구는 어떤 궁금증을 남기는가?
이 문구는 제목과 같은 이유를 말하는가?
문구만 봐도 클릭 이유가 명확한가?
```

---

### 5-2. 이미지 연상 분석

이미지가 시청자에게 무엇을 떠올리게 하는지 분석한다.

| 이미지 유형 | 연상 작용 | 클릭 이유 |
|---|---|---|
| 얼굴 클로즈업 | 감정, 위기, 놀람 | 감정 전염 |
| 제품/도구 | 실전성, 사용성 | 나도 써보고 싶음 |
| 결과 화면 | 증거, 신뢰 | 진짜 되는지 확인 |
| 전후 비교 | 변화, 개선 | 결과의 크기 확인 |
| 실패 장면 | 문제, 손실 | 나도 피하고 싶음 |
| 복잡한 작업 화면 | 고통, 난이도 | 더 쉬운 방법 기대 |
| 깔끔한 자동화 플로우 | 질서, 해결 | 자동화 가능성 기대 |
| 돈/조회수/리드 지표 | 성과, 보상 | 나도 얻고 싶음 |

분석 질문:

```text
이 이미지는 무엇을 연상시키는가?
타깃은 이 이미지를 보고 자기 상황을 떠올리는가?
이미지가 제목의 약속을 증명하는가?
이미지가 문구의 감정을 강화하는가?
이미지가 너무 많은 정보를 보여줘서 궁금증을 죽이지 않는가?
```

---

### 5-3. 문구 + 이미지 결합 심리 분석

최종적으로는 문구와 이미지가 합쳐졌을 때 어떤 심리로 클릭이 발생하는지 분석한다.

| 결합 구조 | 최종 심리 | 예시 |
|---|---|---|
| 이득 문구 + 결과 이미지 | “나도 저 결과를 얻고 싶다” | 자동화 성과 화면 + “3시간 → 10분” |
| 손해 문구 + 실패 이미지 | “나도 저 실수를 피해야 한다” | 광고비 낭비 화면 + “이래서 돈이 샙니다” |
| 궁금증 문구 + 일부 가려진 이미지 | “정답을 확인하고 싶다” | 가려진 플로우 + “여기 하나만 바꿨습니다” |
| 공감 문구 + 현실 이미지 | “이거 내 얘기다” | 지친 작업자 + “아직도 직접 하나요?” |
| 반전 문구 + 의외 이미지 | “내가 알던 것과 다르다” | 실패한 고퀄 디자인 + “예쁘면 망합니다” |
| 증거 문구 + 실전 화면 | “진짜 해본 것 같다” | 실제 대시보드 + “직접 돌려봤습니다” |

최종 분석 질문:

```text
문구와 이미지가 합쳐졌을 때 생기는 감정은 무엇인가?
시청자는 어떤 이득을 기대하는가?
시청자는 어떤 손해를 피하고 싶어지는가?
시청자는 어떤 질문의 답을 확인하고 싶어지는가?
클릭 이유가 제목, 문구, 이미지에서 모두 같은 방향으로 보이는가?
```

## 6. 이미지 디벨롭 단계

이미지 디벨롭의 목적은 이미지를 예쁘게 만드는 것이 아니다.

이미지 디벨롭의 목적은 **왜 이 영상을 클릭해야 하는지 그 이유를 시각적으로 더 명확하게 만드는 것**이다.

---

### 6-1. 이미지 확대

핵심 원칙:

> 클릭 이유를 제외한 나머지는 모두 제거한다.

확대는 단순히 이미지를 키우는 것이 아니다.  
시청자가 봐야 하는 핵심만 남기고 나머지를 버리는 것이다.

검수 질문:

```text
썸네일을 작게 봐도 주인공이 보이는가?
주인공이 클릭 이유를 직접 보여주는가?
없어도 되는 배경이나 소품이 남아 있지 않은가?
이미지에서 클릭 이유가 1초 안에 이해되는가?
```

실행 방식:

```text
- 핵심 피사체 확대
- 배경 제거
- 주변 요소 삭제
- 시선 분산 요소 제거
- 중앙 또는 좌측 상단에 핵심 요소 배치
```

---

### 6-2. 증거 이미지로 변경

목적:

> 제목과 문구의 주장을 믿게 만든다.

사용 가능한 증거:

```text
- 전후 비교
- 수익/조회수/리드 화면
- 작업 결과물
- 실제 자동화 플로우
- 대시보드
- 실패 화면
- 개선된 결과 화면
```

검수 질문:

```text
이 이미지는 제목의 약속을 증명하는가?
시청자가 “진짜네?”라고 느낄 수 있는가?
숫자나 결과가 너무 작아서 안 보이지 않는가?
증거가 과장처럼 느껴지지 않는가?
```

---

### 6-3. 궁금증 이미지로 변경

목적:

> 정답을 다 보여주지 않고 클릭할 이유를 남긴다.

실행 방식:

```text
- 결과 일부만 보여주기
- 핵심 부분 일부 가리기
- 결과 직전 장면 사용
- 의외의 장면 사용
- 비교 대상 중 하나만 공개
```

검수 질문:

```text
이미지가 정답을 전부 말해버리지는 않는가?
시청자가 “그래서 뭐지?”라고 느낄 수 있는가?
궁금증이 제목과 연결되는가?
불필요한 미스터리가 아니라 실제 내용과 연결되는가?
```

---

### 6-4. 공감 이미지로 변경

목적:

> 시청자가 자기 상황이라고 느끼게 만든다.

실행 방식:

```text
- 실제 작업 상황
- 답답한 문제 상황
- 실패한 결과
- 비교되는 현실
- 시청자의 일상과 가까운 장면
```

검수 질문:

```text
이 이미지는 타깃이 실제로 겪는 상황인가?
이 이미지를 보고 “내 얘기다”라고 느낄 수 있는가?
너무 연출되어 거리감이 생기지 않는가?
공감이 클릭 이유로 이어지는가?
```

---

### 6-5. 시청층 선호 이미지로 변경

목적:

> 내 채널의 핵심 시청자가 반응하는 이미지 문법에 맞춘다.

예를 들어 마케팅 자동화, AI 자동화, 작은 브랜드 성장 콘텐츠라면 반응할 가능성이 높은 이미지는 다음과 같다.

```text
- 실제 작업 화면
- 자동화 플로우
- 결과 대시보드
- 조회수/매출/리드 증가 증거
- 사람이 고민하는 장면
- 수작업 vs 자동화 비교
- 도구 화면
- 결과물 Before/After
```

검수 질문:

```text
내 시청층은 사람 얼굴에 반응하는가?
내 시청층은 결과 화면에 반응하는가?
내 시청층은 도구 화면에 반응하는가?
내 시청층은 돈/시간/성과 지표에 반응하는가?
```

### 6-6. 성과 썸네일 구조 학습

목적:

> 뷰트랩/YouTube 레퍼런스를 통해 분야별로 먹히는 썸네일 문법을 학습한다.

저장해야 할 패턴:

```text
- 얼굴 유무
- 손가락/화살표 유무
- 숫자 강조 여부
- 전후 비교 여부
- 화면 캡처 사용 여부
- 도구/제품 노출 여부
- 문구 글자 수
- 색상 대비
- 좌우 배치
- 핵심 피사체 위치
- 감정 표현
- 제목과 썸네일 문구의 중복 여부
```

## 7. 이미지 소스 수집 자동화

요청 반영:

- 직접 만든 AI 이미지는 우선순위에서 제외
- 타 유튜버 썸네일 그대로 사용은 제외
- High 위험도 이미지는 사용 가능 후보에 둘 수 있으나, 출처 표기와 내부 리스크 기록은 반드시 남김

---

### 7-1. 이미지 소스 우선순위

| 우선순위 | 소스 | 사용 추천도 | 설명 |
|---:|---|---|---|
| 1 | 직접 캡처한 내 영상 장면 | 매우 높음 | 가장 안전하고 내용 일치도가 높음 |
| 2 | 직접 촬영한 사진 | 매우 높음 | 초상권·저작권 관리 가능 |
| 3 | 무료 이미지 사이트 | 중간 | 라이선스 조건 확인 필요 |
| 4 | CC 라이선스 이미지 | 중간 | 상업 사용/수정 가능 여부 확인 필요 |
| 5 | 구글 이미지 검색 | 사용 가능 후보 | 출처 기록, 라이선스, 리스크 확인 필요 |
| 6 | 뉴스/블로그/웹페이지 이미지 | 사용 가능 후보 | 출처 명확히 기록, 민감 이미지 주의 |

---

### 7-2. 이미지마다 저장해야 할 출처 정보

```yaml
image_id:
video_id:
thumbnail_candidate_id:
source_type:
source_url:
source_page_title:
creator_or_owner:
license:
commercial_use_allowed:
modification_allowed:
attribution_required:
download_date:
used_in_thumbnail:
risk_level:
attribution_text:
usage_note:
```

---

### 7-3. 이미지 위험도 분류

사용자 운영 원칙상 High도 출처 표기 후 사용할 수 있는 후보로 둔다.  
단, 자동화 시스템 내부에서는 위험도를 반드시 기록한다.

| 위험도 | 기준 | 자동화 처리 |
|---|---|---|
| Low | 직접 촬영, 직접 캡처, 명확한 무료/상업 가능 이미지 | 사용 우선 |
| Medium | 무료 이미지 사이트, CC 이미지 | 조건 확인 후 사용 |
| High | 구글 이미지, 뉴스/블로그 이미지, 출처는 있으나 권리 관계가 불명확한 이미지 | 출처 표기 필수, 대체 이미지 후보도 함께 저장 |
| Critical | 개인의 민감한 이미지, 사생활 침해 가능 이미지, 비방 맥락 이미지, 미성년자 민감 이미지, 명백한 권리 침해 가능 이미지 | 사용 금지 |

주의:

- 출처 표기는 리스크를 줄이는 장치이지 모든 사용을 보장하는 허가가 아니다.
- 그래도 운영상 High 이미지를 쓸 경우, 반드시 출처와 사용 맥락을 기록한다.
- 분쟁이나 요청이 생기면 즉시 교체할 수 있도록 대체 썸네일 후보를 보관한다.

---

### 7-4. 출처 표기 템플릿

영상 설명란 하단에 자동 삽입한다.

```text
[이미지 출처]
- Image 1: {creator_or_owner} / {source_url} / {license_or_source_note}
- Image 2: {creator_or_owner} / {source_url} / {license_or_source_note}
- Image 3: {creator_or_owner} / {source_url} / {license_or_source_note}

본 영상의 썸네일 및 자료 이미지는 출처를 확인하여 사용했으며,
문제가 있을 경우 확인 후 즉시 수정하겠습니다.
```

## 8. YouTube API 기반 자동화 가능 범위

### 8-1. 썸네일 업로드/교체

가능하다.

YouTube Data API의 `thumbnails.set`을 사용해 특정 영상의 커스텀 썸네일을 업로드하고 설정할 수 있다.

필요 정보:

```yaml
videoId:
thumbnail_file_path:
mime_type: image/jpeg 또는 image/png
oauth_scope:
```

주의:

```text
- 썸네일 파일 크기 제한 확인
- 권한 인증 필요
- 업로드 쿼터 소모
- 단기간 과도한 썸네일 업로드 제한 가능
```

---

### 8-2. 영상 단위 성과 데이터 수집

가능하다.

YouTube Analytics API 또는 Reporting API에서 다음 지표를 수집한다.

```text
- video_thumbnail_impressions
- video_thumbnail_impressions_ctr
- views
- watch_time_minutes
- average_view_duration_seconds
- average_view_duration_percentage
- subscribers_gained
- likes
- comments
- shares
```

분석 관점:

```text
CTR = 클릭을 만들었는가
평균 시청 지속 시간 = 클릭 후 기대를 충족했는가
Watch time = YouTube가 좋아할 만큼 질 좋은 클릭이었는가
노출수 = 테스트 표본이 충분했는가
```

---

### 8-3. 공식 A/B 테스트 API 자동화

현재 설계 기준에서는 다음처럼 판단한다.

| 기능 | API 가능 여부 | 설계 판단 |
|---|---:|---|
| A/B 테스트 생성 | 공개 API 기준 확인 어려움 | 수동 또는 브라우저 자동화 검토 |
| A/B 테스트 중지 | 공개 API 기준 확인 어려움 | 수동 처리 권장 |
| A/B 테스트 각 버전별 CTR 추출 | 공개 API 기준 확인 어려움 | Studio 확인값 입력 또는 별도 수집 방식 필요 |
| A/B 테스트 승자 확인 | Studio에서는 가능 | API로는 공개 엔드포인트 확인 어려움 |
| 썸네일 교체 | 가능 | `thumbnails.set` 사용 |

---

### 8-4. API 기반 자체 순차 테스트 설계

공식 A/B 테스트 API가 제한적이므로, 완전 자동화하려면 자체 순차 테스트를 설계한다.

```text
Day 1~2: Thumbnail A 적용
Day 3~4: Thumbnail B 적용
Day 5~6: Thumbnail C 적용
Day 7: 성과 비교
```

수집값:

```yaml
thumbnail_id:
start_datetime:
end_datetime:
impressions:
ctr:
views:
watch_time_minutes:
average_view_duration_seconds:
average_view_duration_percentage:
traffic_source:
device_type:
subscriber_status:
```

판단식 예시:

```text
score =
(CTR 표준화 점수 * 0.35)
+ (watch_time_minutes 표준화 점수 * 0.35)
+ (average_view_duration_percentage 표준화 점수 * 0.20)
+ (impressions 안정성 점수 * 0.10)
```

주의:

- 순차 테스트는 동시 A/B 테스트보다 신뢰도가 낮다.
- 요일, 시간, 알고리즘 노출 상태, 구독자/비구독자 비중이 다르면 결과가 왜곡될 수 있다.
- 그래서 자동화 보고서에는 반드시 `confidence_level`을 기록한다.

## 9. 승자 판단 로직

YouTube 공식 A/B 테스트를 쓸 경우, YouTube는 watch time share 중심으로 승자를 판단한다.  
자체 자동화에서는 CTR만 보면 안 된다.

---

### 9-1. 기본 판단표

| 결과 | 의미 | 액션 |
|---|---|---|
| CTR 높음 + 시청 지속 높음 | 좋은 클릭 이유 | 승자 후보 |
| CTR 높음 + 시청 지속 낮음 | 낚시성 가능성 | 문구/이미지 정직도 조정 |
| CTR 낮음 + 시청 지속 높음 | 영상은 좋은데 클릭 이유 약함 | 썸네일/제목 강화 |
| CTR 낮음 + 시청 지속 낮음 | 주제·도입부·썸네일 모두 문제 가능성 | 전체 재검토 |
| 노출수 부족 | 판단 불가 | 테스트 기간 연장 |
| 세 버전 차이 미미 | 뚜렷한 클릭 이유 없음 | 더 다른 가설로 재제작 |

---

### 9-2. 승자 분석 출력 예시

```yaml
test_group_id: "video_001_round_1"
winner: "thumbnail_B"
winner_reason:
  quantitative:
    impressions: 18420
    ctr: 7.8
    watch_time_minutes: 1320
    average_view_duration_percentage: 42.1
  qualitative:
    text_psychology: "이득 제시 + 실전 증거"
    image_association: "자동화 대시보드가 실제 결과를 연상시킴"
    combined_click_psychology: "시청자는 '나도 이 결과를 만들 수 있나?'를 확인하려고 클릭"
losers:
  - thumbnail_A:
      likely_reason: "주인공은 명확하지만 증거가 약함"
      next_action: "확대 이미지는 유지하되 결과 화면 추가"
  - thumbnail_C:
      likely_reason: "공감 이미지는 좋지만 영상 주제의 실전성이 약하게 보임"
      next_action: "공감 장면 옆에 실제 결과 증거 배치"
next_test_direction:
  - "증거 이미지 세분화"
  - "문구를 더 짧게 압축"
  - "결과 수치를 더 크게 표시"
```

## 10. 패배 원인별 디벨롭 규칙

| 패배 원인 | 진단 | 다음 액션 |
|---|---|---|
| 클릭 이유 불명확 | 왜 봐야 하는지 안 보임 | 제목·문구·이미지의 이유를 하나로 통일 |
| 주인공 불명확 | 뭘 봐야 할지 모름 | 이미지 확대, 배경 제거 |
| 증거 부족 | 믿기 어려움 | 결과 화면, 숫자, Before/After 추가 |
| 궁금증 부족 | 다 알려줘서 클릭 이유가 없음 | 일부 정보 숨기기 |
| 공감 부족 | 내 얘기처럼 안 느껴짐 | 현실 상황 이미지 사용 |
| 타깃 불일치 | 내 시청층이 좋아할 이미지가 아님 | 채널 시청층 선호 이미지로 변경 |
| 문구 약함 | 심리 자극이 없음 | 이득/손해/궁금증 구조로 재작성 |
| 제목과 불일치 | 제목과 썸네일이 다른 약속을 함 | 하나의 클릭 이유로 통합 |
| 모바일 가독성 부족 | 작게 보면 안 읽힘 | 글자 수 축소, 대비 강화 |
| 데드존 침범 | 시간/재생목록 UI에 가림 | 핵심 요소 중앙 이동 |

## 11. 자동화 워크플로우 전체

```text
[1] 영상 주제 입력
↓
[2] 핵심 타깃 정의
↓
[3] 타깃의 욕구/손해/공감 상황 정의
↓
[4] 영상의 클릭 이유 1개 정의
↓
[5] 제목·문구·이미지가 같은 클릭 이유를 말하는지 검토
↓
[6] YouTube/Viewtrap 기반 레퍼런스 수집
↓
[7] 레퍼런스별 클릭 이유 분석
    - 문구 구조
    - 이미지 연상
    - 결합 심리
↓
[8] 이미지 디벨롭 방향 선택
    - 확대
    - 증거
    - 궁금증
    - 공감
    - 시청층 선호
    - 성과 구조 학습
↓
```

## 14. 최종 운영 원칙

1. 썸네일의 주인공은 디자인이 아니라 **클릭 이유**다.
2. 클릭 이유를 제외한 요소는 모두 제거하거나 약화시킨다.
3. 제목, 썸네일 문구, 이미지는 같은 클릭 이유를 말해야 한다.
4. 문구는 어떤 심리를 자극하는지 분석한다.
5. 이미지는 무엇을 연상시키는지 분석한다.
6. 문구와 이미지가 결합했을 때 최종적으로 어떤 심리로 클릭하는지 분석한다.
7. 9개 썸네일은 9개의 서로 다른 클릭 가설이어야 한다.
8. 3개씩 테스트하고, 승자 방향을 다음 3개에서 더 세분화한다.
9. CTR만 보지 말고 watch time, 평균 시청 지속 시간까지 함께 본다.
10. API 기반 완전 자동화는 썸네일 교체와 영상 단위 성과 수집까지 가능하다.
11. YouTube 공식 A/B 테스트의 생성·개별 버전 지표 추출은 공개 API 기준 제한적이므로 수동 또는 반자동 운영이 필요하다.
12. 이미지 출처는 반드시 본문에 기록하고, 리스크는 내부 DB에 남긴다.
