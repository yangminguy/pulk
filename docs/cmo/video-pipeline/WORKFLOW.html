01무엇이 바뀌었나

기존 설계(rev5)는 기준 영상 캘리브레이션에서 시작해 60초 파일럿을 최대 승인 지점으로 뒀습니다. 이번 지시로 네 가지를 확정합니다.

항목기존 rev5확정
시각 파라미터 기준 영상 2~3편을 실측해 값을 채운다 (사람 60분, 매번 교정) 초기에 한 번만 세팅. 전달한 디자인 파일 frame.md 기준, 부족한 값은 brandboy edit-profile.json 기본값으로 보충. 이후 그 데이터로 전 과정 진행.
핵심 승인 60초 파일럿(G3)이 최대 게이트 스토리보드가 최대 게이트. 녹음 후 타이밍이 붙은 상태로 반복 승인. 소스·모션·사진 촬영모션까지 전부 여기서 결정.
오디오 여러 테이크 중 최적 선택 + 접합 + 마스터 무재테이크 전제. 테이크 선택 제거. ①빈 공백 정리 ②세션 접합 ③연속 마스터, 이 셋만.
소스 종류 스톡 상한만 규정(≤10%) 영상 우선. 사진은 핵심 강조에만 소수. 촬영 모션은 parallax 기본으로 다 만든 뒤 사장님이 확정(다운그레이드=켄번즈).

한 줄 요약

디자인 파일로 룩을 한 번 잠그고 → 원고 키워드로 영상 소스를 긁고 → 무재테이크로 녹음·접합 → 타이밍이 붙은 스토리보드에서 사장님이 “이 소스/이 편집/이 사진 모션 바꿔”를 반복 → 확정되면 조립. 창작 판단은 전부 타이밍 스토리보드 위에서.

02전체 흐름 (Phase A–F)

순서가 바뀌었습니다 — 녹음(C)이 스토리보드(D) 앞으로 옵니다. 소스 수급(B)은 원고 키워드만 있으면 되므로 녹음과 병행 가능하고, 스토리보드에서 둘이 만납니다.

04★ 스토리보드 — 이 파이프라인의 심장

사장님이 가장 중요하게 삼는 지점입니다. 녹음 후 타이밍이 붙은 상태에서, “원고의 각 비트에 어떤 화면(영상·사진+촬영모션·모션)이 몇 초에 붙는가”를 한 화면에 펼친 정적 HTML입니다. 모든 창작 결정이 여기서 일어납니다.

스토리보드에 담기는 것

  • 원고 문장 + 키워드 + 타임코드 — 어떤 말에, 몇 초 구간에 붙는 화면인지
  • 영상 소스 후보 — 유튜브·웹·페이지에서 긁은 구간(프록시 클립 미리보기)
  • 사진 + 촬영 모션 — 소수의 사진 각각에 켄번즈/parallax 등 어떻게 움직일지를 명시
  • 모션 그래픽 후보 — critical 키워드의 hyperframes 삽입 클립
  • AI 제안 선택 + 근거, 그리고 컷 속도·강조·원본음 사용 같은 편집 의도
“3년 만에 매출 10배를 찍었죠”매출 10배02:14.3–02:17.1
✓ IR영상 04:12–04:16 official·video ◈ 숫자 카운트업 hyperframes ＋ 소스 추가
“처음엔 창고 하나에서 시작했어요”창고 시작02:17.1–02:20.0

“고객이 먼저 찾아오더라고요”고객 유입02:20.0–02:23.4
✓ 매장 인터뷰 08:02–08:09 interview·원본음 🖼 지도 사진 · parallax 기본 ＋ 소스 추가

위는 예시 렌더입니다. 각 후보엔 재생 가능한 프록시 클립·출처·권리 상태·AI 점수가, 각 사진엔 촬영 모션 미리보기가 붙습니다.

왜 스토리보드가 조립보다 먼저인가. 300개 샷을 다 붙인 뒤 “이 소스/이 모션 바꿔”를 받으면 재작업이 눈덩이가 됩니다. 스토리보드는 싼 단계에서 창작 결정을 다 끝내고, 조립(E)은 그 결정을 기계적으로 실행만 하게 만듭니다. 이제 타이밍까지 붙어 있으므로 “몇 초에 이 화면이 뜬다”를 사장님이 실제 리듬으로 보고 판단합니다.

05소스 수급 — 영상 우선 · 사진 촬영 모션

사진은 영상에서 그대로 쓰기 어렵습니다. 확대하거나 영상적 요소를 더해야 화면에 붙습니다. 그래서 수급은 영상 우선, 사진은 소수만, 그리고 쓰는 사진마다 어떻게 움직일지를 스토리보드에서 확정합니다.

수급 정책

종류우선순위규칙
영상 (공식영상·인터뷰·B-roll)1순위키워드당 최대한 확보. 자막 구간 검색으로 정확한 지점을 찾는다.
사진 (아카이브·제품컷)핵심 강조에만핵심을 강조할 때만 소수. 15분당 상한(3~6장), 촬영 모션 없이는 배치 불가(기본 parallax).
스톡최후기존 상한 ≤10% 유지. 가급적 피한다.

촬영 모션 — 사진을 어떻게 움직이나

두 단계로 처리합니다. 기본은 결정론적 코드, 히어로 컷만 hyperframes로 승격합니다.

방식쓰는 곳어떻게
parallax
(기본)		 모든 사진 (먼저 다 생성) hyperframes로 전경/배경 레이어를 분리해 깊이감·라이트·그레인 같은 “영상적 요소”를 더한다. 스틸이 살아 움직이는 인상. 일단 다 parallax로 만들고 사장님이 스토리보드에서 확정한다.
켄번즈
(다운그레이드)		 사장님이 바꾼 사진 ffmpeg zoompan으로 느린 줌 + 초점 이동. 초점=피사체(얼굴/제품/텍스트/간판)를 잡아 그쪽으로. 방향은 내레이션 흐름에 맞춤. 조립 단계에서 렌더.

06오디오 — 무재테이크 접합

재테이크 없이 세션별로 녹음하므로, AI는 고르지 않고 붙이기만 합니다. 딱 세 가지입니다.

하는 일내용구현
① 빈 공백 정리문장·단어 사이 죽은 공백과 어색한 멈춤을 자연스러운 호흡만 남기고 다듬는다. 말은 안 지운다.무음 감지 + 갭 트리밍 (align/edit.ts)
② 세션 접합세션별 WAV의 경계 톤·레벨을 맞춰 접합음 없이 잇는다.세션 정합 (align/sessions.ts)
③ 연속 마스터하나의 끊김 없는 narration-master.wav(A1). 조각 파일은 미리듣기용.align 최종 출력

안 하는 것

  • 테이크 선택 안 함 — 다중테이크 최적 선택 로직 제거. 무재테이크 전제라 불필요.
  • 말 내용 재생성 안 함 — TTS 아님. 사장님 목소리 원본만.
  • 씬 단위로 자르지 않음 — A1은 언제나 하나의 연속 마스터.

※ 원고를 고쳐 특정 세션만 다시 녹음하는 것은 여전히 정상 절차. 이때 sentence_key 재고정이 이미 승인한 화면·사진모션 선택을 보존한 채 시각만 이동시킵니다.

07승인 지점 정리

지점무엇을 승인왜 여기서무게
① 원고 + 시각 파라미터 말할 내용·순서·세션 구분 + 디자인 룩 1회 확정이후 전부가 여기에 매달린다보통
② 스토리보드 ★ 영상·사진(촬영모션)·모션의 매핑·타이밍·편집 의도 (반복) 창작 결정 전부가 여기 모인다. 재작업이 가장 싼 지점.최상
③ 최종 마감 실제 속도 시청 후 최종 컷·발행기계가 못 잡는 말맛·호흡의 최종 판단높음

시각 파라미터를 ①에서 확정하므로 기존의 “룩 확인(G3)” 별도 게이트는 사라집니다. rev5의 G0·G1(소스 충분성·근거 검증)은 스토리보드 검토(②)에, G5(발행 점검)는 ③에 흡수됩니다.
