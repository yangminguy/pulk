0. 먼저 알아둘 핵심 개념 5가지

아래 5가지만 알면 모든 단계가 이해됩니다.
1
키 콘텐츠 vs 풀링 콘텐츠
키 콘텐츠 = 실제로 상품을 파는 핵심 영상(1개). 풀링 콘텐츠 = 아직 상품에 관심 없는 사람을 키 콘텐츠로 끌어오는 영상(5개). 풀링이 모으고, 키가 판매합니다. 풀링은 반드시 키로 이어지는 브릿지 문장이 있어야 통과합니다.
2
소비자 행동 5단계 — 현상 → 욕구 → 계획 → 행동 → 보상
고객은 "문제를 느끼고(현상) → 해결하고 싶어지고(욕구) → 방법을 찾고(계획) → 행동하고(행동) → 결과를 얻는(보상)" 흐름을 탑니다. 단계를 콘텐츠에 고정 배정하지 않습니다 — 한 콘텐츠가 여러 단계를 동시에 덮어도 되고, 세트 전체가 5단계를 자연스럽게 설명하면 통과입니다.
3
판매 논리 = 기능을 거꾸로 뒤집어 고객 문제에서 출발
"우리 상품 좋아요"가 아니라 기능 → (역설계) → 고객 문제 → 판매 논리 6요소 순서로 갑니다: 문제 제시 → 카테고리 기능·혜택 → 카테고리 필요성 → 내 상품 기능·혜택 → 내 상품 해결 선언 → CTA.
4
발굴 = YouTube API · 지표 검증 = Viewtrap (이용횟수 차감 주의)
아이디어·경쟁 영상을 찾을 때는 YouTube API(무제한), 성과도·기여도·노출확률을 검증할 때는 Viewtrap(CDP 크롬으로 자동 운전 가능하나 검색은 이용횟수 차감 — 기본 OFF, use_viewtrap=true일 때만). 공통 필터: 조회수 5만+ · 성과도 Good/Great · 기여도 Good/Great · 채널가치/인물가치 배제. 추가로 시청자 정체성 일치(이 영상을 보는 사람의 자기인식이 우리 타깃과 같은가, 상위 댓글이 직접 증거)가 1순위 — mismatch면 조회수가 높아도 제외.
5
Pulk = 무엇을·왜·누구에게 / Factory = 어떻게 보여줄지
Pulk(CMO)는 전략·원고·VideoExecutionBrief까지만 책임지고, 영상 공장(AI Slide Factory)이 장면·길이·타임라인을 결정합니다. CMO는 scene_type / best_medium / duration / timeline을 절대 확정하지 않습니다(힌트 visual_intent_hint만 전달).

PHASE A — 전략

2. 전략 대화 · PT 컨텍스트 · 상품 정의 status 1~3

바로 기획으로 점프하지 않습니다. 컨텍스트를 먼저 흡수하고, 상품 정의를 승인받은 뒤에야 실검색이 시작됩니다.
1
전략 대화 시작 자동
상품명·설명·가격·제공 방식·타깃·비즈니스 목표(상담/판매/대기자/브랜드)·CTA를 가볍게 확인합니다.
입력: 상품 기본 정보 → VideoRoomProject 생성
2
Business PT 컨텍스트 로딩 자동
Second Brain/Notion의 비즈니스 PT 강의·컨설팅 기록·썸끝/원끝 분석·이전 프로젝트 성과 Memory를 검색(최소 3개 참조)해 이번 프로젝트의 기획 원칙을 스냅샷으로 저장합니다. 이 단계 없이 키 콘텐츠 후보 생성 금지(PRD 금지 규칙).
출력: BusinessPTContextSnapshot — key_principles / key·pulling_content_rules / thumbnail_intro_rules / script_structure_rules / caution_notes
3
상품 정의 8섹션 승인 승인 게이트
키 워크플로우 Step 1~7 분석(후보 생성은 아직 안 함) + 뷰트랩 실검색용 짧은 키워드(2~4어절)를 정리한 8섹션 보드를 사장님이 승인합니다: ①상품 한 줄 ②타깃 ③기능·특징·장점 ④사용자 문제 ⑤현상·욕구·계획·행동·보상 배치 ⑥키워드 후보 ⑦최종 검색 키워드 ⑧승인.
액션: cmo:proposeProductDefinition → product_definition 카드 · UI: ProductDefinitionBoard
왜 승인을 2번(상품 정의 → 키 보고서)으로 쪼갰나? 간단한 상품 정보에서 곧장 실행으로 점프하면 잘못된 키워드로 5~15분짜리 실검색을 낭비합니다. 검색 전에 "무엇을 검색할지"부터 사장님이 확정합니다 (2026-06-11 신설).

3. 키 콘텐츠 기획 11스텝 + 실검색 보고서

상품을 실제로 파는 핵심 영상 1개를 만듭니다. "장점 자랑"이 아니라 "고객 문제 역설계"로 판매 논리를 만드는 게 핵심입니다. (정본: cmo-content-strategy-v3 §3)

3-1. 기획 11스텝 (도메인 로직)

1
내 아이템 일반화 자동
내 아이템 → 직접 카테고리 → 상위 카테고리 → 고객이 인식하는 문제 카테고리로 넓힙니다. (예: AI 마케팅팀 → AI 마케팅 자동화 → 콘텐츠 마케팅 시스템 → 손님이 오게 만드는 콘텐츠 흐름)
2
아이템 기능/특징/장점 정리 자동
기능(무엇을 하는가) / 특징(어떤 방식인가) / 장점(왜 좋은가)을 정리합니다.
3
카테고리 기능/특징/장점 정리 자동
상품군 수준에서도 정리 — 이게 있어야 고객이 "이런 종류의 해결책이 필요하구나"를 먼저 이해합니다.
4
문제 도출 — 기능을 거꾸로 자동
"이 기능이 있다는 건, 고객이 이런 문제를 겪는다는 뜻"이라고 역으로 끌어냅니다. (아이템 문제 + 카테고리 문제, 각각 출처 기능 표기)
5
퍼널 배치 자동
문제들을 현상/욕구/계획/행동/보상 5단계에 배치합니다 (최소 2개 단계 필수).
6
진입 단계 결정 자동
키 콘텐츠가 현상/욕구/계획 중 어디서 시작해야 판매 논리가 자연스러운지 결정 + 이유. (계획 단계 고객 부족 → 앞단으로, 상품 장점이 너무 빨리 나옴 → 더 앞단으로)
7
검색 키워드 도출 — 5개 축 자동
①문제 ②아이템명 ③카테고리명 ④아이템 기능·혜택 ⑤카테고리 기능·혜택 — 5개 축의 Viewtrap 검색 키워드를 만듭니다.
8
Viewtrap/YouTube 검증 자동(발굴 파이프라인) 노출확률은 옵션
3단계 발굴 파이프라인: ①YouTube API 검색+stats(5만+ 필터) ②뷰트랩 확장 등급 스크랩(성과도·기여도, CDP 크롬) ③viewtrap 사이트 노출확률(use_viewtrap=true일 때만, 이용횟수 차감) → Sonnet 의도 분류(fit/ambiguous/unfit). 채널·인물 가치 영상 제외, 성장 그래프 확인.
액션: cmo:runDiscovery {query, mode, use_viewtrap?} → discovery 카드 + 검증 초안
9
판매 가능한 콘텐츠 산정 자동
후보 중 실제로 팔 수 있는 것만: 보는 사람이 고객이 되는가 / 상품과 연결되는가 / 내 수익구조·단가에 맞는가.
10
판매 논리 6요소 완성 자동
문제 제시 → 카테고리 기능·혜택 → 카테고리 필요성 → 내 상품 기능·혜택 → 내 상품 해결 선언 → CTA.
출력: SalesLogicMap (problem_statement / category_feature_benefit / category_need / item_feature_benefit / item_solution_statement / cta)
11
키 콘텐츠 확정 승인①
추천 1개를 승인/수정/다른 후보/보류 중 결정. 승인 시 풀링 입력 카드(key_content_choice·draft)가 자동 커밋됩니다.

3-2. 실검색 키 콘텐츠 보고서 (key_content_ideation에서 자동 생성)

11스텝의 Step 8·9를 실데이터로 수행하는 보고서 파이프라인입니다 (runKeyContentReport, 소요 5~15분):

1
키워드별 시장성 측정
승인된 최종 키워드들로 실검색 → computeMarketMetrics로 키워드별 시장성 표.
2
배치 LLM 판정
키워드별 진행추천/보류/제외 verdict.
3
후보 풀 → 최종 3선
자격 조건: 롱폼 + 조회수 5만+ + 성과도/기여도 Good↑. 그리고 시청자 정체성 정합성이 1순위 — 영상 시청자의 정체성·자기인식(예: "실무자" vs "마케팅팀 없는 대표")이 우리 타깃과 같아야 하며, 인기 댓글(YouTube commentThreads, relevance순)을 직접 증거로 첨부합니다. mismatch는 조회수 높아도 제외.
4
자막 수집 + 판매 논리 분해
후보 영상의 자막(CDP로 "Show transcript" 패널 스크랩, 서버 fetch 폴백)을 확보해 현상→욕구→계획→행동→보상 + 수익화 구조를 분해합니다.
5
우리 상품 적용 판매논리 + 추천 1
분해한 구조에 우리 상품을 끼워 적용한 판매논리와 추천 사유를 만들어 7섹션 보고서(KeyContentReportBoard)로 제출 → 승인①로 연결.

4. 풀링 콘텐츠 기획 12스텝

키 콘텐츠를 볼 준비가 된 사람을 만드는 콘텐츠 5개를 설계합니다. 풀링은 단계 고정 배정이 아니라 "키로 자연스럽게 이어지는가"로 평가합니다. (정본: cmo-content-strategy-v3 §4)
0
키 콘텐츠 판매 논리 불러오기 자동
키 제목·핵심 문제·판매 논리·CTA·검증 결과를 기준점으로 로드. 키 없이 풀링 생성 금지.
1
"키를 볼 준비가 된 사람" 정의 자동
어떤 문제 인식·욕구·계획 수준이 있어야 키가 먹히는지 + 아직 준비 안 된 사람은 왜인지.
2
논리적 확장 자동
내 상품 → 카테고리 → 기능·혜택 → 문제 → 그 문제를 가진 사람 → 그 사람이 보고 싶을 콘텐츠 주제. (예: AI 마케팅팀 → … → "인스타 열심히 해도 손님이 안 오는 이유")
3
문제 축 6종 분류 자동
증상 / 원인 / 욕구 / 계획 / 오해 깨기 / 보상·사례 — 분류 도구일 뿐 고정 단계가 아닙니다(한 콘텐츠가 여러 축 가능).
4
콘텐츠 유형 포트폴리오 자동
에버그린(꾸준)/데일리(저비용)/시즌성(폭발)/히어로(고비용)로 분류. 운영 원칙: 에버그린·데일리를 중심으로 깔고, 결에 맞는 시즌성·히어로를 찍는다.
5
풀링 Viewtrap 기본 검증 자동(파이프라인)
실제 검색 절차(PRD 8단계): 키워드 검색 → 기여도 good/great 필터 → 성과도 good/great 필터 → (미드폼이면 shorts 제거) → 구독자 적은 순 정렬 → 상세 팝업에서 조회수 성장 그래프 확인 → 성장 멈춘 주제 대신 지금도 오르는 주제 → 채널·인물 가치 제외. 판단 기준: 성과도/기여도/재현성/성장성/채널·인물가치 배제/키 연결성/상품 논리 연결성.
6
핫비디오 구조 템플릿 자동
지금 홈에서 노출 확률 높은 영상들의 제목을 구조 단위로 분해해(예: "타깃이 원하는 결과 + 그 결과를 막는 행동 금지") 우리 주제로 치환합니다. 베끼지 않고 구조만.
7
노출 확률 높은 주제 확인 use_viewtrap 옵션
노출 확률 normal/good/great 필터 → 높은 순 정렬 → 지금 알고리즘 타는 주제 확인 (데일리·시즌성 후보).
8
롱테일·에버그린 (노다지) 자동
게시일 오래된 순 정렬 → 오래됐는데도 노출 확률 좋은 주제. 강한 규칙: 발견하면 반드시 쓴다(must_use). 못 찾으면 넘겨도 된다.
9
풀링 후보 점수화 (10항목) 자동
성과도/기여도/노출확률/성장성/에버그린성/재현성/채널·인물가치 배제/키 연결성/상품 논리 연결성/홈 선택 가능성 → use/watch/reject.
10
키 연결 문장 검사 (강제) 자동
"이 콘텐츠는 [고객]의 [문제/오해/욕망]을 건드려서 [키의 핵심 문제]를 인식하게 만들고, 결국 [키 제목]을 볼 이유를 만든다" — 완성 못 하면 통과 불가.
11
소비자 여정 커버리지 평가 자동
키+풀링 세트 전체가 현상~보상 5단계를 자연스럽게 덮는지 (개별 고정 배정 아님). 안 덮이면 경고.
12
풀링 세트 확정 승인②
풀링 5개 역할(문제 인식/문제 심화/욕구 형성/계획 진입/키 브릿지) + 브릿지를 묶은 최종 세트 승인. 승인 시 pulling_plan 카드 자동 커밋 → 제목 디벨롭 입력으로 연결.

PHASE B — 훅 (제목·썸네일·도입부)

5. 제목 디벨롭 8단계 감 → 검증 가능한 제목

검증된 레퍼런스 2개를 교차 조합해 7번 다듬고 100점 채점으로 끝냅니다. (정본: cmo-title-development + 5주차 강의 노트)
입력 조건 (하나라도 미달이면 진행 금지): 같은 주제(exact, 없을 때만 같은 의미 범위 확장) 레퍼런스 2개, 각각 조회수 5만+ · 성과도 Good/Great · 기여도 Good/Great · 제목·썸네일 문구 존재 · 선택 이유 기록. 레퍼런스 자동 발굴 함수(discoverTitleReferences, YouTube API 같은 주제 조회수 상위 2개)는 도메인 완성 — 라이브 배선은 후속(현재는 수동 입력). 인접 주제는 수식어·구조 참고용으로만.

1단계 — 4가지 교차 조합

한 영상의 제목+썸네일을 그대로 가져오면 원작자 충돌·표절 위험 → 분리해서 조합합니다: ①Ref1 썸네일+Ref2 제목 ②Ref1 제목+Ref2 썸네일 ③Ref1 썸네일 문구를 제목화+Ref2 썸네일 구조 ④Ref2 썸네일 문구를 제목화+Ref1 썸네일 구조. 어색함 판단(제목-썸네일 중복/주제 불일치/타깃 불일치/원고 불일치/과장/클릭 이유 부족) 후 통과 조합만 다음으로.

2~8단계 — 제목을 7번 다듬기 자동 (단계당 LLM 1콜, 실패 시 그 단계만 결정론 폴백)

2
쉬운 단어로 전환
한자어·전문어 → 타깃이 실제 쓰는 일상어(중학생에게 말하듯). 실패 기준: 의미가 달라짐 / 사람들이 안 쓰는 표현 / 조회수 합계가 더 낮은 표현.
3
상위어로 전환
좁은 단어 → 더 큰 욕망의 단어(창업→돈 버는 법). 실제 시장이 더 큰지 조회수로 확인 — 떨어지면 되돌린다. 전달 포인트가 달라지면 안 됨.
4
부정에 부정 걸기
긍정형 → 손실 회피형(이렇게 하면 부자된다 → 이렇게 안 하면 가난해진다). 원고에 그 부정의 근거가 있어야만 사용.
5
수식어 추가
핫비디오에서 수식어를 찾는다(굳·그레이트 + 조회수 10만+ + 구독자 적은 순). 유형: 문제지적/결과강조/대상한정/시간절약/강도/구조/대비. 35자 초과 시 조사 먼저, 그다음 수식어 제거.
6
질문이 생기게 전환
답이 다 보이는 제목에서 정보 하나(누가/언제/어디서/무엇을/어떻게/왜)를 뺀다. 누락은 시청자의 욕구 기반 — 혜택·피해와 연결된 정보를 빼야 물음표가 생긴다.
7
핫비디오 구조로 갈아끼우기
지금 타고 있는 제목의 구조를 분해해 내 주제로 치환(베끼지 않음). 구독자 낮은데 조회수 높은 영상 우선. 뷰트랩 실측 hot_videos 주입 시 실데이터 기반(미주입 시 일반 지식 폴백 + 노트 표기).
8
강한 단어로 변경
약한 단어 → 강한 단어(문제→함정·망하는 이유). 이미 구독자 많은 채널용 — 처음부터 쓰면 망한다. 근거 부족 시 한 단계 낮춘 안전 후보도 함께 보존.

최종 평가 — 100점 채점 게이트

항목배점질문
타깃 적합도20우리 타깃(작은 브랜드 대표 등)이 실제로 볼 문장인가
욕망 선명도20매출·문의·시간 절약 같은 욕망이 보이는가
문제 지적20"내 얘기다"라고 느낄 문제를 건드리는가
호기심15클릭해야 확인할 정보가 남아 있는가
원고 일치도15제목의 약속을 영상에서 실제로 보여줄 수 있는가
썸네일 결합도10제목과 썸네일이 다른 역할로 함께 후킹하는가

85점 이상 업로드 후보 · 70~84점 수정 후 후보 · 69점 이하 레퍼런스 선정부터 재실행 — 최종 제목 1개 + 대체 후보 3개 + 썸네일 방향이 승인③으로 갑니다. 각 단계의 입력/출력/버린 후보/이유는 전부 저장(AC-10), 결과는 세컨 브레인 요약으로도 저장.

6. 썸네일 9개 매트릭스 + 이미지 소스 3×3 클릭 가설

클릭 가설이 서로 다른 9개 기획안을 만들고, 심리분석과 이미지 출처·위험도까지 기록합니다. (정본: cmo-thumbnail-ab-automation + 6주차 강의 노트)
클릭률 비중 (강의 확정): 이미지 45% · 문구 45% · 디자인 10%. 초보가 망하는 이유 = 디자인에만 시간을 쓰는 것. 디자인 못하면 아예 안 해도 된다 — 이미지와 문구에 집중. 썸네일 문구는 글자를 줄인다(16자 기준), 시선은 왼쪽 위부터, 무게중심은 가운데.

Stage A — 9개 매트릭스: 이미지 전략(3) × 문구 전략(3)

#이미지 전략문구 전략클릭 가설
1확대 이미지이득 문구주인공이 명확하면 클릭한다
2확대 이미지손해 회피 문구위험을 느끼면 클릭한다
3확대 이미지궁금증 문구뭔지 궁금하면 클릭한다
4증거 이미지이득 문구결과가 보이면 클릭한다
5증거 이미지손해 회피 문구손실의 증거가 보이면 클릭한다
6증거 이미지궁금증 문구증거 일부만 보이면 확인하려고 클릭한다
7공감 이미지이득 문구내 상황의 해결책처럼 보이면 클릭한다
8공감 이미지손해 회피 문구내 문제를 건드리면 클릭한다
9공감 이미지궁금증 문구내 상황인데 답이 숨겨져 있으면 클릭한다

규칙: 9개는 반드시 서로 다른 클릭 가설 / 제목·문구·이미지는 같은 클릭 이유를 강화 / 제목과 썸네일 문구가 같은 말 반복 금지 / 레퍼런스 구조 참고하되 복사 금지. 공감 = 시청자가 원하면서, 피해를 막거나 이득이 되는 방향 — 내 채널에 모인 사람이 누구냐에 따라 매력적인 썸네일이 다릅니다(주제 매몰 금지, 사람에 집중).

Stage B — 클릭 이유 심리분석 3단계 (9개 각각)

1
문구 구조 분석
이득/손해회피/비밀/반전/증거/비교/금지·경고/숫자 중 어떤 구조이고 어떤 욕구·두려움·궁금증을 자극하는가. 제목과 같은 이유를 말하는가.
2
이미지 연상 분석
얼굴 클로즈업(감정 전염)/제품·도구(실전성)/결과 화면(증거)/전후 비교(변화)/실패 장면(손실 회피)/플로우(해결 기대) — 타깃이 자기 상황을 떠올리는가, 제목의 약속을 증명하는가.
3
결합 심리 분석
문구+이미지가 합쳐졌을 때의 최종 감정("나도 저 결과를 얻고 싶다" / "이거 내 얘기다" 등). 클릭 이유가 제목·문구·이미지에서 모두 같은 방향인가.

Stage C — 이미지 소스 수집 + 출처·위험도

위험도기준처리
Low직접 촬영, 명확한 상업 사용 가능사용 우선
Medium무료 사이트(Unsplash 등)·CC 라이선스조건 확인 후 사용
High구글 이미지·뉴스·블로그(권리 불명확)출처 표기 필수 + 대체 후보 보관 + 최종 사용은 D3 승인
Critical민감·사생활 침해·미성년자사용 금지 (D4 차단)

이미지마다 source_url/저작자/라이선스/상업사용·수정·표기 의무/다운로드일/attribution_text를 기록하고, 출처 표기 블록이 영상 설명란에 자동 삽입됩니다. 내 영상 캡처는 소스에서 제외(사장님 지시). 분쟁이 생기면 즉시 교체 원칙.

Stage D·E — 제작·검수

G1 승인(9개 기획안 + 이미지 후보) 후 제작으로 넘어가며, 검수 체크리스트로 봅니다: 데드존 4종(시간 표시·재생목록·추천탭 상단 가림·카톡 공유 하단 가림) / 작은 화면 가독성 / 무게중심 가운데 / 글자 수. 실제 썸네일 이미지 제작(AI 생성)은 MVP 범위 밖 — 기획안+소스까지가 자동, 제작은 사람/후속.

벤치마킹 분석 규칙: 그 썸네일을 고른 게 이미지 때문인지 제목 때문인지를 먼저 판단하고 그 이유를 업그레이드한다. 모르겠으면 둘 다 디벨롭. 썸네일이 9점이면 도입부도 9점이어야 한다.

7. 도입부 30초 + 승인③ 제목·썸네일 약속 회수

레퍼런스 영상의 0~30초를 분석해 우리 도입부를 설계하고, 제목·썸네일·도입부를 한 게이트에서 승인받습니다.
1
레퍼런스 도입부 분석 자동
분석 항목: 첫 문장 / 문제 제기 방식 / 시청자 지칭 / 반전·긴장 형성 / 기대감("A부터 Z까지 알려줄 것 같은 느낌") / 개념 세팅 / 다음 내용을 보게 만드는 표현 → 재사용 가능한 도입부 공식 추출.
출력: Intro30sAnalysis (first_sentence / hook_structure / tension_device / promise_made / curiosity_gap / reusable_intro_formula / adapted_intro_candidates)
2
Second Brain 인사이트 결합 자동
레퍼런스 구조만 쓰면 얕아짐 → 썸끝/원끝·비즈니스 PT·과거 성과 인사이트를 검색해 hook/logic/example/sales_argument/cta로 결합. (구현에서는 별도 status가 아니라 이 단계 카드로 수행)
3
썸네일/제목/도입부 통합 승인 승인③
제목 최종 후보(+대체 3) + 썸네일 9개(또는 선별) + 도입부 후보 + 키 브릿지를 한 번에 검토. 옵션: 승인 / 수정 요청 / 다른 후보 보기 / 레퍼런스 다시 찾기 / 보류. 제목+썸네일 단일 통합 보드는 배선 후속(현재 보드 2개)

원고 승인 승인④

1
녹음 업로드 사람

2

PHASE E — 발행

10. 유튜브 업로드 비공개 초안 → 최종 승인 → 게시

자동 공개는 절대 없습니다. 업로드 초안은 항상 private으로 시작합니다.
1
업로드 초안 생성 자동
brief에서 제목·설명·태그를 결정론 생성 + 확정 썸네일 연결 + 이미지 출처 표기 블록 자동 삽입. visibility=private·approval=pending 강제.
액션: cmo:createUploadDraft (upload_draft→upload_approval 자동 전진)
2
업로드 최종 승인 승인⑥
제목/설명/태그/썸네일/공개 범위(공개·예약) 최종 결정. 옵션: 수정 요청 / 승인 / 예약 설정.
3
실제 YouTube 게시 현재 수동 — videos.insert 미배선
승인 후 실제 업로드는 현재 사장님이 YouTube Studio에서 수동 수행합니다(승인된 메타데이터 복사). OAuth 자격증명·TokenManager는 이미 있으므로 videos.insert 배선이 후속 과제(D3+, 승인⑥이 게이트). 게시 후 썸네일 교체(thumbnails.set)는 이미 구현되어 있습니다.

11. 업로드 후 — 썸네일 A/B · 제목 교체 7일 골든 윈도우

교체 작업은 업로드 후 일주일 안에 끝내야 의미가 있습니다(강의 확정). completed 이후 post-publish 모드로 진입합니다.

11-1. 썸네일 순차 A/B (Track B = 정본)

1
A/B 시작 승인 G2
9개 중 클릭 가설이 다른 3개 선택(예: 확대형 vs 증거형 vs 공감형) + 후보당 기간(기본 2일). 3개×2일=6일로 7일 윈도우 안에 완료(3일×3개=9일은 경고 — validateRotationWindow).
2
순차 교체 + 수집 자동
thumbnails.set으로 A 적용(D3, G2 승인 커버) → 기간 종료 → Analytics 기간별 수집 → B 적용 → … → C까지. 후보별 impressions/CTR/views/watch_time/평균 시청 지속 분리 수집.
3
점수식 + 신뢰도 자동
score = CTR×0.35 + watch_time×0.35 + 평균시청완료율×0.20 + 노출 안정성×0.10 (라운드 내 min-max 정규화). CTR 단독 판단 금지, CTR null이면 가중치 재분배(0.525/0.35/0.125). confidence_level(high/medium/low/insufficient) 필수 기록 — insufficient면 연장.
4
승자 적용 G3 → 패배 원인 디벨롭 → 다음 라운드 G4
판단표: CTR↑+지속↑=승자 / CTR↑+지속↓=낚시성(정직도 조정) / CTR↓+지속↑=훅 강화 / 둘 다↓=전체 재검토 / 노출 부족=연장 / 차이 미미=다른 가설로 재제작. 패배 원인별 규칙(주인공 불명확→확대, 증거 부족→Before/After, 궁금증 부족→정보 숨기기 등)으로 다음 3개 제안. 3라운드 운영: 가설 비교 → 승자 방향 세분화 → 미세 조정.

Track A(YouTube Studio 공식 A/B)는 보조 경로 — API 미공개라 사장님이 Studio 결과를 수동 입력하면 동일 테이블에 저장됩니다.

11-2. 제목 교체 모니터링

업로드 7일 후 조회수 100회 미만이면 제목 교체 권장(shouldSwapTitle, 임계값 설정형 — 신생 채널 보수 기본값). 썸네일도 동일 신호(evaluateThumbnailSwapSignal — 분당 조회수 강의 원기준은 옵션, 기본은 7일 100회 일할 추세). 성과 수집 경로 연결 + 텔레그램 알림 배선은 후속

12. 성과 재학습 다음 기획에 자동 반영

올린 영상의 성과가 Second Brain에 쌓여 다음 프로젝트의 PT 컨텍스트 로딩(2단계)으로 되돌아갑니다.
1
성과 자동 수집 자동 (M5 완료)
YouTube Analytics v2로 영상별 조회수·시청시간·평균 시청 지속·완료율·구독 증감 수집(폴백 사다리: 전체→축소→채널 합계). 수동 입력 경로도 동일 ingest로 유지.
collectVideoPerformance → mapAnalyticsToPerformanceInput → cmo:recordVideoPerformance
2
노출수·CTR Reporting API 리포트 대기 + plugin 배선 잔여
targeted Analytics는 노출/CTR 미지원(실측 확정) → Reporting API channel_reach_basic_a1 경로. 클라이언트(collectImpressionsCtr)는 완성, 구글 리포트 백필 후 plugin 배선하면 ctr/impressions가 채워집니다(그 전까지 null + 사유 표기).
3
완료 인사이트 추출 자동
잘 된 제목·문제·브릿지·썸네일 구조를 인사이트로 추출(usage: hook/intro/pulling/topic/thumbnail_ab) → Second Brain 저장.
extractCompletionInsight · cmo:getCompletedVideoInsights
4
다음 기획에 반영 자동
다음 프로젝트의 PT 컨텍스트 로딩·키/풀링/제목 기획 단계에서 참고 자료로 재주입 → 루프 완성.

13. 사장님이 손대는 곳 총정리

아래를 제외한 모든 단계는 AI가 초안까지 자동으로 만듭니다.
구분무엇을언제
상품 정의 승인8섹션 상품 정의 + 최종 검색 키워드실검색 시작 전
