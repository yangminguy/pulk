🎯 Viewtrap 활용 기획 — 콘텐츠 기획에 어떻게 쓸까

L5 CMO · 키 콘텐츠 & 풀링 기획 통합 · 기준 2026-06-10 · 전제 = CDP로 사장님 로그인 크롬을 화면 밖에서 운전(실증 완료) · 검색→크롤링→분류 자동
1핵심 문제 — 검색 결과는 "의도"가 섞여 있다

검색축(키워드)을 Viewtrap에 넣으면 조회수 높은 영상이 쏟아진다. 하지만 조회수가 높다고 우리 상품을 살 시청자가 보는 주제는 아니다. 같은 키워드 안에 전혀 다른 욕망을 가진 시청자가 섞여 있다.

"같은 '영상 자동화'여도, 쇼츠 수익화를 목적으로 하는 사람이 볼 주제가 있고, 실제 대표들이 자기 마케팅을 자동화하고 싶어서 보는 주제가 있다. 그걸 잘 분류해서 가져와야 한다."

❌ 부적합 — 쇼츠 수익화 시청자

예: "쇼츠 100개 자동 생성해서 월 500 버는 법" · "AI로 떡상 쇼츠 양산"

→ 욕망 = 부업·수익화. 우리 상품 구매자 아님. 조회수 높아도 버린다.

✅ 적합 — 대표/마케터 시청자

예: "대표님 마케팅을 AI가 대신하게 만드는 법" · "1인 사업가 콘텐츠 자동화 시스템"

→ 욕망 = 내 사업 마케팅 자동화. 우리 타깃. 이 주제를 키 콘텐츠로.

결론: 단순 "조회수 5만+ 필터"는 함정이다. 시청자 의도 분류가 먼저, 그 다음 성과 검증이다.

2그래서 Viewtrap을 쓰는 진짜 이유 3가지
목적쓰는 지표/데이터판단
① 타깃 적합성
(가장 중요)		 제목 + 채널명 이 영상을 보는 시청자가 "우리 상품 구매자"인가? 쇼츠 수익화 vs 대표 마케팅 자동화를 제목·채널로 분류.
② 수요 검증 성과도 (구독자 대비 터짐) + 조회수 적합한 주제 중 "구독자 규모를 넘어 터진" 영상 = 그 주제에 실수요가 있다는 증거.
③ 주제 파워 기여도 · 노출확률 이 주제가 채널 성장에 기여하고 알고리즘 확산되는가 = 키 콘텐츠로 키울 가치.

※ 기여도/성과도/노출확률의 Viewtrap 내부 정확 정의는 화면에 툴팁 없음 — 위는 일반적 유튜브 분석 해석. 실배선 전 1회 확정 필요(가이드 페이지 크롤링).

3무엇을 검색하나 — 검색축 설계

키 콘텐츠 워크플로우 Step7(검색 키워드 생성)의 산출물을 그대로 쓴다. 단 의도를 좁히는 게 핵심.

검색축 종류예시 (영상 자동화 상품 가정)의도 좁히기
문제 키워드"콘텐츠 만들 시간 없다", "마케팅 외주 비싸다"타깃 수식어 결합:
"대표"·"사업"·"1인"·"마케팅" 등을 붙여 쇼츠 수익화군과 분리
기능·장점 키워드"AI 콘텐츠 자동화", "영상 자동 생성"

→ 검색축마다 Viewtrap 자동 검색. 결과를 다음 단계(분류)로 넘긴다.

4무엇을 크롤링하나 — 필요한 것만 (전체 340 ✗)

전체를 다 가져오지 않는다. 분류와 검증에 필요한 필드만 뽑는다.

✓ 제목✓ 채널명 ✓ 조회수✓ 성과도 ✓ 기여도✓ 노출확률 ✓ 게시일✓ 썸네일+videoId ✗ CC✗ 구독자 절대수✗ 총영상수

수집 범위 = 성과도/기여도 신호가 좋은 상위 + 타깃 적합 후보. 가상 스크롤 끝까지 긁지 않고, 신호 기준으로 끊는다(과수집 방지).

5어떻게 분류하나 — 시청자 의도 분류 (핵심 엔진)

크롤링한 각 영상을 LLM이 우리 상품·타깃 컨텍스트로 3분류한다.

입력분류처리
제목 + 채널명적합우리 상품 구매자가 볼 주제 → 키 콘텐츠 후보 풀에 넣음
제목 + 채널명모호경계 주제 → 성과도 높으면 사장님 확인용으로 보류 표시
제목 + 채널명부적합다른 욕망(쇼츠 수익화 등) → 제외(조회수 무관)

분류 + 검증 결합: [적합] 중 [성과도 Good]인 주제 = "우리 타깃이 실제로 보고, 실제로 터진" 주제. 이게 키 콘텐츠 후보의 가장 강한 근거다.

6키 콘텐츠 워크플로우 통합 — Step7 → Step8 재설계
7
검색 키워드 생성 (기존, 결정론)
문제·기능 키워드 + 타깃 수식어 → 검색축.
8a
Viewtrap 자동 검색 (신규)
검색축을 화면 밖 크롬 검색창에 자동 입력 → 검색 실행.
8b
필요 필드 크롤링 (신규)
제목·채널·조회수·성과도·기여도·노출확률·썸네일 추출.
8c
시청자 의도 분류 (신규, LLM)
적합/모호/부적합 → 적합+성과 좋은 주제만 추림.
8d
Step8 검증 데이터 자동 주입 (기존 칸 채움)
지금 사장님 수동 입력 → 실데이터로 buildViewtrapValidation 자동 채움.
★
후보 3주제 "viewtrap 선정이유"에 실근거 (개선)
지금은 LLM 추측 → "OO 주제는 △△채널서 구독자 5배 터짐" 실데이터로.
7풀링 콘텐츠도 동일 적용

풀링 워크플로우(Step 0~12)도 같은 엔진을 재사용한다.

  • Step5 풀링 Viewtrap 검증 + Step8 롱테일 노다지: 풀링 검색축(롱테일 포함)으로 자동 검색 → 같은 의도 분류.
  • 풀링은 "키로 끌어오는" 주제라, 분류 기준에 "키 콘텐츠로 브릿지되는가"를 추가.
  • 롱테일 에버그린(must_use)은 성과도보다 꾸준한 검색 수요 신호로 판정.
