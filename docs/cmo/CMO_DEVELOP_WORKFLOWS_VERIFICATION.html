2. CMO 전체 워크플로우에서의 위치

두 디벨롭 모두 새 상태 추가 없이 썸네일 구성 단계(thumbnail_pattern_extraction) 안에서 수행되고, 승인③(hook_draft_approval)에서 사장님이 함께 승인합니다.

풀링 세트 승인→ 썸네일 구성 + 제목 디벨롭
← 여기서 두 디벨롭 실행→ 원고 도입부 30초→ 승인③ 썸네일/제목/도입부→ 원고 기획·작성·승인④→ 녹음→렌더→QA→업로드→ 완료 + 성과 재학습

썸네일 A/B의 Stage F~H(순차 테스트·승자판단·패배원인 디벨롭)는 업로드 이후(post-publish) 구간에서 돌고, 결과가 성과 재학습(R7) 루프로 들어가 다음 라운드 썸네일을 진화시킵니다.

3. 제목 디벨롭 8단계 6/10 추가

감으로 짓던 제목을 "Viewtrap에서 검증된 레퍼런스 2개 → 교차 조합 → 8단계 디벨롭 → 100점 평가"의 검증 가능한 파이프라인으로 교체.

결정론(코드) LLM(Sonnet, 실패 시 그 단계만 폴백) 사장님 승인/입력
입
입력 — 풀링 주제 + Viewtrap 검증 레퍼런스 2개
사장님이 같은 주제/의미 범위의 레퍼런스 2개 입력. 조건: 조회수 5만+ · 성과도/기여도 Good·Great. 풀링 주제 미입력 시 최신 풀링 플랜의 첫 주제 자동 사용.
검
레퍼런스 검증
조회수·등급·주제 유사도 검사. 불합격 시 failed_references(사유 포함) 반환하고 중단 — 잘못된 재료로 디벨롭하지 않음.
조
4종 교차 조합 생성
레퍼런스 2개의 제목·썸네일을 교차: (제목1×썸네일1) (제목1×썸네일2) (제목2×썸네일1) (제목2×썸네일2).
1
1단계 — 어색함 판단
각 조합을 LLM이 감점 누적 방식으로 판단(0점=정상). 어색한 조합은 사유와 함께 탈락 기록.
2~8
2~8단계 — 제목 디벨롭 (단계당 LLM 1콜, 입력/출력/탈락이유 저장)
② 쉬운 단어로 전환 → ③ 상위어로 전환 → ④ 부정어/반대 구조 → ⑤ 수식어 추가(35자 제한) → ⑥ 답이 보이는 제목을 질문이 생기게 → ⑦ 핫비디오 구조로 갈아끼우기 → ⑧ 강한 단어로 변경. 각 단계는 원고 내용과의 일치를 확인하며 진행.
평
최종 100점 평가 (6항목)
타깃 적합 20 + 욕망 선명도 20 + 문제 지적 20 + 호기심 갭 15 + 원고 일치도 15 + 썸네일 결합도 10. ≥85 업로드 후보 / 70~84 수정 / ≤69 레퍼런스 재검색.
승
승인③ — Founder 승인 전 외부 게시 금지
title_development 카드로 저장(approval_status='draft') + 세컨브레인 요약. 확정 제목은 승인④(원고 확인) 화면에도 노출되어 "원고가 제목의 약속을 회수하는지" 검토.
코드 경로 — 도메인 l5-core/cmo-strategy/title-development{,-types,-llm}.ts · 스킬 cmo.title.development (pulling.plan 의존 → script.write로 연결) · 액션 POST /api/cmo:proposeTitleDevelopment · UI TitleDevelopmentBoard.tsx(표시 전용, 도메인 로직 없음)

B
Stage B — 클릭 이유 심리분석 3단계 analyzeThumbnailPsychology
후보별 ① 문구 구조(이득/손해/비밀/반전/증거/비교/금지/숫자) → ② 이미지 연상(얼굴/제품/결과화면/전후비교/실패장면/플로우) → ③ 결합 심리("문구+이미지가 합쳐지면 어떤 감정이 생기고, 클릭 이유가 한 방향인가").
C
Stage C — 이미지 소스 수집 + 출처·위험도 collectImageSources · classifyImageRisk
소스 우선순위: 직접촬영(Low) → 무료스톡/CC(Medium) → 구글/뉴스·블로그(High). Critical(민감·사생활·미성년자)은 사용 차단(D4), High 최종 사용은 사장님 승인(D3). 출처표기 블록 자동 생성(buildAttributionBlock) — 영상 설명란에 삽입.
G1
승인 G1 — 9개 기획안 세트 + 이미지 후보
thumbnail_matrix·image_sources 카드로 저장 → ThumbnailMatrixBoard에서 9개 그리드로 확인·승인.
D·E
Stage D·E — 제작 + 검수
기존 buildThumbnailPlan 확장으로 제작 후보화 + 모바일 가독성·데드존 검수. 이후 도입부 30초 → 승인③ → 원고 → 업로드의 기존 흐름으로 합류.

업로드 이후 — 순차 A/B 테스트 루프 (Track B = 정본)

G2
승인 G2 — A/B 시작: 9개 중 3개 선택 + 기간(기본 2일/후보)
1차 라운드는 클릭 이유가 다른 3개(확대형 vs 증거형 vs 공감형) 권장.
F
Stage F — 순차 로테이션 buildSequentialRotationPlan → thumbnails.set(D3)
A 적용 → 2~3일 → Analytics 수집 → B 적용 → 수집 → C 적용 → 수집. 공식 Studio A/B는 API로 버전별 지표 추출 불가 → Track A(수동 입력)는 보조 경로.
G
Stage G — 승자 판단 점수식 scoreAbTestResults + computeConfidenceLevel
score = CTR 0.35 + 시청시간 0.35 + 평균시청률 0.20 + 노출안정성 0.10 (라운드 내 min-max 정규화). CTR 단독 판단 금지 — CTR null이면 가중치를 시청시간에 재분배(0.525/0.35/0.125). 신뢰도: high(노출 5천+·3일+) / medium / low / insufficient(테스트 연장).
G3
승인 G3 — 승자 썸네일 적용
H
Stage H — 패배 원인별 디벨롭 → 다음 라운드 evaluateAbRound
패배 원인 → 다음 액션 규칙: 클릭이유 불명확→이유 통일 / 주인공 불명확→이미지 확대 / 증거 부족→숫자·Before/After / 궁금증 부족→정보 숨기기 / 공감 부족→현실 이미지 / 문구 약함→이득·손해·궁금증 재작성 / 모바일 가독성→글자 축소·대비 강화. 결과는 R7 성과 루프(extractCompletionInsight, usage='thumbnail_ab')로 저장.

승인 G4 — 다음 라운드 3개 시작 (선택)
3라운드 운영: 1차 가설 비교 → 2차 승자 방향 세분화 → 3차 미세 조정(문구축약/이미지확대/대비강화).

5. 남은 것 / 주의

항목내용
제목 디벨롭 라이브 1회 확인thumbnail 단계에 도달한 프로젝트에서 레퍼런스 2개를 넣고 proposeTitleDevelopment 실호출 1회 확인 권장 (코드·dist·테스트는 전부 검증됨).
fallback_count 관찰LLM 단계가 매번 폴백이면 "통과처럼 보이지만 빈약". 결과 카드의 폴백 수가 0~1인지 확인.
A/B Stage F 실운전순차 교체(thumbnails.set)는 실제 업로드된 영상이 생긴 뒤에 라운드를 시작할 수 있음. CTR·노출수는 Reporting API 리포트 백필 후 채워짐(없으면 가중치 자동 재분배로 동작).
