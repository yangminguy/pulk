CMO 콘텐츠 마케팅 워크플로우 — 전체 가이드

상품 하나가 들어오면 → 영상이 나오고 → 성과가 다시 다음 기획에 반영되기까지, AI CMO가 어떻게 일하는지 모든 과정을 단계별로 정리했습니다.

비개발자도 읽을 수 있게 쉬운 말로 적었습니다 · 기준: 현재 코드 실제 구현 (2026-06-10)

📌 한 문장 요약

CMO는 "상품의 장점을 자랑"하는 게 아니라 "고객이 겪는 문제"에서 출발해서, 사람들이 유튜브 홈에서 눌러보고 싶어지는 영상을 기획·제작합니다. 그 과정은 ① 키 콘텐츠(핵심 판매 영상) → ② 풀링 콘텐츠(끌어오는 영상 5개) → ③ 제목·썸네일 → ④ 원고 → ⑤ 영상 제작 → ⑥ 성과 학습 순서로 흐릅니다.

전체 흐름 한눈에

상품 입력→ 키 콘텐츠 기획→ 승인①→ 풀링 5개 기획→ 승인②→ 제목·썸네일→ 승인③→ 원고→ 승인④→ 영상 제작→ 승인⑤→ 업로드 승인⑥→ 성과 학습
사장님 = 사장님이 직접 보고 결정하는 곳 자동 = AI가 초안까지 자동으로 만드는 곳

목차

0. 먼저 알아둘 3가지 개념 1. 전체 25단계 지도 + 승인 6곳 2. 키 콘텐츠 기획 (11스텝) 3. 풀링 콘텐츠 기획 (12스텝) 4. 제목·썸네일 기획 (제목 디벨롭 8단계) 5. 원고 작성 6. 영상 제작 파이프라인 7. 성과 재학습 8. 사장님이 손대는 곳 정리

0. 먼저 알아둘 3가지 개념

이 3가지만 알면 아래 모든 단계가 이해됩니다.
1
키 콘텐츠 vs 풀링 콘텐츠
키 콘텐츠 = 실제로 상품을 파는 핵심 영상(1개). 풀링 콘텐츠 = 아직 상품에 관심 없는 사람을 키 콘텐츠로 끌어오는(pulling) 영상들(보통 5개). 풀링이 사람을 모으고, 키가 판매합니다.
2
소비자 행동 5단계 (현상 → 욕구 → 계획 → 행동 → 보상)
고객은 "문제를 느끼고(현상) → 해결하고 싶어지고(욕구) → 방법을 찾고(계획) → 행동하고(행동) → 결과를 얻는(보상)" 흐름을 탑니다. 콘텐츠 세트 전체가 이 5단계를 자연스럽게 덮도록 기획합니다.
3
유튜브 발굴 = YouTube, 지표 검증 = Viewtrap
아이디어/경쟁 영상을 찾을 때는 YouTube(검색 한도 없음), 그 영상이 진짜 잘 됐는지 성과·노출 지표를 확인할 때는 Viewtrap(횟수 제한 있음)을 씁니다. Viewtrap 검색은 사장님이 직접 하고, AI는 결과를 읽어 분석합니다.

1. 전체 25단계 지도 상태머신

하나의 영상 프로젝트는 아래 순서대로 "단계(status)"를 밟아 나갑니다. 노란색은 사장님 승인이 있어야 다음으로 넘어가는 곳입니다.
#단계이 단계에서 하는 일구분
1전략 대화 시작어떤 상품을, 누구에게, 어떤 목표(상담/판매/대기자)로 팔지 가볍게 확인전략
2비즈니스 PT 로딩그동안 쌓인 강의·컨설팅·후기 자료(Second Brain)를 불러와 기획 원칙 정리전략
3상품/문제 정의상품·타깃·고객 문제·USP·CTA 확정전략
4키 콘텐츠 후보 기획판매 목표를 먼저 정하고 거꾸로, 고객 문제에서 출발한 키 콘텐츠 후보 2~4개 생성전략
5Viewtrap 키 리서치검색 키워드를 뽑아 사장님이 Viewtrap에서 경쟁 영상 검증 (사람이 직접)전략
6키 콘텐츠 확정 승인①근거를 바탕으로 키 콘텐츠 1개 추천 → 사장님 승인승인
7Viewtrap 풀링 리서치소비자 여정 단계별 풀링 후보를 Viewtrap에서 검증전략
8풀링 5개 선별역할별(문제인식·심화·욕구·계획·브릿지) 풀링 콘텐츠 5개 선별전략
9풀링 세트 승인 승인②풀링 5개 세트 + 키 콘텐츠로 이어지는 다리(브릿지) 확인 → 승인승인
10썸네일 구성 + 제목 디벨롭썸네일 후보 + 제목 디벨롭 8단계(아래 4장) 수행제작
11도입부 30초 분석영상 시작 0~30초의 후킹·빌드업 구조 설계제작
12썸네일/제목/도입부 승인 승인③제목·썸네일·도입부 후보 → 사장님 승인승인
13원고 기획승인된 제목으로 원고 구성 설계제작
14원고 작성도입부 + 판매 논리 블록 + 통합 원고 자동 작성제작
15원고 승인 승인④작성된 원고 검토 → 승인 (제목 약속을 원고가 회수하는지 확인)승인
16녹음읽기용 원고로 변환 → 사장님이 녹음 파일 업로드제작
17슬라이드 스펙 생성원고+녹음으로 슬라이드 영상 설계도(SlideDeckSpec) 생성제작
18렌더링설계도를 영상 공장(Factory)에 제출해 실제 영상 생성제작
19QA완성 영상을 전략 일치성 + 품질 기준으로 점검제작
20QA 승인 승인⑤QA 결과 확인 → 승인승인
21업로드 초안제목·설명·태그·썸네일로 업로드 초안 생성 (기본 비공개)발행
22업로드 승인 승인⑥최종 승인 → 공개/예약은 승인 후에만승인
23완료 → 성과 학습성과 기록 후보를 남기고 다음 기획에 반영학습
승인 게이트는 정확히 6곳입니다. ①키 콘텐츠 ②풀링 세트 ③썸네일/제목/도입부 ④원고 ⑤QA ⑥업로드. 이 6곳을 빼면 AI가 알아서 초안까지 진행하고, 6곳에서만 사장님이 멈춰 서서 결정합니다. 승인 없이 외부에 자동 게시되는 일은 절대 없습니다.

2. 키 콘텐츠 기획 11스텝

상품을 실제로 파는 핵심 영상을 기획합니다. "장점 자랑"이 아니라 "고객 문제 역설계"로 판매 논리를 만드는 게 핵심입니다. Step 1~7,10은 AI가 자동 초안, Step 8·9·11은 검증·사장님 몫입니다.
1
일반화 — 기능·특징·장점 정리 자동
상품(아이템)과 그 상품군(카테고리) 각각의 기능/특징/장점을 정리합니다.
출력: item·category 의 features / characteristics / benefits
2
아이템 기능–혜택 연결 자동
이 상품만의 기능이 고객에게 어떤 혜택이 되는지 연결합니다.
3
카테고리 기능–혜택 연결 자동
상품군 전체 수준에서 기능–혜택을 연결합니다 (왜 이 카테고리가 필요한가).
4
문제 도출 — 기능을 거꾸로 자동
"이 기능이 있다는 건, 고객이 이런 문제를 겪는다는 뜻"이라고 역으로 고객 문제를 끌어냅니다. (아이템 문제 + 카테고리 문제)
출력: item_problems[], category_problems[] (각 문제가 어느 기능에서 나왔는지 표기)
5
퍼널 배치 — 5단계에 문제 꽂기 자동
도출한 문제들을 소비자 행동 5단계(현상/욕구/계획/행동/보상)에 배치합니다. 최소 2개 단계는 반드시 채웁니다.
6
진입 단계 결정 자동
키 콘텐츠가 5단계 중 어디서 시작해야 판매 논리가 가장 자연스러운지 정합니다 (현상/욕구/계획 중 택1 + 이유).
7
검색 키워드 도출 자동
Viewtrap에서 경쟁 영상을 찾을 검색 키워드를 뽑습니다.
8
Viewtrap 검증 사람
사장님이 키워드로 Viewtrap에서 경쟁 영상의 성과·구조를 검증합니다 (조회수, 썸네일, 도입부 등).
9
검증 결과 반영 사람
검증으로 얻은 근거를 기획에 반영합니다.
10
판매 논리 완성 자동
최종 판매 논리 6요소를 만듭니다: 문제 제시 → 카테고리 기능·혜택 → 카테고리 필요성 → 내 상품 기능·혜택 → 내 상품 해결 선언 → CTA(행동 유도).
출력: problem_statement / category_feature_benefit / category_need / item_feature_benefit / item_solution_statement / cta
11
키 콘텐츠 확정 승인①
AI가 추천한 키 콘텐츠 1개를 사장님이 승인/수정/다른 후보/보류 중에서 결정합니다.
왜 거꾸로? 보통은 "우리 상품 좋아요"부터 말하는데, 이 워크플로우는 기능 → (역설계) → 고객 문제 → 판매 논리 순서로 갑니다. 그래야 고객이 "내 얘기네"하고 봅니다. — 별도로 키 콘텐츠 후보 3개를 만들어 비교·택1하는 단계도 있습니다.

3. 풀링 콘텐츠 기획 12스텝

아직 상품을 모르는 사람을 키 콘텐츠로 끌어올 영상들을 기획합니다. 콘텐츠 1개가 여러 단계를 담당해도 되고, 세트 전체가 소비자 여정 5단계를 자연스럽게 덮으면 됩니다.
0
키 콘텐츠 판매 논리 불러오기 자동
앞서 확정한 키 콘텐츠의 판매 논리를 기준점으로 가져옵니다 (풀링은 전부 여기로 연결돼야 함).
1
"키 콘텐츠를 볼 준비가 된 사람" 정의 자동
어떤 문제 인식·욕구·계획 수준이 있어야 키 콘텐츠가 먹히는지, 또 아직 준비 안 된 사람은 왜인지 정의합니다.
2
논리적 확장 자동
상품·카테고리·기능혜택·문제·고객 상황에서 가능한 콘텐츠 주제들을 넓게 펼칩니다.
3
문제 축 분류 자동
주제를 6가지 축으로 분류: 증상 / 원인 / 욕구 / 계획 / 오해 / 보상사례. (고정 단계가 아니라 분류 도구)
4
콘텐츠 유형 포트폴리오 자동
한 가지 유형에 쏠리지 않게 콘텐츠 유형을 골고루 배분합니다.
5
풀링 Viewtrap 검증 사람
풀링 주제 후보들을 Viewtrap에서 검증합니다 (주제·핫비디오 구조·노출 확률·오래된 영상의 노출성).
6
핫비디오 구조 템플릿 자동
지금 잘 되는 영상의 제목·구성 구조를 분해해 우리 주제에 끼워 맞출 템플릿으로 만듭니다.
7
노출 확률 후보 사람
Viewtrap의 노출 확률(홈 추천 가능성) 지표로 후보를 평가합니다.
8
롱테일·에버그린 후보 자동
시간이 지나도 꾸준히 노출되는(에버그린) 주제 후보를 추립니다.
9
풀링 주제 점수화 자동
후보 주제들을 점수로 매겨 우선순위를 정합니다.
10
키 연결 문장 검사 자동
각 풀링이 키 콘텐츠로 어떻게 이어지는지 연결 문장을 만들고, 연결이 없으면 통과시키지 않습니다(강제 규칙).
11
소비자 여정 커버리지 평가 자동
세트 전체가 5단계(현상~보상)를 자연스럽게 덮는지 점검합니다. 안 덮이면 경고.
12
풀링 세트 확정 승인②
승인된 풀링 주제들을 묶어 최종 세트를 조립하고 사장님이 승인합니다.

4. 제목·썸네일 기획 제목 디벨롭 8단계

"감"으로 제목을 짓던 걸, 잘 된 레퍼런스 2개를 조합·발전시켜 검증 가능한 제목으로 만듭니다. 결과는 승인③(썸네일/제목)에서 만들어지고 승인④(원고)에서도 함께 봅니다.
입력 조건: 같은 주제의 Viewtrap 레퍼런스 2개가 필요합니다. 각각 조회수 5만 이상 + 성과도·기여도 Good 또는 Great를 만족해야 시작합니다. (조건 미달이면 "추가 레퍼런스 필요"로 멈춥니다.)

1단계 — 4가지 교차 조합

레퍼런스 2개의 제목·썸네일을 4가지로 섞습니다: ①Ref1 썸네일+Ref2 제목 ②Ref1 제목+Ref2 썸네일 ③Ref1 썸네일 문구를 제목으로+Ref2 썸네일 ④Ref2 썸네일 문구를 제목으로+Ref1 썸네일. → 어색한 조합은 이유를 적고 탈락시킵니다.

2~8단계 — 제목을 7번 다듬기 자동(AI 단계마다 1번씩 생각)

2
쉬운 단어로 전환
전문 용어를 타깃이 실제 쓰는 쉬운 말로. 의미가 약해지면 버립니다.
3
상위어로 전환
좁은 단어를 더 큰 욕망의 단어로 넓힙니다. 주제가 흐려지면 되돌립니다.
4
부정어/반대 구조
긍정형을 "손실 회피"형으로. 단, 원고에 근거가 없으면 쓰지 않습니다.
5
수식어 추가
클릭 이유를 선명하게 하는 수식어 추가. 제목 35자를 넘기면 탈락.
6
질문이 생기게 전환
답이 다 보이는 제목에서 정보 일부를 빼 호기심을 만듭니다.
7
핫비디오 구조로 갈아끼우기
지금 잘 되는 영상의 제목 구조에 우리 주제를 치환합니다(베끼지 않음).
8
강한 단어로 변경
약한 단어를 같은 의미의 강한 단어로. 근거 부족하면 한 단계 낮춰 안전 후보도 함께 남깁니다.

욕망 선명도20원하는 게 분명히 드러나는가
문제 지적20고객 문제를 날카롭게 찌르는가
호기심15눌러보고 싶게 만드는가
원고 일치도15제목 약속을 영상에서 실제로 보여주는가
썸네일 결합도10썸네일과 잘 맞는가

85점 이상 바로 업로드 후보 · 70~84점 수정 권장 · 69점 이하 레퍼런스부터 다시. — 최종 제목/썸네일 방향은 승인③에서 사장님 승인을 받습니다.

썸네일 별도: 같은 단계에서 썸네일 후보(카피 + 시각 방향 + 클릭 논리)도 3개 만들어 택1합니다. 제목 디벨롭과 짝을 이룹니다.

5. 원고 작성 자동 초안

승인된 제목을 기준으로 원고를 자동 작성합니다. 4개 묶음으로 구성됩니다.
1
도입부 30초 (Intro 30s)
첫 문장으로 후킹 → 빌드업 문장으로 긴장 → "왜 끝까지 봐야 하는지" 제시. 제목·썸네일의 약속을 여기서 회수합니다.
2
로직 블록 (판매 논리 전개)
문제 제시 → 기존 방식 한계 → 새 관점 → 카테고리 필요성 → 내 상품 연결 → CTA. 각 블록이 소비자 여정 단계를 담당합니다.
3
통합 원고
도입부 + 블록을 하나의 매끄러운 원고로 합치고, 중복을 제거합니다.
4
QA 점검
원고가 판매 논리·말투·CTA를 지켰는지 자동 점검 리포트를 냅니다.

이어서 내 말투 변환(사장님 말투 프로필로 바꾸되 판매 논리·CTA는 보존)을 거쳐, 승인④(원고 승인)에서 검토받습니다. 이때 4장의 확정 제목/썸네일 방향이 함께 보여서 "제목 약속을 원고가 지키는지" 확인할 수 있습니다.

6. 영상 제작 파이프라인 원고 → 영상 파일

승인된 원고가 실제 영상 파일이 되기까지의 흐름입니다. "영상 공장(Factory)"이 실제 렌더링을 담당하고, 우리 시스템은 설계도 전달과 상태 확인을 합니다.
1
녹음 업로드 사람
읽기 좋은 원고로 변환 → 사장님이 직접 음성 파일을 녹음·업로드합니다.
2
슬라이드 설계도 생성 (SlideDeckSpec) 자동
원고+녹음으로 장면별 자막·길이·슬라이드 구성 설계도를 만듭니다.
3
렌더 잡 제출 → 영상 공장 자동
설계도를 영상 공장의 작업 폴더(jobs/)에 제출합니다.
4
상태 추적 (파일 기반)
별도 시스템 없이 파일 존재로 상태를 판단합니다: 잡 파일 생김=대기 → 출력 폴더 생김=렌더링 중 → video.mp4 + 리포트 생김=완료 (오류 파일=실패).
5
완성 영상 QA 자동
파일·길이·해상도·메타 + 전략 일치성·품질 7개 항목으로 점검합니다.
6
QA 승인 승인⑤
QA 결과를 사장님이 확인·승인합니다.
7
업로드 초안 → 최종 승인 승인⑥
제목·설명·태그로 업로드 초안을 만들되 기본 비공개(private/pending). 실제 업로드/공개는 사장님 최종 승인 뒤에만 됩니다. 자동 공개는 절대 없습니다.

7. 성과 재학습 다음 기획에 반영

올린 영상의 성과를 수집해 "무엇이 잘 됐는지"를 다음 기획에 반영합니다.
1
성과 지표 수집 현재 수동 입력
조회수·노출·CTR 등 성과를 기록합니다. (일부 지표는 수동 입력 단계)
2
완료 인사이트 추출 자동
잘 된 제목·문제·브릿지 구조를 인사이트로 뽑아 Second Brain에 저장합니다.
3
다음 기획에 반영 자동
저장된 인사이트는 다음 프로젝트의 키/풀링/제목 기획 단계에서 참고 자료로 다시 들어갑니다 (2장 Step2의 Second Brain 로딩).

8. 사장님이 손대는 곳만 정리

나머지는 AI가 초안까지 자동으로 만듭니다. 사장님은 아래만 보면 됩니다.
구분무엇을언제

승인③썸네일·제목·도입부제목 디벨롭 8단계 결과 확인
승인④원고 (+ 확정 제목 함께 표시)원고가 제목 약속을 지키는지 확인
승인⑤완성 영상 QA영상 품질 확인
