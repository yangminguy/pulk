01 · Overview

한눈에 — 무엇을 만드는가

CMO Video Room은 "마케팅을 몰라도 콘텐츠로 고객을 만드는" 유튜브 설명형 영상을 반자동으로 찍어내는 임원 작업실이다. 창업자는 CMO와 채팅으로 기획하고, 시스템은 각 단계의 산출물을 카드로 쌓으며, 위험한 결정(키콘텐츠 확정·발행)에서만 승인 게이트로 창업자에게 멈춰 묻는다.

핵심 원칙 DESIGN PRINCIPLE

① AI는 전략·대본·Scene JSON을 설계한다(픽셀/영상 생성 ✗). ② 영상은 React 컴포넌트·텍스트·카드·표·자막·음성으로 구성된다. ③ 모든 비즈니스 규칙(풀링 정확히 5개, Viewtrap 증거 없이 키콘텐츠 확정 금지, Second Brain 없이 원고 확정 금지)은 도메인 순수함수가 throw로 런타임 강제한다.

흐름 한 줄 요약:  PT 컨텍스트 로딩 → 상품 전략 → 키콘텐츠 후보 → Viewtrap 리서치 → 레퍼런스 분석 → 키콘텐츠 승인(게이트) → 풀링 5세트 → Second Brain 병합 → 원고 → 녹음 → 슬라이드덱 → 렌더 → QA → 발행 승인(게이트)

02 · System Layers

4계층 구조 — 화면부터 렌더 엔진까지

UI는 도메인 로직을 절대 갖지 않는다. 판단·검증은 전부 l5-core 순수함수에 있고, NocoBase는 그것을 호출·영속화하는 Shell이며, 실제 영상 렌더는 별도 Remotion 프로젝트가 담당한다.

① UI — Founder 화면 apps/founder-ui /video-room

3탭(Strategy · Production · Review&Publish) + 12노드 미니 로드맵 + CMO Chat(좌) + Board(중, 단계별 카드) + Approval Panel(우, 게이트 승인). 버튼이 백엔드 액션을 호출하고 cmoGetProject로 새로고침. 도메인 판단 없음.

② Backend Actions — NocoBase Shell plugin-orchestration · registerCmoResource

15개 cmo: 액션. 인증·ACL·영속화(video_room_cards 등 INSERT)만 담당하고, 판단은 l5-core 도메인 함수에 위임. 검증 throw → 400으로 변환.

③ Domain Brain — l5-core 순수함수 functions/video-room · functions/cmo-strategy

↓  VideoFactoryTransport (job JSON)

독립 프로젝트. Strategy Brief → Script → Scene JSON → Timeline → Remotion Render → 16:9 MP4 + 썸네일 + QA 리포트. CLI(render-final.ts). L5는 transport로 job JSON 작성·validate까지 연결, 실제 렌더(수 분)는 CLI 단계.

↕  persist

04 · CMO Behavior

CMO는 어떻게 말하고 · 정보를 가져오고 · 기획하는가

CMO 대화 엔진(runCmoStrategyTurn)은 CTO 기획 패널과 같은 패턴이다. 현재 단계를 상태머신에서 읽어 STAGE_SCRIPT(25단계 대화 가이드)로 발화를 구성하고, LLM 주입 시 자연어로, 미주입 시 결정론적 폴백으로 동작한다.

🗣️ 어떻게 말하나

  • ①
    상태 인지 발화 — 프로젝트 current_status를 읽어 그 단계의 STAGE_SCRIPT 가이드로 다음 할 일을 제안.
  • ②
    제안→카드 — 발화의 proposal이 해당 stage 카드(video_room_cards)로 저장.
  • ③
    게이트 자동 생성 — 위험 단계 도달 시 approval_gate를 만들고 "승인할까요?"로 멈춤.
  • ④
    ready_to_advance 신호로 UI가 "다음 단계로" 버튼을 노출.

📥 어떤 정보를 가져오나

  • ·
    Business PT Context — 사업의 사람·타깃·규칙(3소스+ 강제).
  • ·
    Viewtrap 리서치 — 외부 유튜브/SNS 레퍼런스(6단계 키워드 전략).
  • ·
    레퍼런스 분석 — 썸네일 패턴·인트로 30초 훅.
  • ·
    Second Brain — 회사 누적 인사이트(썸네일/인트로/원고 구조에 병합).
기획의 강제력: CMO가 "대충" 넘어갈 수 없다. 풀링은 반드시 5개, 키콘텐츠는 Viewtrap 증거가 있어야 확정, 원고는 Second Brain 인사이트가 있어야 확정 — 이 규칙들이 commitStrategyArtifact 액션에서 도메인 함수 throw로 런타임에 거부된다(E2E에서 빈 입력 → 400 확인).

06 · Approval Gates

승인 게이트 — 사람이 멈춰 서는 지점

CMO는 대부분 자율로 흐르되, 되돌리기 어렵거나 외부로 나가는 결정에서만 창업자에게 묻는다. (L5 위험도 모델 D1~D5와 정합.)

🔒 키콘텐츠 승인어떤 콘텐츠로 영상을 만들지 확정. Viewtrap 증거 기반. 잘못 고르면 전체 제작이 헛수고 → 게이트.
🔒 발행 승인 (D4)외부 고객 도달(유튜브 공개). 업로드 초안은 항상 private으로 생성되고, 공개 전환은 창업자 승인 필요.
✓ 자율 구간리서치·대본·녹음·슬라이드·렌더·QA = 내부 작업(D1~D2). per-task 승인 없이 흐름.
