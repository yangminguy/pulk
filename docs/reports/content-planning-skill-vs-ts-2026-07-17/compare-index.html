같은 재료로 만든 승인 보고서 — 코드 방식 vs 스킬 방식

동일한 상품·동일한 실제 YouTube 데이터·동일한 보고서 양식으로 기존 코드와 새 스킬이 각각 키 콘텐츠 승인 보고서를 생성했습니다. 바뀐 건 "생각하는 층(추론)" 하나뿐입니다. 아래는 두 결과물의 실제 차이입니다.

실험 조건 (양쪽 동일)
상품: 가게 손님 늘리기 컨설팅 타깃: 손님 없는 소상공인 사장님 키워드: 소상공인 마케팅 · 가게 손님 늘리는 법 · 장사 잘되는 비결

실제 YouTube 발굴 3키워드 → 시장표 3행·벤치마크 영상 3편(조회수 실측). 자막 스크랩(CDP)은 이번 실행에서 꺼져 있어 양쪽 모두 메타데이터 기반이라 조건은 공정합니다.

1한눈에 보는 결론

코드 방식  보고서 생성 도중 중간 AI 단계가 60초 제한에 걸려 실패했습니다 — final select 실패: claude-cli failed: timeout after 60000ms. 시스템이 조용히 "조회수 상위 3개"로 폴백해, 벤치마크 영상별 '시청자 정체성 분석'이 통째로 빠진 보고서가 나왔습니다. 바로 사장님이 겪으신 "코딩으로 하면 오류가 많다"의 실제 장면입니다.
스킬 방식  같은 데이터로 오류 0건(status: draft, issues 없음)으로 완주했고, 영상마다 정체성 분석(match/partial + 사유)을 붙이고, 풀링 키워드도 2개→3개로 전략 배치까지 제시했습니다.

3무엇이 바뀌었나 — 속을 보면

보고서는 여러 층이 조립됩니다. 스킬이 대체하는 건 "생각하는 층" 하나뿐이고, 데이터·계산·양식은 그대로 재사용합니다.

유지
① 유튜브 발굴 — 실제 조회수·영상 수집(라이브 도구). 스킬은 검색을 안 함.
유지
② 시장 계산기 — 표본·평균/최고 조회수·판정(제외/추천)을 정확히 계산하는 결정론 코드. AI 아님 → 숫자가 절대 틀리지 않음.
교체
③ 생각하는 층 — 어떤 영상이 우리 타깃인지, 판매 논리·추천·키워드 전략. 여기만 거대 하드코딩 프롬프트 → 스킬 카드로 교체.
유지
④ 보고서 양식 — 지금 보시는 HTML 레이아웃(결정론 렌더러). 양쪽 100% 동일.

즉 3단계(정리)에서 창고로 옮기는 건 ③의 낡은 프롬프트 텍스트뿐입니다. ①②④(도구·계산기·양식)와 테스트는 그대로 남아 화면·게이트가 계속 소비합니다.

4정직한 단서

  • 이번 스킬 실행은 ①②(발굴·계산)의 산출을 컨텍스트로 주입받아 ③(추론)만 수행했습니다 — 실제 운영 배선과 동일한 구조(계산기가 스킬을 먹여줌)라 공정합니다.
  • 자막(CDP)이 꺼져 있어 판매 로직·퍼널은 양쪽 모두 메타데이터 추정입니다. 스킬은 이 점을 provenance에 스스로 명시했습니다(지어내지 않음).
  • 코드 방식의 60초 타임아웃은 상시가 아니라 간헐적입니다. 그러나 이 간헐성이 "될 때/안 될 때"를 만드는 불안정성의 정체입니다.
