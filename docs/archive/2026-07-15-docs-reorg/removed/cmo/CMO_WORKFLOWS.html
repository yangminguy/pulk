Workflow ① · 라이브 검증

키 콘텐츠 기획

key-content-draft.ts · runKeyContentWorkflow + key-content-candidates.ts
입력 = 상품·타깃·목표 + 고객 핵심 문제 + 핵심 제안 (1회)
1
일반화 buildItemGeneralization결정론
상품을 "고객 문제 카테고리"로 일반화. 이후 모든 스텝의 뿌리.
2
아이템 기능·특징·장점 buildItemFeatureBenefitMapLLM
내 상품의 기능/특징/장점(F·B·B) 맵.
3
카테고리 기능·특징·장점 buildCategoryFeatureBenefitMapLLM
Step1 일반화 + Step2 입력 → 카테고리 전체의 F·B·B. (Step2∥Step3 병렬, R3)
4
실제 사용자 문제 도출 deriveProblemMapLLM
아이템+카테고리 F·B·B → 시청자가 실제 겪는 문제 후보. 사장님 입력 문제가 출발점.
5
퍼널 기획 buildFunnelPlanningMapLLM
문제 → 인지·관심·욕구·행동 퍼널 단계 매핑.
6
진입 단계 결정 decideKeyContentEntryStageLLM
퍼널 중 이 키 콘텐츠가 진입할 단계 + 근거(rationale).
7
검색 키워드(검색축) generateSearchKeywords결정론
문제·기능 키워드 → Viewtrap 검색축 생성.
8
Viewtrap 검증 buildViewtrapValidation수동
검색축으로 실제 수요 검증. 현재 사장님 수동 입력(R5 자동화는 구조적 한계).
10
판매 논리 buildSalesLogicMapLLM
problem_statement + 해결 약속 + CTA. (Step1~7,10 = 8 progress)
★
주제 후보 3개 생성 generateKeyContentCandidatesLLM
서로 다른 제목 3개 + 썸네일 약속 + 선정이유 4종: viewtrap · feature_benefit · customer_problem · funnel_application.
🔒 게이트: HTML 보고서 새창 → 사장님이 3개 중 1개 선택 → finalizeKeyContentChoice (ApprovedKeyContentTopic)
↓ 확정된 키 토픽 1개 → 풀링 워크플로우 입력

풀링 콘텐츠 기획

입력 = 확정 키 토픽 1개 → 끌어오는 풀링 주제 N개(기본 5)
0
키 판매논리 로드 loadKeyContentSalesLogic결정론
키 콘텐츠 Step10 판매논리를 풀링 출발점으로.
1
키 볼 준비된 시청자 정의 buildKeyReadyAudience결정론
2
논리적 확장 buildLogicalExpansionMapLLM
키 주제에서 논리적으로 뻗어나갈 주변 주제.
3
풀링 문제 축 buildProblemAxisMapLLM
분류 도구(고정 단계 아님).
4
콘텐츠 유형 포트폴리오 buildContentTypePortfolioLLM
5
풀링 Viewtrap 검증 buildPullingViewtrapValidation수동
키 Step8과 같은 판단 모델.
6·7
핫비디오 구조 · 노출확률 buildHotVideoStructureTemplate / buildExposureProbabilityCandidate결정론
viewtrap-tools에서 재사용.
8
롱테일 에버그린 (노다지) buildLongtailEvergreenCandidate강한규칙
must_use 롱테일은 반드시 최종 세트에 포함(미포함 시 throw).
9
풀링 주제 스코어 scorePullingTopic결정론
10
키 연결 문장 강제 buildKeyConnectionSentence결정론

11
소비자 행동 5단계 커버리지 assessConsumerJourneyCoverage결정론
세트가 소비자 여정 전체를 자연스럽게 설명(누락 단계 시 throw).
★
풀링 후보 N개 생성 generatePullingCandidatesLLM
제목 + 선정이유 4종: consumer_stage · bridge_to_key · search_demand · problem_addressed.
12
세트 조립 assembleApprovedPullingContentSet결정론
Step8 노다지 + Step11 커버리지 강한 규칙 재검증.
🔒 게이트: 보고서 → 사장님 풀링 주제 선택 → 세트 확정 (ApprovedPullingContentSet) · 텔레그램 알림(R2)
↓ 확정 키 + 풀링 세트 → 선택 주제별 콘텐츠 제작

콘텐츠 제작 (제목·썸네일·원고)

content-production.ts — 기존 도메인 함수 재활용(재구현 금지)
입력 = 확정 주제 1개 → 제목/썸네일 상세 + 도입 30초 + 전체 원고
A1
썸네일 초안 — 결정론 후보 buildThumbnailPlan결정론
항상 최소 3개 후보 + 추천 + 근거.
A1+
썸네일 카피·시각 보강 proposeThumbnailDraft (LLM)LLM
카피/시각 방향 풍부화(실패 시 base 유지) + recommended 보정.
A2·0
VOC 확보 (카드 / 결정론 폴백)입력
고객의 소리. 비면 buildIntro30s가 throw → 폴백 생성.
A2·1
도입 30초 buildIntro30s결정론
훅·문제 제기 첫 30초.
A2·2
로직 블록 작성 writeLogicBlockPartLLM
본문 논리 블록 3개(카드에 있으면 정규화, 없으면 문제/단계로 생성).
A2·3
원고 통합 integrateScript결정론
도입 + 로직 블록 → 한 편의 통합 원고(IntegratedScript).
A2·4
원고 QA evaluateScriptQa결정론
길이·훅·논리 흐름 자동 점검.
A2·5
말투 매칭 founder-voice (voice-matched)LLM
사장님 말투로 원고 보이스 매칭.
🔒 게이트: ThumbnailPlanBoard / ScriptDraftPanel에서 사장님 편집·확정
↓ 확정 원고 + 도입 + 썸네일 → 영상 제작(Brief)
Workflow ④ · Brief 전달까지 라이브 (R6)

영상 제작 (Brief → Factory → 렌더)

strategy-package · video-execution-brief · factory-handoff · video-factory-transport
입력 = 확정 키+풀링+원고 → 슬라이드 영상
1
전략 패키지 조립 assembleContentStrategyPackage결정론
키 토픽 + 풀링 세트 통합. cross-consistency 검증(서로 다른 전략이면 throw).
2
전략 브리프 strategy-brief (CmoVideoStrategyBrief)결정론
core_message + logic_blocks 채운 CMO 전략 브리프.
3
영상 실행 브리프 buildVideoExecutionBrief검증
title·core_message·full_script·logic_blocks 비면 throw. 소비자 단계 EN 매핑.
4
팩토리 핸드오프 준비 prepareFactoryHandoff검증
validate → valid면 handoff_status='not_sent'.
5
실 Factory 전달 sendBriefToFactory → submitBrief라이브✓
~/ai-slide-video-factory/briefs/<slug>.json 실제 기록 + validate:brief → handoff_status='sent'. (stub=false 검증)
6
슬라이드덱 생성 slide-deck-generator잔여
brief 직접 참조하도록 연결 잔여.
7
렌더 잡 push submitJob잔여
실제 렌더 잡 제출(현재 brief 핸드오프와 분리됨).
8
렌더 상태 폴링 → QA → 업로드 getRenderJobStatus / evaluateScriptQa잔여
렌더 완료 폴링 → 영상 QA → 업로드 초안.
🔒 게이트: 슬라이드 생성·렌더·QA·업로드 발동 버튼(Production/ReviewPublish 보드). E2E 19/19 PASS로 완료 상태까지 주행 확인.
핵심 패턴 (4개 동일): [최소입력 → 스텝 순차(이전 산출물이 다음 입력) → 후보/초안 N개 → HTML 보고서 → 사장님 승인·선택]. LLM 스텝은 실패 시 그 스텝만 결정론 폴백(전체 폴백 아님). 모든 buildXxx는 검증 throw로 품질 강제.
