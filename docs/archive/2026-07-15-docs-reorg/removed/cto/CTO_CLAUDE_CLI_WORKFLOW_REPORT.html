CTO가 Claude CLI를 활용하는 방법 — 작업 보고서

썸네일 9개 A/B 자동화 PRD 구현 과정에서 나온 점검·개선 계획, 남은 일, 그리고 전체 워크플로우 정리

2026-06-11 대상: 비개발자도 이해 가능 백엔드 통합 라이브 작동 검증 완료
먼저, 한 문장으로.
CTO는 "현장 감독"이고, Claude·Codex·Agy(=Claude CLI 3종)는 각자 다른 회사에서 온 외주 개발자 3명입니다. 감독(CTO)이 일을 잘게 쪼개 지시서를 만들면, 외주 개발자들이 각자 격리된 책상(작업 복사본)에서 작업하고, 감독이 실제로 돌려보고 통과한 것만 본 작업물에 합칩니다. 이 보고서는 그 과정에서 (1) 무엇이 삐끗했고 어떻게 고칠지, (2) 앞으로 무엇을 더 할지, (3) 전체 작업 흐름이 어떻게 돌아가는지를 설명합니다.

1점검에서 나온 문제 & 수정 계획

이미 고친 것(소진 오인·검증 게이트·진행표시 등)은 제외하고, 아직 남은 것만 정리했습니다.

문제쉽게 말하면종류어떻게 고칠지(계획)
검증 명령이 너무 까다로웠음 외주에게 "이 정확한 시험지 파일을 풀라"고 했는데, 외주가 파일 이름을 조금 다르게 지어서 "시험지 없음"으로 처리돼 작업이 통째로 버려짐. (감독의 검수 기준이 너무 빡빡했던 셈) 작업방식 검수를 "특정 파일 1개"가 아니라 "그 폴더의 시험 전체"로 돌리도록 규칙화. verify 명령 자동 생성기를 만들어 사람이 실수로 파일명을 박지 않게 함.
외주 2명이 지치면 3번째가 놀고 있음 Claude·Codex가 한도에 걸리면, Agy가 멀쩡히 비어있는데도 일을 안 넘기고 "기다리기"를 선택. 인력을 다 못 씀. 설계결정 대타 순번에 Agy를 포함(3명 로테이션)할지 결정. 단, "정밀한 코드 작성은 Claude가 제일 안전"이라는 기존 원칙과 충돌 → '급할 때만 Agy 대타' 옵션으로 설계 후 적용.
독립된 두 작업을 동시에 못 시킴 서로 상관없는 작업 A·B도 "A 끝나고 B" 식으로 줄세워짐. 정말 따로 노는 작업은 동시에 시키면 더 빠른데, 그걸 표현하는 방법이 어색함. 기능보완 지시서에 "선행 작업 없음"을 명시적으로 표현할 수 있게 함(depends_on: []). 그러면 진짜 독립 작업은 깔끔하게 동시 실행.
운영 프로그램 재시작 시 진행 중 작업이 미아 됨 작업을 돌리던 자동화 프로그램(데몬)을 중간에 껐다 켜면, "진행 중"이던 일이 아무도 안 집는 상태로 붕 뜸. 안정성 데몬이 켜질 때 "진행 중인데 멈춘 일"을 자동으로 '대기'로 되돌려 다시 집게 함(고아 작업 자동 복구).
일부 통합 작업은 외주에 안 맞음 회사 핵심 시스템(NocoBase)의 특정 파일은 손으로 정교하게 패치해야 해서, 외주에게 맡기면 깨질 위험이 큼. 설계결정 그런 민감한 배관 작업은 감독(메인 CTO)이 직접 담당으로 분리. 또는 자동 빌드 스크립트를 붙여 손패치 자체를 없앰.
Codex가 느림 같은 일을 시켜도 Codex가 Claude보다 한참 오래 걸림(정밀 작업+자가 검수 반복). 정책 정밀·핵심 코드는 Claude에 우선 배정, Codex는 병렬로 짐을 나눌 때만 활용(기존 라우팅 원칙 유지·강화). 코드 변경 불필요, 배정 정책으로 해결.
참고 — 이미 고쳐서 여기서 뺀 것들: ① 작업이 성공했는데 "한도 초과"로 오인하던 버그(보고서에 "rate limit"이라는 단어가 들어가면 오작동) ② 검수를 형식(종료코드)만 보던 것 → 실제로 빌드·시험을 돌려 통과해야 합치도록 격상 ③ 진행 중 작업이 화면에 "진행중"으로 표시되게 함 ④ 작업 책상 경로 혼동 ⑤ 시스템 부팅 시 자동화가 못 켜지던 버그. → 모두 적용·검증 완료.

2CTO가 Claude CLI를 굴리는 전체 워크플로우

감독(CTO)이 일을 어떻게 쪼개서 외주(Claude CLI)에 맡기고, 어떻게 검수해 합치는지의 전체 흐름.

🧑‍💼 일하는 3명의 외주 (토큰 풀)
Claude
설계·핵심 구현 담당. 가장 정확. 경로/파일을 잘 지킴.
Codex
테스트·검증 보조. 정밀하지만 느림.
Agy
경량·기계적 작업. 대타로 투입 가능.
· 셋 다 "구독 세션"으로 동작(추가 비용 키 없이)· 각자 일일 한도(토큰 풀)가 있음
1. 요구/PRD
사장님 요청·기획서
"썸네일 9개 A/B 자동화를 만들어줘"
→
2. CTO 두뇌
일을 잘게 쪼갬
단계별 지시서(어떤 외주가·무엇을·검수기준·위험도) 작성
→
3. 작업 대기열
큐에 등록
지시서를 작업 큐에 올림
↓
4. 자동 운영(데몬)
상시 대기하며 큐를 집음
컴퓨터에 늘 떠 있는 자동화. 새 일이 오면 바로 시작
→
5. 격리 책상
작업 복사본(worktree) 생성
원본은 절대 안 건드림. 외주는 복사본에서만 작업
→
6. 외주 실행
Claude/Codex/Agy 호출
지시서대로 코드·문서 작성. 필요하면 테스트는 Codex에 재위임
↓
7. 검수 (핵심 개선)
실제로 돌려본다
빌드·테스트를 진짜 실행해 통과해야만 다음으로. 실패하면 버림
→
8. 합치기
통과분만 본 작업에 병합
동시에 한 여러 작업은 충돌 안 나게 순서대로 합침
→
9. 현황판
사업별 모니터에 기록
어떤 단계가·누가·어떤 상태인지 + 결과물 전체를 사장님이 확인
토큰 한도 관리(예산 루프): 외주가 일일 한도에 걸리면 → 자동으로 다른 외주에게 넘기거나, 다 지쳤으면 회복될 때까지 기다렸다 재시도. 감독(CTO)은 전 과정을 현황판으로 지켜보다, 마지막에 직접 다시 검사하고 본 시스템에 통합합니다.

3개선을 적용하면 — 새로워진 워크플로우

이번에 겪은 문제들을 반영하면 흐름이 이렇게 더 똑똑하고 안전해집니다.

BEFORE — 예전 방식
·
검수를 "형식"만 봄 → 안 돌아가는 코드도 합쳐질 위험
·
보고서에 'rate limit' 단어만 있어도 "한도 초과"로 오인 → 멀쩡한데 15분 대기
·
검수 기준이 특정 파일명에 묶여 취약
·
외주 2명 지치면 3번째가 놀아도 대기
·
진행 중 작업이 화면에 안 보이고, 재시작하면 미아됨
AFTER — 새로워진 방식
✓
실제 빌드·테스트 통과해야만 합침 (적용 완료)
✓
진짜 한도 메시지일 때만 대기 — 오인 없음 (적용 완료)
✓
진행 상태가 현황판에 실시간 표시 (적용 완료)
→
검수를 폴더 전체로 돌려 파일명에 안 묶임 (계획)
→
지친 외주는 즉시 대타로·재시작해도 자동 복구 (계획)
비유로 정리: 예전엔 외주가 "다 했어요"라고 말하면 그대로 믿고 합쳤다면(=형식 검수), 이제는 감독이 그 자리에서 실제로 돌려보고 "진짜 되네" 확인된 것만 합칩니다. 덤으로, 외주가 "지쳤다"고 한 게 진짜인지도 정확히 구분하고, 누가 지금 뭘 하는지 현황판에 다 보입니다.

4제가 이어서 할 일 (남은 작업)

썸네일 A/B PRD를 완전히 완성하려면 — 백엔드 핵심은 이미 라이브로 작동합니다.

이미 끝난 것 (실제 작동 검증 완료)
✓
9개 썸네일 기획 생성 엔진 — 이미지×문구 9조합 + 클릭 심리분석 (도메인 로직)
✓
A/B 점수·승자 판단 엔진 — 클릭률만이 아니라 시청시간까지 종합
✓
유튜브 연동 — 썸네일 교체(승인 게이트) + 기간별 성과 수집
✓
서버 연결 + 라이브 검증 — 실제 호출하면 9개 후보가 진짜로 생성·저장·반환됨
앞으로 할 것
1
화면(founder-ui) — 9개 썸네일 후보를 카드로 보여주고, 사장님이 승인/선택하는 보드. A/B 시작·승자 적용 화면.
2
A/B 실행 연결 — "성과 입력 → 점수 계산 → 승자" 버튼들을 서버 액션으로 연결하고, 유튜브 썸네일 교체를 실제 버튼에 배선.
3
이미지 자동 수집 — 외부(무료/검색)에서 이미지를 가져오고 출처·위험도를 기록(내 영상 캡처는 제외).
4
전체 통합 테스트 — 화면 클릭 → 서버 → 결과까지 한 번에 도는지 끝까지 확인.
위 작업은 위에서 만든 새로워진(검수 강화) 워크플로우로 진행합니다. 화면 작업은 표면이 넓어, 안전하게 단계별로 검수하며 이어갑니다.
