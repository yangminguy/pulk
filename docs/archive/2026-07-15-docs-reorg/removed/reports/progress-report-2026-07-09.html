CTO 판단·실행 하네스 — R/S 트랙 라이브 2026-07-09

진단 결과 "실행은 콜드스타트·직렬, 판단은 1-shot·무근거"였던 개발 파이프라인을 Scout → Plan → 모호성 게이트 → Critic → Execute → Verify → Ledger → Calibrate 폐루프로 재구성했습니다.

  • S1 Plan Grounding — 기획 전 repo 실측 스카우트를 프롬프트에 주입 (추측 대신 실제 코드 기준)
  • S4 스키마 강제+재시도 — LLM JSON 산출 검증 실패 시 원문 첨부 재호출 → 결정론 강등
  • S5 모호성 게이트 — blocking 질문이 있으면 계획을 막고 먼저 질문 (실전에서 실제 작동)
  • S6 완료조건(Acceptance Criteria) — 태스크별 측정 가능한 완료조건 생성 → verifier가 조건별 판정
  • S3 Critic 3관점 패널 — 단순화·리스크·검증가능성 병렬 채점을 승인 카드에 첨부
  • S7 결정 원장 — 예측 vs 실측을 JSONL로 축적 → 보정 제안 스크립트
  • R1~R6 실행 하네스 — command-guard 훅(실세션 위험명령 차단 실증), skills 3종, dev subagent 2종, Workflow 파이프라인, 승인 즉시 kick
