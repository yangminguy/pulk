분리하는 것이 좋은 판단

의미 분할, 슬라이드 주장, 증거 선택, 레이아웃, 모션, 자막, 사운드는 서로 다른 전문 판단입니다. 분리하면 각 결과를 독립적으로 검토할 수 있습니다.

분리하면 안 되는 실행

각 에이전트가 제멋대로 원고를 재해석하거나 새 컴포넌트를 만들면 품질과 속도가 모두 떨어집니다. 공통 scene contract, 기존 Factory 컴포넌트, 승인된 원고를 공유해야 합니다.

추천 결론: 스킬을 더 쪼개되, 모든 단계를 직렬로 돌리지 않습니다. `Scene Architect`가 먼저 구조를 확정한 뒤, `Slide Worker`·`Asset Director`·`Motion Director`를 의미 단위별로 병렬 실행하고 마지막에 Slide QA가 합칩니다.

메인 오케스트레이터의 의미 분할 알고리즘

문장 단위가 아니라 “하나의 이해 단위”를 만든다

① 원고와 transcript 정렬

승인 원고를 낭독 영상의 실제 말한 구간과 맞춥니다. 빠진 문장·추가 발화·반복·호흡을 표시합니다.

② 의미 역할 부여

각 블록을 Hook, Problem, Claim, Mechanism, Example, Proof, Contrast, Process, Objection, CTA 중 하나로 분류합니다.

③ 시각화 가능성 판정

구체적 장면·숫자·비교·과정·관계·감정 중 무엇으로 보여줄 수 있는지 결정합니다. 보여줄 수 없으면 얼굴+키네틱 타이포를 기본값으로 둡니다.

④ 슬라이드 단위 묶기

한 블록이 너무 짧거나 화면 주장이 약하면 앞뒤 의미와 합칩니다. 반대로 한 블록에 주장과 증거가 충돌하면 두 장면으로 나눕니다.

⑤ Slideability 평가 후 재분할

주장 한 문장, 시각 증거 하나, 한 가지 초점이 성립하지 않으면 자동으로 merge/split 후보를 만들고, 최종 묶음을 확정합니다.

semantic_unit = { id, source_script_range, transcript_range, narrative_role, assertion, evidence_needed, visual_question, candidate_visual_modes, merge_candidates, split_candidates, slideability_score, confidence }

의미 단위별 Slide Worker가 만드는 것

원고를 화면에 복사하지 않고, 발표용 주장과 증거로 변환

입력Slide Worker의 결정결과
“광고비 없이 판매하려면 고객이 반복해서 묻는 문제를 콘텐츠로 만들어야 한다”Assertion: 광고비보다 반복되는 고객 문제를 먼저 포착해야 한다
Evidence: 질문→콘텐츠→신뢰→판매 흐름		4단계 흐름 슬라이드. 문장 전체를 자막으로 복사하지 않음.
숫자·전후 결과핵심 숫자를 하나만 남기고 비교축 선택전후 카드·카운터·막대 그래프
구체적인 사례실제 이미지·무료 영상·스크린캡처 중 설명력이 가장 높은 매체 선택사례 화면 + 짧은 주석. 출처·라이선스 포함.
추상적인 원칙메타포 또는 관계 다이어그램으로 번역도형·화살표·레이어 구조. 장식용 스톡 영상은 배제.

전문 PT 규칙: 각 슬라이드는 제목이 주제가 아니라 주장이어야 합니다. “콘텐츠 기획법”이 아니라 “광고비를 줄이는 콘텐츠는 고객의 반복 질문에서 시작된다”처럼 말해야 할 내용을 제목으로 올립니다. Assertion–Evidence 구조는 전통적인 주제–목록형 슬라이드보다 인지 부담을 낮추는 방향으로 연구되어 왔습니다. 관련 연구

효율성 판단: 별도 Motion Director는 전문성을 높입니다. 다만 장면마다 새 에이전트를 호출하지 않고, 의미 단위 묶음 3~5개를 한 작업으로 병렬 처리하며, 단순 장면은 motion=`none` 또는 기존 preset으로 종료해야 합니다. 장식용 애니메이션은 기억을 돕지 못하고 오히려 불필요한 인지 부담을 만들 수 있습니다. 관련 연구

품질 기준: “전문적인 PT 슬라이드” 판정

멋있어 보이는지보다 이해와 설득이 되는지 검사

Assertion

슬라이드가 말하고 싶은 한 문장이 있는가? 제목만 읽어도 주장이 이해되는가?

Evidence

그 주장을 실제로 이해시키는 그림·비교·과정·사례가 있는가? 장식용 이미지가 아닌가?

Coherence

말과 무관한 이미지·텍스트·효과가 제거됐는가? 시각 자료가 설명보다 앞서 나가지 않는가?

Contiguity

설명하는 그래픽과 관련 텍스트가 같은 위치와 타이밍에 있는가? 자막과 그래픽이 싸우지 않는가?

Rhythm

모든 장면이 같은 레이아웃이 아닌가? 의미 전환에 맞춰 얼굴·그래픽·이미지·화면 캡처가 바뀌는가?

Relevance

시청자가 이 화면을 봐야 하는 이유가 있는가? 없다면 talking-head 유지가 더 나은가?

이 기준은 멀티미디어 학습 연구의 coherence·signaling·contiguity·segmenting 원칙과 연결됩니다. 말과 그림을 단순히 많이 넣는 것이 아니라, 관련 정보만 같은 타이밍과 위치에 배치해야 합니다. Mayer 연구 요약

앞으로 Storyboard와 Factory 덱은 이 시스템을 기본값으로 사용

Canvas

Black + Warm Cream

캔버스는 #000000, 기본 잉크는 #DCDBCE. 계층은 새 색을 추가하지 않고 cream alpha 100/64/40/16으로 만듭니다.

Point Color

Orange는 도형에만

#E5511F는 solid fill의 AccentBlock, 타임라인 노드, 작은 eyebrow square에만 사용합니다. 주황색 텍스트와 얇은 주황색 선은 금지합니다.

Typography

Three-font hierarchy

영문 디스플레이는 Work Sans 600 uppercase, 메타데이터는 Cutive Mono uppercase, 한국어와 본문은 Pretendard Variable을 사용합니다.

Mark

8-ray Asterisk

슬라이드마다 한 개의 크림색 asterisk mark를 사용할 수 있습니다. 로고·아이콘 세트를 새로 만들지 않고 제공된 mark를 재사용합니다.

다시 정의한 실행 순서

이것이 앞으로의 기준 workflow

1. Pulk에서 영상·원고 업로드

원본 영상과 승인 원고를 등록하고, 기존 title/thumbnail/click reason/CTA 컨텍스트를 불러옵니다.

2. video-production-orchestrator 발동

스크립트 승인 여부를 확인하고 10개 스킬을 정해진 의존성 순서로 실행합니다. 실패한 단계 아래만 멈춥니다.

3. 10개 planning skill 실행

Content Brief부터 Caption Plan까지 만들며, 원고는 master meaning, 낭독 타임코드는 master clock으로 유지합니다.

4. Storyboard Composer가 HTML 생성

각 장면의 읽히는 원고, 시간, 화면 모드, 무료 자산 후보, 애니메이션, 자막, 사운드, fallback, 위험을 시각화합니다.

5. Founder가 storyboard 승인·수정

수정 지시는 scene_id에 연결합니다. 승인 전에는 Factory가 아무것도 최종 제작하지 않습니다.

6. Timeline Assembler → Factory 프리뷰

승인된 계획을 기존 Factory Job으로 변환하고, talking-head·B-roll·graphics·captions·sound를 레이어로 조립합니다.

7. QA → 담당 skill만 재실행

자막 문제는 caption skill, 자산 문제는 asset skill, 장면 의미 문제는 scene skill로 돌아갑니다. 전체 재생성하지 않습니다.

8. 최종 승인 → Final Render → Memory 기록

최종 승인 뒤 고해상도 렌더·완료 기록을 남기고, 명시적으로 승인된 수정만 다음 영상의 스타일 메모리에 반영합니다.

현재 Pulk와 Factory의 역할 분리

기존 구조를 지키면서 새 흐름을 넣는 원칙

Pulk = Control Plane

전략·제목·썸네일·원고 승인·사용자 게이트·AgentSkill 오케스트레이션·스토리보드 HTML·수정 라우팅·렌더 상태 추적을 소유합니다.

Factory = Execution Plane

최종 scene type·medium·duration 선택, scene schema 검증, Remotion 그래픽·자막·오디오·타임라인·렌더·export QA를 소유합니다.

금지: Pulk에 렌더 로직을 복제하지 않습니다. Factory가 승인된 전략을 다시 쓰지 않습니다. 새 mixed-media 필드는 기존 slide-only 작업을 깨지 않는 optional versioned extension으로 추가합니다.
