# SPEC 05 — 비트·샷 검수

> **코드 태스크 T4.** 정적 HTML 하나를 생성한다. 서버를 띄우지 않는다.

## 목적

검수 속도가 아니라 **문장과 화면의 일치**를 최적화한다.

> 이 화면이 이 순간의 말을 가장 빨리 이해시키는가?

---

## 1. 2패스 검수

### 패스 A — 편집 적합성

- 인물·제품·행동이 문장과 일치하는가
- 시청자가 설명 없이도 화면을 이해할 수 있는가
- 직전·다음 샷과 시각적으로 다른가
- 필요한 구간을 충분히 길게 쓸 수 있는가
- 원본음으로 살릴 가치가 있는가

### 패스 B — 근거·권리

- 원본 게시자가 맞는가
- 핵심 주장과 출처가 실제로 연결되는가
- 숫자·연도·인용이 화면과 일치하는가
- 권리 상태와 출처 표기가 기록돼 있는가
- 위험할 경우 대체 화면이 있는가

**`Enter` 연타로 두 판단을 합치지 않는다.**

## 2. 화면 구성

비트 하나가 한 행이다.

```text
b042  02:14.20–02:17.80  evidence  CRITICAL       [ g04 · reveal · energy 4 ]
"티셔츠 한 장이 45만 원입니다."

반드시 보여줄 것: 제품, 실제 가격
피할 것: 일반 러닝 장면, 가격 없는 제품 사진

[A 공식몰 캡처]   [B 광고 12:04–12:09]   [C 직접 만든 비교표]
 official          quotation_review        owned
[강조 카드] "45만 원"

의미 일치     1 2 3 4 5
증거 강도     1 2 3 4 5
앞뒤 다양성   1 2 3 4 5
선택 구간     00:12.4–00:16.8   [ 조정 ]
원본음        mute / moment / quote
```

### 필수 요소

| 요소 | 이유 |
|---|---|
| **나레이션 문장** | 없으면 무엇을 고르는지 알 수 없다 |
| **`purpose` 문구** | 이 샷이 왜 필요한지. 판단 기준이 된다 |
| **막과 에너지 값** | 같은 화면도 build의 설명 컷인지 reveal의 반전 컷인지에 따라 선택과 길이가 달라진다 |
| **출처·권리 배지** | 나중에 문제 될 소재를 지금 거른다 |
| **동영상 실제 재생** | ★ 아래 참조 |

### 동영상은 반드시 재생되어야 한다 ★

**포스터 한 장만 보고 동영상의 사용 가능성을 판단하지 않는다.**

`<video>`에 `#t=source_in,source_out` 프래그먼트를 붙여 해당 구간만 재생한다. 마우스 오버 또는 `Space`로 재생한다.

이게 이 모듈에서 가장 중요한 요구사항이다. 프리뷰 없이 고른 구간은 마감에서 절반이 교체된다.

## 3. 키보드

| 키 | 동작 |
|---|---|
| `1` `2` `3` | 후보 포커스 |
| `Enter` | 선택 |
| `Space` | 재생·정지 |
| `[` `]` | 인점·아웃점 조정 |
| `A` | 진행자 화면으로 지정 |
| `M` | 사진 촬영모션 변경 (parallax↔켄번즈) |
| `R` | 추가 조사 필요 |
| `X` | 원고 수정 필요 |
| `Q` | 원본음 인용 |
| `C` | 계획된 강조 카드 선택·문구 편집 |
| `J` `K` | 이전·다음 비트 |

**선택했다고 자동으로 다음 비트로 이동하지 않는다.** `critical` 비트는 점수와 권리를 확인한 후 이동한다.

`[` `]`로 조정한 인·아웃은 **결정 로그(`review-decisions-<ISO8601>.json`)에 append**되고, `review --apply`가 Z2 구역에 병합하며 `locked_selection: true`로 확정한다. 브라우저는 `shot-plan.json`을 직접 쓰지 않는다.

**`locked_selection`은 사람이 손댄 선택에만 `true`다.** `[` `]`(인·아웃 조정)·`A`(진행자 지정)·`C`(강조 카드)·`M`(촬영모션 변경)은 사람의 명시적 조정이므로 `locked_selection: true`로 기록하고, 재검수·재고정에서 `--force` 없이 보존한다. **후보를 그대로 두고 `Enter`만 눌러 승인하면 `locked_selection: false`** — 앞뒤 리듬이 바뀌면 재검수 대상으로 남긴다(§6). `M`은 사진 샷의 촬영모션을 parallax↔켄번즈로 순환할 뿐이다. **자체 그래픽(모션그래픽 신규 저작)은 검수 키가 아니라 `plan`(Z1)이 만드는 `asset_kind: "motion"` 요청 소관이다.**

## 3.5 마우스 동등 지원 (클릭 선택·버튼) — 1차 동선

> **2026-07-25 Founder 실사용 피드백 반영.** 위 단축키 표는 그대로 유지하되, **마우스만으로 검수를 끝까지 완주**할 수 있어야 한다. 클릭이 1차 동선, 키보드는 숙련자용 가속기다. 버튼·단축키는 **동일한 결정 로그 형식**으로 기록한다(형식이 갈라지면 `review --apply` 병합이 깨진다).

- **클릭 선택** — 후보 카드 프레임 또는 카드의 «이 장면 선택» 버튼 클릭 = 그 후보 선택(`Enter`와 동일: `selection_status: "approved"`, `locked_selection: false`). 선택된 카드는 **굵은 테두리 + 체크마크 + «선택됨» 라벨**로 표시한다. 다른 카드 클릭으로 교체한다.
- **오클릭 방지** — 후보의 **영상 영역 클릭은 재생/정지**, 선택은 카드 프레임 또는 선택 버튼으로 구분한다.
- **선택 후 자동 이동 없음** — 클릭 선택도 §3과 동일하게 다음 비트로 넘어가지 않는다.
- **추천 표시** — 각 비트의 점수 1위 후보에 «AI 추천» 배지(rerank_pending이면 «리랭크 대기» 부가). 나머지는 «대안 N»(교체 소스 후보)으로 라벨링한다.
- **전 기능 버튼화** — 인·아웃(«인 −»/«아웃 +» = `[` `]` 동일 로직·`locked_selection: true`), 촬영모션(드롭다운 = `M` 동일 기록), 비트 헤더의 `A`·`C`·`X`·`R`·`Q` 액션 버튼으로 키보드 없이 모든 결정을 만든다. `C`의 강조 문구는 카드 내 인라인 입력창에서 편집한다.
- **안내·진행** — 상단 고정 바에 «선택 완료 x/y 비트» 진행 표시 + «결정 저장(다운로드)» 버튼 상시 노출 + «?» 도움말(단축키 표 + "선택은 카드 클릭" 안내). 첫 로드 시 1줄 힌트("후보 카드를 클릭해 장면을 선택하세요 · ?=도움말")를 띄운다. 10건 자동 다운로드 제안(§4)은 유지한다.

클릭↔키보드 동선 매핑은 `docs/DIVERGENCE.md`(T4b) 참조. 구현 정본: `src/review/render.ts`.

## 4. 결과 저장

**브라우저는 `shot-plan.json`을 직접 쓰지 않는다.** 검수 결정을 **결정 로그(`review-decisions-<ISO8601>.json`, append-only 증분)**로 남기고, `pipeline review --apply`가 읽어 `shot-plan.json`의 **Z2 구역**에 `writeScoped(Z2)` 병합한다.

결정 로그 한 항목:

```json
{
  "shot_id": "sh0042",
  "source_id": "src_014",
  "source_in": 12.4,
  "source_out": 16.8,
  "selection_status": "approved",
  "rights_status": "permission",
  "source_audio": "mute",
  "photo_motion": { "type": "parallax" },
  "locked_selection": true
}
```

> 위 예시는 `[` `]`로 인·아웃을 조정한 선택이라 `locked_selection: true`다. `Enter`만 눌러 후보를 그대로 승인하면 같은 항목이 `locked_selection: false`로 기록된다(사람 조정 없음). → §3 참조.

강조 카드 선택 시 `asset_kind: "caption_card"`, `rights_status: "owned"`, `emphasis_caption` 확정 기록. 사진 샷은 `review --apply`가 기본 `photo_motion.type: "parallax"`로 채우고, 스토리보드에서 켄번즈로 다운그레이드하면 그 값으로 확정한다.

**`fallback_text`와 `caption_card`를 같은 버튼으로 처리하지 않는다.** 전자는 실패 상태, 후자는 계획된 연출이다.

### 저장·병합 방식

**브라우저에서 JSON을 복사해 사람이 저장하는 흐름은 쓰지 않는다.** 둘 중 하나로 구현한다.

1. `pipeline review --watch` — 로컬에서 결정 로그 변화를 감시해 병합 (권장)
2. 브라우저 다운로드 → `pipeline review --apply <결정로그파일>`

- 결정 로그는 append-only. 브라우저는 **결정 10건마다 자동 다운로드를 제안**한다(`localStorage` 금지 → 손실 창을 10건으로 제한).
- 여러 로그를 인자로 받으면 타임스탬프 순차 적용. 같은 `shot_id` 중복은 나중 것 승리.
- 적용 전 `shot-plan.json.revision`을 HTML에 박힌 값과 대조 → 불일치 시 거부 + diff 출력(`--force`로만 강행).
- `locked_selection: true` 인 기존 선택은 `--force` 없이 덮어쓰지 않는다.

## 6. 검수 종료 조건

**시간 상한을 두지 않는다.** 다음을 만족할 때만 끝낸다.

- 핵심 비트의 의미 일치 4점 이상 (5점 만점)
- 근거 비트의 증거 강도 4점 이상
- 원본 인·아웃을 **실제 재생해 확인**
- 위험도 높은 샷에 대체안 존재
- 훅 30초와 reveal 전체를 연속 재생해 승인
- 같은 화면 크기·같은 원본 반복 해소

이미 승인된 비트는 다시 수집하지 않되, **앞뒤 샷이 바뀌어 리듬이 달라지면 재검수한다.**

## 7. 렌더링

비트 200개 이상이다. 전부 로드하면 느리다.

- `<img loading="lazy">`, `<video preload="none" poster>`
- 썸네일은 CSS로 축소 (base64 인라인 금지)
- 세로 이미지가 섞여도 격자가 무너지지 않게 할 것
- 파일 없음은 회색 박스 + 경고 배지

**`localStorage`를 쓰지 않는다.** 상태는 JS 변수에만 둔다.

## 8. 완료 조건

1. 정적 HTML 하나로 동작한다 (서버 불필요)
2. **동영상 후보가 실제 인·아웃 구간으로 재생된다**
3. `[` `]` 조정이 결정 로그에 append되고 `review --apply` 병합 시 `locked_selection: true`가 된다
4. 선택이 자동으로 다음 비트로 넘어가지 않는다
5. 타임라인 축소 보기에서 자동 경고 6종이 뜬다
6. 결과가 파일로 저장된다 (클립보드 의존 없음)
7. `locked_selection` 선택이 재실행에서 보존된다
8. `motion`·`caption_card`만 있는 비트는 검수 대상과 분모에서 제외된다
