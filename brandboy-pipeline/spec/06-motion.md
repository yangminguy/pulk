# SPEC 06 — 모션그래픽

> **에이전트 작업이다. CLI로 구현하지 않는다.**
> 프롬프트는 `prompts/motion-scene.md`. 사전 검증 P3의 경로에 따라 렌더 방식이 달라진다.

## 목적

소스가 없을 때 빈칸을 메우는 장치가 **아니다.** 실사로 설명하기 어려운 구조·비교·숫자만 더 명확하게 만든다.

---

## 1. 쓰는 경우

성장 전후 수치 비교 · 사건 타임라인 · 퍼널 구조 · 가격 구성 · 고객 행동 변화 · 여러 원인의 관계 · 적용 단계

## 2. 쓰지 않는 경우

- 실제 광고나 제품 화면이 있는데 아이콘으로 대체
- 창업자 발언을 인용할 수 있는데 인물 일러스트 사용
- 화면을 화려하게 만들기 위한 장식
- 글머리표를 순서대로 띄우는 프레젠테이션
- **후보 수급 실패를 숨기기 위한 자동 그래픽**
- 큰 글자 한 줄이면 충분한 반전·숫자·펀치

---

## 3. 화면 종류

```text
chart · timeline · funnel · comparison · map · system · quote · document-highlight
```

`object` 같은 추상 범주가 아니라 **실제 설명 형식**을 기록한다.

`caption_card`는 이 모듈에서 만들지 않는다. `assemble`이 자막 프리셋으로 결정론적으로 생성한다.

---

## 4. 입력

```json
{
  "shot_id": "sh0084",
  "type": "comparison",
  "start": 243.2,
  "end": 249.7,
  "narration": "기존 러닝 브랜드가 기록을 팔았다면...",
  "visual_statement": "왼쪽은 기록·속도, 오른쪽은 감각·문화가 중심인 대비",
  "reveal": [
    { "at_word": "기록", "action": "show_left" },
    { "at_word": "감각", "action": "show_right" }
  ],
  "evidence_ids": ["e031", "e044"]
}
```

**수치 그래픽은 `evidence_id` 없이 렌더하지 않는다** (`motion.requires_evidence_id_for_numbers`).

`at_word`의 실제 시각은 `audio/words.json`에서 가져온다. 이게 그래픽과 나레이션이 붙어 보이게 만드는 지점이다.

---

## 5. 왜 단순한 결과가 나오는가

"이 개념을 설명하는 그래픽"이라고 요청하면 기본값이 나온다 — **가운데 정렬 텍스트, 아이콘 세 개, 페이드 인.** 그건 설명이 아니라 목차다.

원인은 셋 다 입력 문제다.

| 원인 | 해결 |
|---|---|
| 디자인 토큰 없음 | `frame.md`를 프롬프트에 주입 |
| 그림이 지정되지 않음 | `visual_statement`를 필수로 |
| 범용 모드로 호출 | 워크플로우 스킬(`/motion-graphics`)을 명시적으로 켬 |

**움직임 자체가 논리여야 한다.** 장식이면 실패다.

| 개념 | 나쁜 예 | 좋은 예 |
|---|---|---|
| 충성도 축적 | 하트 아이콘 + 숫자 상승 | 저수지에 물이 차오르다 임계선을 넘어 흘러넘침 |
| 세 갈래 전략 | 카드 3장 나란히 | 하나의 길이 세 갈래로 갈라지며 각 폭이 다름 |
| 가격과 가치의 격차 | 막대 두 개 | 나란히 가던 두 선 중 하나만 꺾이며 벌어짐 |

---

## 6. 타이밍

- 내레이션보다 먼저 답을 전부 보여주지 않음
- 핵심 단어에서 해당 요소가 나타남
- 숫자는 `motion.number_hold_min_sec`(1.5초) 이상 유지
- 마지막 `motion.tail_hold_sec`(0.3~0.5초) 정지
- 앞뒤 실사 샷의 방향과 움직임을 고려해 전환

---

## 7. 렌더

**전체 영상을 렌더하지 않는다.** 샷 하나당 5~10초 조각만 만든다.
**수정 중에는 렌더하지 않는다.** 브라우저 미리보기로 확인하고 확정된 것만 렌더한다.

배경 처리는 사전 검증 P3 결과를 따른다.

| 경로 | 방식 |
|---|---|
| A | 투명 배경 렌더(`--format mov`, 알파) → CapCut V3 오버레이 트랙 |
| D | `frame.md` 단색 배경 렌더 → 메인 트랙 배치 |

### hyperframes 툴체인 (실측 2026-07-24)

버전은 **`0.7.71`로 고정**하고 **핀 위치는 `package.json`**이다 — `edit-profile.json`은 *편집 수치* 단일 출처이지 의존성 매니페스트가 아니다. `@latest` 태그는 매 실행 버전이 바뀌어 결정론이 깨지므로 금지한다. 배포 전 `src/`에 미고정 태그가 남지 않았는지 확인한다.

```text
npx hyperframes@0.7.71 lint   <html>                 # 구조 검증 (data-composition-id·트랙 겹침·미등록 타임라인). 실재
npx hyperframes@0.7.71 check  <html>                 # inspect 후속. 헤드리스 시크 → 텍스트 넘침·캔버스 이탈 검출
npx hyperframes@0.7.71 render <html> --format mov    # 투명(알파) 산출. --strict 로 lint 연동
```

- `inspect`는 **deprecated**다. 후속 `check` 서브커맨드를 쓴다.
- `render`의 `--format mov|webm`이 **투명(알파)을 지원**한다. 경로 A(오버레이 V3)는 이 알파 산출을 쓴다. `--strict`를 주면 render 전에 lint가 연동된다.
- 저작 → `lint` → `check` → `render` 순서를 반드시 통과시킨다. `render` 종료코드 ≠ 0이면 해당 샷을 실패로 보고하고 `fallback_text`로 대체하지 않는다.

### 캐시

`visual_statement + type + 길이 + frame.md`의 해시가 같으면 재렌더하지 않는다.
**`frame.md`가 바뀌면 전부 다시 렌더된다.** 의도한 동작이다.

---

## 8. 비중

`ratios.motion`(5~10%)을 기본으로 한다. 10%를 넘으면 확인한다.

- 실제 자료가 부족한 주제를 억지로 만들고 있지 않은가
- 설명이 지나치게 추상적이지 않은가
- 원고를 구체적인 사건과 장면으로 고칠 수 없는가

---

## 9. 완료 조건

- 모든 수치가 근거 카드와 일치한다
- 내레이션의 핵심 단어와 모션이 맞는다
- 모바일 화면에서 읽힌다
- 모션 없이 실사로 보여주는 편이 나은 장면이 없다
- 색·폰트·여백·출처 표기가 `frame.md`와 일치한다
- 같은 `frame.md`로 만든 그래픽 3개의 톤이 동일하다
