# SPEC 07 — 샷 단위 러프컷 조립

> **코드 태스크 T5.** 사전 검증 P2·P3 경로에 따라 출력 방식이 달라진다.
> 편집 문법은 `docs/craft/EDITING-BIBLE.md`, 자막은 `docs/craft/CAPTION-BIBLE.md`.

## 목적

씬 하나를 한 파일로 채우지 않는다. `shot-plan.json`의 인·아웃과 의도대로 **내레이션 위에 샷을 조립**한다.

---

## 1. 트랙 — 10트랙 (V1~V6 · A1~A4)

| 트랙 | 내용 |
|---|---|
| V1 | 메인 B-roll · 공식 영상 · 인터뷰 |
| V2 | 진행자 A-roll · 합성 |
| V3 | 모션 · 문서 강조 · 제품 오버레이 |
| V4 | 기본 자막 |
| V5 | 강조 키워드 · 전체 화면 caption card |
| V6 | 출처 표기 |
| A1 | **연속 내레이션 마스터** |
| A2 | 선택한 원본음 |
| A3 | BGM (비워 둠 — 곡 선택은 사람) |
| A4 | 효과음 · 앰비언스 |

중요한 것은 트랙 개수가 아니라 역할 분리다.

---

## 2. 타임라인

`shot.start`와 `shot.end`를 **그대로 사용한다.** 재계산하지 않는다.

### 동영상
- `source_in` / `source_out`으로 절단
- 앞뒤 `shots.handle_sec`(2초) 핸들을 작업 파일에 보존
- **루프 금지** (`shots.loop_allowed: false`). 부족하면 조립을 실패시키고 보고한다
- 정지 프레임으로 늘리지 않는다

### 이미지
- 자동 켄번즈를 **모든 이미지에 넣지 않는다**
- `shots.still_typical_sec`(2~4초) 초과 시에만, 사진 속 시선·이동 방향에 근거해 패닝
- 문서·가격은 확대와 하이라이트로 읽을 위치를 명시

---

## 3. 편집 문법

### 선행 컷
새 인물·제품·장소는 내레이션보다 0.2~0.5초 먼저 보여줄 수 있다.

### J/L 컷
- 창업자 목소리를 먼저 들려준 뒤 얼굴을 보여줌
- 원본 인터뷰 화면이 끝난 뒤 발언을 잠시 유지
- 다음 장면의 환경음을 먼저 들려 전환

### 크기 변화
`wide → person → product → detail → proof`를 교차한다. 같은 크기가 `shots.same_framing_run_max_shots`(4) 연속이면 경고.

### 전체 화면 강조 카드
- `caption_card` 비트에서만
- 배경은 단색·텍스처·직전 화면의 어두운 정지 중 하나
- `captions.impact_card.hold_sec`(1~3초) 유지 후 **다음 증거 화면으로 연결**
- 실제 강조어보다 `captions.impact_card.lead_sec`(0~0.2초) 먼저 등장 가능
- 같은 스타일을 연속 사용하지 않는다

---

## 4. 원본음

`source_audio`가 `moment` 또는 `quote`인 샷만 A2에 올린다.

- 외국어 발언은 원문 자막과 한국어 번역을 구분
- 원본음 진입 전 BGM을 낮춤
- **내레이션과 원본 발언이 겹치지 않게 한다**
- 광고 음악을 통째로 살리지 않는다
- 발언의 의미를 바꾸는 짜깁기 금지

길이는 `shots.source_audio_sec`(2~9초).

---

## 5. 큐 파일

BGM 트랙을 비워 두는 것에서 끝내지 않는다.

`music-cues.json`
```json
[{ "start": 0, "end": 32.4, "role": "hook-tension", "energy": 3, "note": "가격 공개 직전 잠깐 멈춤" }]
```

**막 경계마다 큐가 있어야 한다.** 자동 조립이 곡을 고르지는 않지만 에너지 전환점과 무음 지점은 표시한다.

`sound-cues.json`
```json
[{ "at": 137.2, "role": "emphasis-soft", "linked_beat": "b042", "required": false }]
```

**모든 강조 자막에 효과음을 넣지 않는다.** 막 전환·결정적 숫자·반전만. 15분 기준 `counts_per_15min.sfx`(10~25개)로 시작하고 필요 없으면 제거한다.

---

## 6. 자막

프리셋은 `frame.md`와 `edit-profile.json`의 `captions`에서 생성한다. **기본 자막 / 키워드 강조 / 전체 화면 카드는 서로 다른 프리셋이어야 한다.**

- 숫자·고유명사·반전어만 색 강조. `captions.keyword.usage_ratio`(15~30%) 범위
- 진행자 화면과 원본 자막을 가리지 않음
- 원본 영상에 이미 자막이 있으면 위치를 조정
- 워터마크를 자르려고 과도하게 확대하지 않음

---

## 7. 출처

`sources/usage.json`에서 **자동 생성한다.**

화면 내 간단 표기 + 최종 자료표(원본 URL · 게시자 · 원본 구간 · 영상 내 구간 · 권리 상태).

> **고위험 자료에만 출처를 표시하는 규칙은 폐기했다. 모든 외부 자료가 역추적 가능해야 한다.**

## 9. 출력 경로

사전 검증 P2 결과에 따른다.

| 경로 | 출력 |
|---|---|
| **A** | CapCut 초안 직접 생성 + 큐 파일 |
| **C** | `0001_sh0042.mp4` 형식 **순번 파일 세트** + SRT + 큐 파일 + 배치 안내 `ASSEMBLY.md` |
| **R** | **DaVinci Resolve OTIO 타임라인** `resolve/<slug>.otio` + 임포트 가이드 `RESOLVE.md` |

경로 C·R에서도 자동 검사와 큐 파일 생성은 동일하게 수행한다.

`--emit`은 **콤마 목록**이다: `capcut|numbered|resolve` (별칭 `both=capcut,numbered`·`all=셋 다`).
**기본값은 `numbered,resolve`** — 사장님 결정(2026-07-25) "Resolve 자동 + CapCut 병행". CapCut 초안(경로 A)은 명시할 때만 생성한다(최신 CapCut은 암호화 신형 포맷이라 초안 자동 생성이 불가 — 실측). 한 타깃이 실패해도 다른 타깃은 진행한다.

### 경로 R — Resolve OTIO

DaVinci Resolve **18.5+가 `.otio`를 네이티브 임포트**한다(무료판 파일 임포트로 충분). 이미터는 `TimelineModel`을 OpenTimelineIO(JSON)로 직렬화해 클립·트랙·타임레인지·마커를 전부 배치한 채 타임라인이 열리게 한다. 시간은 프레임 단위 `RationalTime`(`rate = video.fps`)이고 모든 경계를 `round(t*fps)`로 스냅해 총길이 오차를 ±1프레임 이내로 묶는다. 미디어 참조는 **순수 절대 경로**다(`file://` URL 은 Resolve 임포터가 미발견 처리 — 실측 2026-07-25).

**미디어 스테이징 (사장님 실사용 2026-07-25).** 소스 미디어가 `audio/`·`motion/`·`sources/{a-roll,originals,stills}`·`assemble/work/`에 흩어져 있어 폴더마다 가져와야 하는 번거로움이 있었다(Resolve 는 OTIO 임포트 시 외부 미디어를 자동 링크하지 못한다). 이미터는 타임라인이 참조하는 **모든 미디어(영상·오디오·모션 mov·사진)를 `resolve/media/` 한 폴더로 모으고**(심볼릭 링크 기본, 실패 시 복사 폴백), 각 clip 의 `target_url`을 스테이지된 `resolve/media/` 절대 경로로 바꾼다. 사용자는 `resolve/media/` **한 폴더만 한 번 임포트**하면 전 클립이 자동 연결된다.

- **공유 파일**: 같은 물리 파일을 여러 클립이 참조하면(예: `aroll_001.mp4`를 `sh0017`·`sh0003`이 공유) **한 번만 스테이징**하고 두 클립이 같은 스테이지 파일을 가리킨다.
- **파일명 충돌**: 서로 다른 폴더의 같은 basename 은 원본 경로 해시 프리픽스(`<hash>_<basename>`)로 유일화한다(경로 정렬로 첫 등장이 clean 이름 — 결정적).
- **멱등**: 재실행 시 이미 정합한 심링크/복사는 유지하고 중복 스테이징하지 않는다. `--force` 시 재생성.
- 원본→스테이지 매핑은 `resolve/media-manifest.json`에 남긴다(추적·재실행 멱등).

**트랙 매핑 (모델 10트랙 → OTIO 6트랙 + 타임라인 마커)**

| OTIO 트랙 | 모델 | 내용 |
|---|---|---|
| Video 1 | V1 | 메인 B-roll·공식영상·인터뷰·사진 |
| Video 2 | V2 | 진행자 A-roll·합성 |
| Video 3 | V3 | 모션·사진 촬영모션(알파 mov) |
| Video 4 | V5 `caption_card` | 전체화면 강조 카드 — 렌더 파일 있으면 클립, 없으면 **Gap + 마커(문구)** |
| Audio 1 | A1 | **연속 내레이션 마스터**(통클립·비절단) |
| Audio 2 | A2 | 선택 원본음(`moment`/`quote`) |
| 타임라인 마커 | `music-cues`·A4 `sound-cues`·V6 출처 | 막 경계(구간명+energy)·효과음·출처 표기 |

- **기본 자막(V4)**은 OTIO에 넣지 않는다. `RESOLVE.md`가 `File > Import > Subtitle`로 `captions.srt`를 얹도록 안내한다.
- **V6 출처**는 화면 텍스트(자체 title) 생성이 스코프 밖이라 타임라인 마커로만 역추적 가능하게 남긴다.
- **A3(BGM)**는 비워 둔다(곡 선택은 사람) — 마커의 `music-cue`가 구간·energy를 가리킨다.

**임포트 순서 — 미디어 먼저, 타임라인 나중.** 반대로 하면 클립이 offline 으로 뜰 수 있다. `RESOLVE.md`는 다음을 안내한다: 새 프로젝트 → `File > Import > Media`로 `resolve/media/` 폴더(스테이지된 전 미디어) → `File > Import > Timeline`으로 `resolve/<slug>.otio`(미디어 풀 클립으로 자동 연결) → `File > Import > Subtitle`로 `resolve/captions.srt` → 확인 포인트.

산출물: `resolve/<slug>.otio` + `resolve/media/`(스테이지된 전 미디어) + `resolve/media-manifest.json`(원본→스테이지 매핑) + `resolve/captions.srt` + `resolve/RESOLVE.md`(임포트 가이드).

## 10. 엣지 케이스

- **`selection_status`가 `approved`가 아닌 샷** — 조립 중단. 물음표 클립보다 낫다
- **소스 파일 경로 깨짐** — 조립 중단
- **모션 렌더 실패로 파일 없음** — 해당 샷을 실패로 보고. `fallback_text`로 대체하지 않는다
- **샷이 400개 초과** — CLI 호출을 배치로 나눈다. 인자 길이 제한에 걸린다

---

## 11. 완료 조건

1. A1이 끊긴 씬 파일 묶음이 아니라 **연속 마스터**다
2. 모든 샷의 존재 이유가 `purpose`로 설명된다
3. **루프·정지 프레임으로 부족한 영상을 숨기지 않는다**
4. 도입 30초가 제목·썸네일 약속을 시각적으로 증명한다
5. 진행자·B-roll·원본음·모션이 역할에 따라 교차한다
6. 총 길이가 내레이션 마스터와 ±0.2초
7. 출처 표기가 `usage.json`에서 자동 생성된다
8. `music-cues.json`과 `sound-cues.json`이 출력된다
9. 사람이 CapCut에서 열었을 때 **선택과 마감에 집중할 수 있다**
