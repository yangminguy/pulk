# V4 → V5 변경

품질 기준은 낮추지 않았다. **구현 가능한 형태로 잘랐고, 검증되지 않은 가정을 앞으로 뺐다.**

## 유지 — V4의 핵심 자산

- 세그먼트 → 비트 → 샷 3층 구조
- `hook / build / reveal / punch` 막 구조
- 편집 기준 4종 (EDITING · CAPTION · SOUND · SOURCE)
- 연속 내레이션 마스터, 씬별 정규화 금지
- 유튜브 길이 제한 폐기 + 자막 기반 구간 검색
- `caption_card`와 `fallback_text` 분리
- `critical` 비트 자동 강등 금지
- 후보 점수에서 의미 일치 최우선
- 60초 파일럿 게이트
- 치명 오류 12종, 품질 경고 13종

## 변경

| V4 | V5 | 이유 |
|---|---|---|
| CLI 명령 12개 | **코드 4개 + 에이전트 워크플로우 4개** | `ingest` `evidence` `plan` `harvest` `motion` `caption-pass` `sound-pass` `pilot`은 브랜드마다 달라지는 탐색이다. CLI로 굳히면 예외 처리만 늘어난다 |
| 사전 검증 없음 | **`spec/00-preflight.md` 신설** | Whisper 단어 타임스탬프·CapCut 초안·알파 렌더는 파이프라인 절반이 딛고 선 가정이다. 확인 전에 구현하면 T5에서 발견하고 되돌아온다 |
| 수치가 문서 곳곳에 분산 | **`config/edit-profile.json` 단일 출처** | 40여 개 숫자가 5개 문서에 흩어져 있었다. 코드가 어느 값을 읽어야 하는지 알 수 없다 |
| 멱등성·캐시·타임아웃 명세 없음 | **공통 구현 규약 신설** | 캐시가 없으면 특정 비트만 재수집할 때 API를 다시 부른다. 검수→재수집 루프가 기본 동작이므로 필수 |
| 시간 목표 없음 | **RUNBOOK에 단계별 예산 명시** | 목표가 없으면 계속 무거워지기만 한다 |
| 완료 조건이 산문 | **태스크별 검증 가능한 조건** | "거의 다 됐다"를 판단 기준으로 쓰지 않기 위해 |
| 후보·시간 상한 없음 | **중요도별 탐색 규칙으로 구현** | 원칙은 유지하되 코드가 멈출 조건이 필요하다. `critical`은 상한 없음 + 미달 시 중단, `bridge`는 상위 2개 소스만 |
| 4회 시청 필수 | **첫 3편은 2회** | 소리 없이 보기와 실시간만으로 대부분 잡힌다. 나머지는 편수가 쌓인 뒤 |
| 검수 결과 클립보드 복사 | **파일 저장 방식** | 200개 비트에서 복사 실패는 전량 손실이다 |
| 동영상 후보 포스터 판단 | **실제 구간 재생 필수** | 프리뷰 없이 고른 구간은 마감에서 절반이 교체된다 |

## 추가

- `Shot.locked` — 사람이 확정한 선택을 `--force` 없이 덮어쓰지 않는다
- 원고를 이미 쓴 경우의 **소재 가능성 스캔** (RUNBOOK §3)
- 사전 검증 실패 시 **대안 경로 B·C·D** — 실패해도 멈추지 않는다
- `qc`의 `human_required` 판정 — 자동 판정 불가 항목을 통과 처리하지 않는다

## 비용

- 첫 편은 예산보다 오래 걸린다. 검색어 정확도와 추천 품질이 아직 맞춰지지 않았다
- `critical` 비트가 막히면 파이프라인이 멈추고 사람이 결정해야 한다
- 원본 영상과 자막 저장 공간이 필요하다

이 비용은 제거 대상이 아니라 품질의 조건이다.
