# RUNBOOK — 한 편 제작 순서

사람이 따라가는 문서다. 구현 문서는 `TASKS.md`와 `spec/`에 있다.

담당 표기 — **[나]** 사람 · **[AI]** 에이전트 · **[C]** 코드

---

## 0. 기준 영상 캘리브레이션 [나] · 1회성

이번 편과 가장 가까운 브랜드보이 영상 2~3편을 골라 기록한다.

첫 30초 컷 수 · 진행자 첫 등장 · 챕터 수 · 전체 화면 카드 수 · 원본음 사용 위치 · 평균 샷 길이 · 화면 소스 종류

이 값으로 `edit-profile.json`을 수정한다. **이후 모든 자동 검증이 이 파일을 기준으로 동작한다.**

---

## 1. 주제와 화면 가능성 [나] · G0

- 영상의 목적문
- 가장 비싼 시청자 문제
- 클릭 약속
- 핵심 반전
- CTA
- 공식 화면·인터뷰·제품·숫자 확보 가능성

**화면이 빈약하면 브랜드를 바꾸거나 각도를 수정한다.** 여기가 되돌아가기 비용이 가장 싼 지점이다.

---

## 2. 조사와 원본 수집 [AI] · 90분 · G1

원고보다 **먼저** 원본 저장소를 만든다.

최소 기준 — 공식 영상 10편 이상 · 인터뷰 3편 이상 · 광고 5편 이상 · 제품·가격·퍼널 화면 · 뉴스·독립 검증 자료 · 소비자 반응

**자막 확보가 목적이다.** 90분 인터뷰에서 필요한 건 12초이고, 그 12초는 자막 검색으로만 찾는다.

숫자는 1차 자료 또는 독립 자료로 검증한다.

---

## 3. 원고 잠금 [나] · G2

- `hook` / `build` / `reveal` / `punch` 표시
- 사실 · 타인 주장 · 자체 해석 구분
- 각 문장에 예상 화면 기능 표시
- 진행자 문장 표시
- 원본음 인용 위치 표시
- 강조 키워드와 임팩트 카드 후보 표시

### 원고를 이미 쓴 상태라면

**소재 가능성 스캔을 먼저 돌린다.** 에이전트가 `critical` 문장만 골라 해당 화면이 존재하는지 확인하고 **못 찾은 목록만** 보고한다. 수집은 하지 않는다.

그 목록을 보고 셋 중 하나를 고른다.
① 그 문장을 자료가 있는 주장으로 수정 · ② 자체 그래픽으로 대체 · ③ 그대로 두고 강조 카드로

**비어 있는 채로 다음 단계로 넘어가지 않는다.**

## 4. 내레이션·A-roll [나] + [C] · 30분

- **통으로 연속 녹음.** 씬 단위로 끊지 않는다
- **NG가 나면 3초 쉬고 그 문장을 처음부터 다시** 읽는다
- 강조·멈춤 표시는 대본에만, 자막에 노출하지 않는다
- 진행자 구간을 별도 촬영

```bash

```

산출물 — 연속 마스터 · 단어 시각 · 자막 · `timeline.json`

## 5. 의미 비트 [AI] · 40분

실제 발화 시각을 기준으로 비트를 나눈다. 각 비트에 화면 기능 · 반드시 보여줄 것 · 피할 것 · 핵심 여부 · 검색 의도 · 임팩트 카드 여부 · 원본음 여부.

```bash
pipeline validate --project . --human
```

## 6. 후보 수급 [AI] · 90분

**핵심 비트부터 처리한다.**

1. 훅 전체
2. reveal 전체
3. 숫자·인용·제품
4. build
5. bridge

맞는 화면이 나올 때까지 후보를 추가한다. `critical`이 비면 자동 강등하지 않고 사람에게 넘긴다.

## 7. 스토리보드 승인 ② [나] · 40분 ★

**전체 조립 전, 스토리보드에서 방향을 확정한다.** 스토리보드는 전 비트를 프록시(720p)로 덮고 타이밍이 부착된 검수 HTML이다(다음 절 `pipeline review`가 생성). 60초 파일럿 게이트는 rev5에서 제거됐다 — 게이트는 이제 스토리보드다.

사장님이 **모든 구간을 실제 재생으로** 보고 반복 승인한다(승인 ②).

승인 항목 — 말맛 · 컷 속도 · 자막 크기 · 강조 색 · 진행자 합성 · 음악 에너지 · 출처 가독성

승인된 샷만 고화질로 수급한다(화질 2단, `harvest 3단계`). 디스크는 승인분만 쓴다.

> 이 게이트가 재작업을 막는 가장 큰 장치다. 전체를 조립한 뒤 자막 크기를 고치면 300개 이상의 샷을 다시 손대야 한다.

### `--pilot` — 선택적 첫 구간(spine) 룩체크 (게이트 아님)

전체 조립 전 첫 연속 구간 하나만 먼저 조립해 눈으로 확인하는 스모크 체크다. 승인 게이트가 아니다.

- spine은 **연속 구간 1개.** A1 마스터를 자르지 않고 그대로 쓴다
- samples / 10요소 강제 없음. 캘리브레이션 재측정 없음

## 8. 검수 [나] + [C] · 40분

```bash
pipeline review --project . --watch
```

2패스로 본다. **동영상은 반드시 실제 구간을 재생해서 확인한다.** 포스터만 보고 고른 구간은 마감에서 절반이 교체된다.

`critical`을 먼저 꼼꼼히, `bridge`는 추천안 그대로.

## 10. 편집 패스 [나] · 60분

**한 번에 전부 고치지 않는다. 목적별로 나눠서 본다.**

1. **의미** — 문장과 화면이 맞는가
2. **리듬** — 샷 길이·화면 크기·진행자 리셋이 맞는가
3. **자막** — 말맛·강조·모바일 가독성
4. **사운드** — 원본음·음악·무음·효과음
