L5 Business OS · 개발 현황 브리핑

AI가 운영하는 회사를 만드는 중입니다

L5는 창업자(Founder) 한 명이 AI 임원진과 대화하며 새 사업을 기획하고, 일을 시키고, 실제 코드/문서까지 만들어내는 AI 회사 운영체계입니다. 이 문서는 지금 어디까지 만들었고, 두 가지 작업 방식이 어떻게 돌아가며, 앞으로 어떻게 발전하는지를 비개발자 눈높이로 정리한 것입니다.

기준일: 2026-06-02 · 라이브 운영 중 (NocoBase·ACR·Founder UI·Hermes 상시 가동)

한 문장 비유 — 창업자는 CEO 비서(AI) 한 명에게만 말을 겁니다. 그러면 CEO가 회의를 소집해 마케팅·재무·기술 등 담당 임원(AI)에게 일을 나눠주고, 결과를 직접 검수합니다. 그중 실제 코드를 짜야 하는 일만 별도의 "개발 작업실(ACR)"로 보내 진짜 프로그램을 만들어 옵니다.

이 제품의 두 가지 작업 방식

지금 시스템은 일을 두 갈래로 처리합니다. 들어온 지시가 "생각/기획"이냐 "실제 코드 제작"이냐에 따라 길이 갈립니다.

방식 ① · CEO 기반

생각하고 기획하는 일

마케팅 전략, 가격 분석, 운영 절차, 제품 방향처럼 판단과 문서 산출물이 필요한 일.

  • 담당 임원 AI(CMO·CRO·CFO·COO·CPO 등)가 실제로 분석/기획해서 결과물을 만듭니다.
  • 그 결과물을 CEO AI가 직접 검토해서 통과/수정/창업자에스컬레이션을 결정합니다.
  • 전부 시스템 안에서 끝납니다 (외부로 나가는 게 없음).
방식 ② · CTO / ACR 기반

실제 코드를 만드는 일

"이 기능 만들어줘", "배포 자동화해줘"처럼 진짜 프로그램 코드가 나와야 하는 일.

  • CTO AI가 일을 단계(phase)로 쪼개 ACR(개발 작업실)로 보냅니다.
  • ACR이 실제 코딩 AI를 띄워 코드를 작성·커밋·병합합니다.
  • 위험한 작업은 별도 격리 공간(브랜치)에서만 진행됩니다.

ACR = Agent Control Room. 코딩 AI가 안전하게 코드를 만들고 검증하는 별도 시스템(레포지토리)으로, L5와 약속된 통신(콜백)으로 연결돼 있습니다.

지금 실제로 돌아가는 워크플로우 LIVE · 구현됨

방식 ① — CEO 기반 (생각/기획 작업)

창업자 채팅 지시→ CEO가 해석·사업 추론→ 여러 임원에게 작업 분배→ 임원 AI가 산출물 작성→ CEO가 검토→ 완료 / 재검토 / 창업자 승인
1
창업자가 채팅으로 지시"○○ 사업의 마케팅 메시지를 만들어줘" 같은 자연어 한 줄을 입력합니다.
2
CEO AI가 해석어떤 사업에 대한 일인지 추론하고, 목표·가정·성공 기준을 정리합니다. 애매하면 되묻습니다.
3
작업 분배(decompose)일을 여러 워크스트림으로 쪼개 적합한 임원(CMO/CRO/CFO…)에게 배정합니다.
4
임원 AI가 실제 산출물 생성각 임원(Haiku 모델)이 "나중에 하겠다"가 아니라 실제 분석·기획·초안을 만들어 제출합니다.
5
CEO가 검토(review loop)CEO AI가 결과물을 읽고 통과(approve) / 방향 수정(revise) / 창업자 승인 요청(escalate) 중 하나를 판정합니다.
6
상태 확정 + 과정 기록완료(done)·검토필요(needs_review)·차단(blocked)으로 상태가 정해지고, 임원↔CEO 대화가 인박스에 남아 과정이 보입니다.
창업자에게 올라오는 건 "외부로 메시지를 보내야 할 때"와 "돈을 써야 할 때" 딱 두 경우뿐입니다. 나머지 내부 판단은 CEO가 알아서 처리합니다. (위험도 D1~D5는 내부 신호일 뿐, 승인 게이트가 아닙니다.)

방식 ② — CTO / ACR 기반 (실제 코드 작업)

CTO 작업 생성(queued)→ Hermes가 60초마다 감지→ CTO가 단계로 분해→ ACR로 전달(dispatch)→ 코딩 AI가 코드 작성·커밋→ 검증 후 병합→ L5로 결과 콜백
1
기술 작업이 대기열에 쌓임CEO가 만든 기술 과제(또는 자가치유 재시도)가 "대기(queued)" 상태로 등록됩니다.
2
Hermes 디스패처가 자동 감지60초마다 도는 무인 작업기가 대기 작업을 집어옵니다. (위험도 D1·D2는 자동, D3 이상은 창업자 승인 후에만 픽업)
3
CTO가 단계(phase)로 분해 + 모델 선택조사→설계→구현→검증 식으로 쪼개고, 각 단계에 맞는 AI 모델 등급(T1/T2/T3)을 고릅니다.
4
ACR로 전달 → 실제 코딩 AI 실행ACR이 사업 전용 작업 폴더(repo)에서 코딩 AI(claude)를 띄워 실제 코드를 씁니다. 시간 제한·재시도·산출물 검증이 걸려 있습니다.
5
격리 브랜치에 커밋 후 병합안전한 별도 가지에서 작업하고, 검증을 통과하면 본선(main)에 병합하거나 PR을 만듭니다. 충돌·빈 결과는 검토필요로 보냅니다.
6
L5로 결과 보고(콜백)만료 없는 공유 비밀키로 인증된 콜백이 결과(완료/검토필요/충돌)를 L5에 되돌려주고 화면에 반영됩니다.

실패해도 멈추지 않는 자가치유(self-heal)

작업이 실패하면 원인을 분류해서 — 기술 문제는 CTO가, 기획/권한 문제는 CEO가 복구 지침을 만들어 원래 담당에게 한 번 더 시도시킵니다. 단, 결제·외부발송·인원·브랜드 관련이면 자동 복구하지 않고 창업자에게 올립니다.

현재 개발 상태 요약

완성·라이브 부분 완성·개선 예정 계획됨

✓ 작동 중인 것

  • 창업자 채팅 → CEO 해석 → 임원 실행 → CEO 검토 전 과정 라이브
  • CTO → ACR 연결로 실제 코드 작성·커밋·main 병합 E2E 실증
  • 5개 서비스 상시 무인 가동(부팅 자동시작·크래시 자동재시작)
  • 사업별 작업 폴더(repo) 자동 생성·격리
  • 실패 시 자가치유(CTO/CEO 복구 1회 재시도)
  • 배움 루프: 작업 인사이트 자동 수집 → 검토 → 저장 → 다음 기획에 참고
  • Founder UI(Joinery 라이트 디자인) Vercel 배포 + 모바일 대응

◐ 다듬는 중 / 남은 과제

  • 임원↔CEO 검토가 1회 왕복만 — 다회 협의/팀 협업으로 확장
  • NocoBase 플러그인을 수동 패치 중 — 정식 빌드 파이프라인 필요
  • 임원 실행이 AI 2회 호출이라 응답 지연 여유 확인 필요
  • 자가치유 다회 시도 + 복구 이력 테이블 미구현
  • 로드맵 화면 줌·노드 상세 패널 등 UI 디테일
  • 레거시 데이터 백필(사업 미지정 과거 작업)
