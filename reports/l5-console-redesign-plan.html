L5 — 운영 콘솔 재편 + 종합 산출물 개발 계획

작성 2026-06-02 · 창업자 통증 기반 재우선순위 · 보완 로드맵: reports/l5-collaboration-roadmap.html

0 한 줄 진단

"지시는 되는데, 각 에이전트 결과가 종합되어 나에게 최종 산출물로 오지 않는다. 그래서 다음 세션을 못 간다."

+ UI에 쓰임을 모를 기능이 많고(워크플로 팩토리), 메모리 리뷰는 raw JSON이라 손쓸 게 없고, Control Room은 CTO 작업이 한눈에 안 보인다.

재편 방향: 콘솔을 "지시 → 자동 수행(가시화) → 종합 산출물 → 다음 지시" 한 바퀴가 매끄럽게 도는 루프로. 안 쓰는 건 덜어내고, 핵심 4개(종합·모니터링·메모리 자동화·CTO 현황)만 또렷하게.

② Memory Review → "지식 자동 큐레이션"

지금 (스크린샷)

raw JSON 카드({"id":...,"insight":...}) + [저장]/[폐기] 수동 버튼. 창업자가 일일이 판단 불가. PII 배지만 있고 정리 안 됨.

만들 것

알아서 저장·알아서 폐기. 규칙+LLM이 중복·저품질 자동 폐기, 재사용가치 높으면 세컨 브레인에 자동 append. 창업자는 "이번 주 새로 적립된 지식" 요약만 보고, 원하면 개입.
슬라이스내용공수
P3.1자동 큐레이션 규칙 — 중복(임베딩 유사도)·저품질(길이/구체성)·고PII → 폐기. 고가치 → saved + 세컨브레인 append. (현재 CEO 게이트는 "자동 + 사후 알림"으로 완화)M
P3.2지식 페이지 재설계 — JSON 제거, "이번 주 적립/폐기 요약" + 세컨브레인 링크. 수동 개입은 보조S

주의: 자가수정은 코드/도구를 스스로 바꾸는 D3+ 고위험. 반드시 창업자 승인 게이트 + 변경 미리보기(diff) + 롤백을 함께. "버튼 한 번에 무인 적용"이 아니라 "버튼 → 제안된 변경 → 승인 → 적용"이 안전.

▶ 추천 실행 순서

순서무엇왜
1P0 데이터 초기화 (범위 확정 후)깨끗한 출발
2P1 종합 산출물가장 답답한 통증 해소. "다음 세션" 가능해짐
3P2 실시간 모니터링 + P3② 지식 자동 큐레이션지시 후 안심하고 지켜볼 수 있게 + 메모리 손볼 일 제거
4P3③ Control Room(ACR) + P3④ Tool Requests 자가수정CTO 실행 레이어 가시화·자동화. ACR 어댑터 공유
5(보완 로드맵) 무인 위임 M8 · 채팅 회의 M7위 토대가 받쳐주면 자연스럽게 연결
창업자 결정 필요: ① P0 삭제 범위(chat·memory 포함?) ② 지식 자동 폐기를 어디까지 위임할지(완전 자동 vs 폐기 전 1초 확인) ③ CTO 자가수정 승인 강도(매번 승인 vs D2 이하 자동).

⚠ 리스크 · 원칙

  • 자가수정 = 고위험 — 코드 자기수정은 diff 미리보기 + 승인 + 롤백 없이는 금지. D3+ 게이트 유지.
  • 자동 폐기의 역설 — 좋은 지식을 자동 폐기하면 손실. 폐기는 "보관함(soft delete)"으로 30일 유예 후 영구삭제 권장.
  • 종합 우선 — 화려한 모니터링보다 "결과가 손에 들어오는 것"이 먼저. P1을 절대 뒤로 미루지 않는다.
  • PII 분리 — 종합 산출물·세컨브레인 적립에 고객 PII 혼입 차단(기존 governance).
  • 동기 HTTP 한계 — 종합·모니터링·자가수정은 비동기/SSE 인프라 공유(보완 로드맵 M8.3과 동일 기반).
