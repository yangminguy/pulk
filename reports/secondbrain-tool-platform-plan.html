임원 도구 플랫폼 + 세컨 브레인 양방향 인사이트

목표는 단 하나입니다 — 창업자가 "임원에게 도구를 쥐어주고, 세컨 브레인으로 학습시키고, 함께 방식을 정해 그 도구를 발전시켜라"라는 식의 지시를 내렸을 때 그게 실제로 작동하는 서비스를 만드는 것. 영상 생성기·CMO는 하나의 예시일 뿐, 모든 임원·모든 도구에 통하는 일반 구조로 짭니다.

기준일 2026-06-02 · 코드 진단 기반(executive-llm.ts · plugin-orchestration · memory-loop) · 라이브 시스템 위 증축

한 문장 비유 — 지금 임원 AI는 "혼자 머릿속으로만 생각해서 보고서 한 장 쓰는 직원"입니다. 우리가 만들 건 ① 책상 위에 도구(영상 생성기 등)를 올려주고, ② 회사 공용 지식창고(세컨 브레인)를 읽고 쓰게 하고, ③ 창업자와 여러 번 의논한 뒤 그 도구를 손수 개선하게 만드는 것입니다.
이 기획서가 답하는 진짜 질문 — "창업자가 자연어로 지시하면 CEO가 해석해 CTO에게 넘기고, CTO가 그 수준의 작업을 실제로 구현해낼 수 있는가?"

답(2층 분리):
• 층 A · 사업 산출물(CMO가 영상 생성기로 실제 영상·마케팅 제작) → 도구 런타임만 깔리면 가능. CEO 해석→CTO 전달은 이미 라이브.
• 층 B · L5 플랫폼 자체를 짓는 코드(아래 5개 부품) → 지금은 CTO 자가구현 불가. ① pulk(=L5 본체)는 L5_PROTECTED_PATHS로 ACR이 차단됨(의도적 안전장치) ② 현 ACR은 단일 task→phase 모델이라 플랫폼 코어 설계는 사람 몫.

결론: 이번 기획서의 부품들은 사람(개발팀)이 구현한다. 깔린 뒤부터 "영상 만들어라" 류 사업 작업은 CMO가 자율 수행.

출발점 — 작동시켜야 할 "작업 방식"

창업자가 앞으로 쓸 지시(작업 방식 예시)
"CMO에게 AI 영상 생성기를 도구로 연결해라. CMO는 세컨 브레인 MCP로 마케팅 방법을 학습하고, 비즈니스 PT에서 정한 마케팅·유튜브 콘텐츠 방식을 나와 함께 정한 뒤, 그 방식을 도구에 넣어 발전시켜라."

이 한 줄을 분해하면 5가지 능력이 필요합니다. 이게 이 기획서의 요구사항 전부입니다.

① 도구 바인딩

임원에게 외부 도구(영상 생성기)를 손에 쥐어주고 실제 호출

② 세컨브레인 학습

MCP로 지식창고를 읽어 일에 반영

③ 양방향 인사이트

배운 걸 다시 지식창고에 써서 누적

④ 창업자 협의

방식을 여러 번 주고받아 함께 확정

⑤ 도구 발전

확정한 방식을 코드에 반영해 도구 개선(ACR)

전 임원 공용

CMO 전용이 아니라 모든 임원이 같은 토대를 공유

현재 코드 진단 — 양방향은 "절반"만 있다

이미 배움 루프(learning loop)가 있어 인사이트가 일부 흐릅니다. 하지만 외부 세컨 브레인도, 임원의 도구 사용도 없고, 양방향의 한쪽이 끊겨 있습니다.

능력현재 코드 상태판정
인사이트 쓰기(저장)임원 작업 후 persistTaskInsight가 collectInsights로 자동 추출 → founder_memory에 pending 저장있음
단, 자동추출만 — 임원이 능동적으로 못 씀
인사이트 읽기 → CEOloadFounderMemories가 saved 메모리를 CEO 해석에 주입 (plugin.ts:368)있음
인사이트 읽기 → 임원executive-llm.ts에 메모리 주입 전혀 없음 — CMO가 과거 학습을 못 봄끊김
외부 세컨 브레인(MCP)코드 전체에 MCP 흔적 0. 내부 DB(founder_memory)만 존재없음
임원 도구 호출(tool-calling)임원 = Haiku 1회 호출로 텍스트만. required_tools:[] 항상 빈값, 소비처 없음없음
창업자 ↔ 임원 협의채팅은 CEO하고만, 임원↔CEO는 1회 왕복없음
도구 가치 판단 규칙tool-request.ts — PMF≥60·반복3회 게이트 (줄지 말지 판단만)있음
연결 런타임은 아님
핵심 갭: "양방향"이라 부르려면 ① 임원이 읽고 → ② 일하고 → ③ 다시 쓰는 고리가 닫혀야 하는데, 임원으로의 읽기와 외부 세컨 브레인 연결이 비어 있습니다. 여기가 이번 작업의 심장입니다.

만들 구조 — 5개의 새 부품

기존 라이브 시스템을 갈아엎지 않고, 임원 런타임 옆에 공용 부품을 붙입니다. 모두 전 임원 공용으로 설계합니다.

신규 1 임원 공용 도구 런타임 (Tool-Calling Loop)

임원 실행을 "1회 질문 → 텍스트"에서 "도구를 쥐고 여러 번 호출하는 루프"로 바꿉니다. executive-llm.ts의 runExecutive가 도구 목록을 받아 AI가 호출 → 결과 수신 → 다음 판단을 반복. required_tools 필드가 드디어 실제로 쓰입니다.

임원에게 도구목록 전달→AI가 도구 호출→결과 받기↺다음 판단→산출물

신규 2 세컨 브레인 MCP 게이트웨이 (전 임원 공용)

세컨 브레인을 MCP 서버로 연결하고, 그 도구를 도구 레지스트리에 "공용"으로 등록합니다. 그러면 CMO·CRO·CFO·COO·CPO·CTO·RiskQA 누구나 같은 세컨 브레인에 접근합니다. 권한은 역할별로 스코프(읽기 전용/읽기+쓰기)를 둘 수 있게 합니다.

모든 임원
CMO·CRO·CFO·COO·CPO·CTO·RiskQA
⇄
세컨 브레인 MCP
공용 지식창고

신규 3 양방향 인사이트 버스 (Insight Bus)

끊긴 고리를 닫고 내부·외부 지식을 잇습니다. 읽기: 임원 실행 직전 관련 인사이트를 (내부 founder_memory + 외부 세컨 브레인 둘 다에서) 불러와 프롬프트에 주입. 쓰기: 임원이 insight_to_record로 저장 제안 → CEO 검토 후 → 내부 DB와 세컨 브레인에 적립. Pulk에서 나온 인사이트가 세컨 브레인에 체계적으로 누적되는 것이 이 부품의 1차 목표입니다.

읽기 (recall)
세컨브레인 + founder_memory → 임원·CEO 프롬프트
⇄
쓰기 (write-back)
임원 인사이트 → founder_memory + 세컨브레인

※ PII 분리 원칙 유지: 고객 PII(pii_level:high)는 세컨 브레인에 동기화하지 않음 (현 배움루프의 high 제외 규칙 계승).

신규 4 창업자 ↔ 임원 협의 채널

"나와 함께 정한다"를 위해, 임원이 산출물 대신 질문/제안을 창업자에게 직접 올리고 답을 받아 이어가는 다회 대화 상태를 둡니다. (현 HANDOFF의 "임원↔CEO 1회 왕복 → 다회 협의 확장" 과제와 동일 토대를 쓰되, 창업자까지 포함.)

재사용+증축 신규 5 · 도구 레지스트리 (도구는 임원별로 소속)

중요한 구분 — ACR은 CTO의 도구(코드 작성용)이고, 영상 생성기는 CMO의 도구(별도 로컬 프로젝트)입니다. 즉 임원마다 자기 도구를 가집니다. 도구 레지스트리는 "어느 임원이 / 어떤 도구를 / 어떤 권한으로" 쓰는지를 등록하고, tool-request.ts 게이트를 통과한 도구를 해당 임원의 tool-calling 슬롯(신규 1)에 꽂습니다.

CTO 도구
ACR(코드 작성·커밋·병합) — 라이브
CMO 도구
AI 영상 생성기(별도 로컬 프로젝트)

영상 생성기의 내부 개선은 그 프로젝트 자체에서 일어나고, L5는 그것을 CMO의 도구로 연결·호출·발전 방향 합의를 담당합니다.

예시 프롬프트가 새 구조에서 돌아가는 전체 흐름

1
창업자 지시 → CEO 해석CEO가 "CMO에 영상 생성기 도구 연결 + 세컨브레인 학습 + 협의 후 발전"을 작업들로 분해.재사용: 기존 CEO 해석/분해
2
CTO가 도구 등록·검토영상 생성기 초안을 도구 레지스트리에 등록, tool-request 게이트 통과 → CMO에 바인딩.신규 5 + 재사용 tool-request
3
CMO가 세컨 브레인 학습(읽기)도구 런타임이 세컨브레인 MCP를 호출해 마케팅·유튜브 방법론을 불러와 맥락에 주입.신규 1 + 2 + 3(읽기)
4
창업자와 방식 협의CMO가 "이 포지셔닝/콘텐츠 방식 어떤가요?" 제안 → 창업자 응답 → 합의까지 다회 왕복.신규 4
5
합의 방식을 도구에 반영(발전)확정 방식을 CTO가 ACR로 보내 영상 생성기 코드/설정에 반영·커밋.재사용: CTO→ACR 라이브
6
인사이트 양방향 저장(쓰기)이번에 정한 방식·결과를 founder_memory + 세컨브레인에 누적 → 다음엔 CRO·CFO도 이 지식을 읽음.신규 3(쓰기) — 전 임원 공유

구축 순서 (마일스톤)

M1
임원 공용 도구 런타임모든 신규의 토대. tool-calling 루프 + 도구 레지스트리 골격.검증: 더미 도구를 임원이 실제 호출하는 단위테스트
M2
양방향 인사이트 버스 (내부부터)임원으로의 읽기 주입 + 능동 쓰기. 먼저 내부 founder_memory로 고리를 닫음.검증: 임원 A가 쓴 인사이트를 임원 B가 읽어 반영
M3
세컨 브레인 MCP 게이트웨이MCP 클라이언트 연결 → 공용 도구로 등록 → 버스에 외부 소스 합류.검증: 세컨브레인 read/write E2E, PII 제외 동기화
M4
창업자↔임원 협의 채널다회 대화 상태 + UI.검증: 영상생성기 방식 합의 1사이클
M5
도구 발전 루프 결선합의 → CTO/ACR 코드 반영 → 결과를 다시 버스로.검증: 예시 프롬프트 전체 E2E 통과

무엇을 재사용하고 무엇을 새로 만드나

이미 있음(재사용) 부분 있음(증축) 신규
