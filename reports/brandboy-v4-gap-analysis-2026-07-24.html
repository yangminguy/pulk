03 / TARGET ARCHITECTURE

권장 통합 구조

동일 작업을 두 시스템이 다시 하지 않도록, 판단·승인·실행·검증의 소유자를 하나씩만 둡니다.

① Pulk Control Plane brief, claim/evidence, run state, artifact version, 권리 상태, Founder 승인과 수정 라우팅
② 전문 스킬 scene·asset·caption·sound·rough-cut 판단과 계획 JSON. 원본 파일은 직접 수정하지 않음
③ Factory Execution Plane 단일 timeline, media resolve, EDL 적용, caption·sound mix, Remotion render, export
④ QA Aggregator V4 규칙 + 내레이션 표준 + 권리·출처 + 사람 검수를 모아 PASS/REVISE/BLOCK
V4의 새 역할

새 실행기가 아닌 품질 프로필

  • quality_profile: "brandboy_v4"
  • act/beat/shot/source/rights 확장 계약
  • 컷 밀도·A-roll·스톡·임팩트 카드 기준
  • 공식 원본 우선순위와 자료표 규칙
  • 치명 오류·경고·출고 기준
단일 진실 공급원

누가 무엇을 최종 결정하는가

내용·승인Pulk + Founder원고와 근거를 Factory가 다시 쓰지 않음
시간정리된 narration timeline모든 scene/caption/shot이 같은 master clock 사용
파일 변경Factory executor 1곳스킬별 FFmpeg 덮어쓰기 금지
음량 표준개인 후반작업 표준-15 LUFS, true peak ≤ -1.5 dBFS
출고 판정통합 QA 1곳P0·rights open·decode 실패 중 하나면 BLOCK
CapCut 판단: V4 문서의 “CapCut rough cut”은 현재 Remotion Factory와 실행 엔진이 충돌합니다. 1차 개발에서는 Remotion을 정본으로 유지하고, 사람이 CapCut에서 마감해야 할 때만 EDL + SRT + selected assets + source sheet를 내보냅니다. CapCut 프로젝트 자동생성은 별도 제품 결정 전까지 만들지 않는 것이 안전합니다.

05 / BUILD PLAN

단계별 구현 계획

기존 변경을 보존하면서 최소 범위로 진행합니다. 각 단계는 독립적인 성공 기준을 갖고, 승인된 파일을 재실행이 덮어쓰지 않게 합니다.

현재 상태 고정

두 저장소의 미커밋 변경을 기능별로 분리하고, 실제 동작 기준 브랜치·산출물·환경을 inventory로 고정합니다.

완료 기준
기능별 commit/branch 소유가 명확하고, 기존 32개 집중 테스트+Factory typecheck가 재현됨.
승인: CTO/Risk QA 내부 검토

단일 계약 확정

video_production_v1을 유지하고 Claim, Evidence, Beat, Shot, Source, Usage, Rights를 versioned extension으로 추가합니다. V4 별도 스키마는 만들지 않습니다.

완료 기준
깨진 ID, 근거 없는 critical claim, unknown/blocked rights, timeline gap/overlap이 테스트에서 실패.
승인: Founder가 권리 정책 선택

공식 원본 수급 모듈

YouTube research를 source catalog에 연결하고, 공식 채널·인터뷰·광고·제품·공시 순으로 수집합니다. transcript 검색→preview/contact sheet→candidate clip까지 생성합니다.

완료 기준
샘플 브랜드 1개에서 핵심 비트마다 직접 증거·대체안·출처·원본 인/아웃 확보. 재업로드는 원본 추적용 힌트로만 사용.

내레이션·비트·샷 연결

현재 재테이크 정리 결과를 master clock으로 만들고, 의미 비트와 shot requirement를 단어 시간에 고정합니다. 수동 수정은 immutable patch로 보존합니다.

완료 기준
원고 문장→실제 발화→beat→shot→source 사용구간을 왕복 추적. 허용되지 않은 0.2초 공백/겹침 0개.

자막·사운드 표준 통합

5계층 자막 계약과 voice-first mix plan을 Factory schema에 추가합니다. -15 LUFS/-1.5 dBFS를 단일 출고 기준으로 하고 stem 측정을 저장합니다.

완료 기준
“다시” 자막 0개, 원고 문단 coverage 100%, active speech 구간 BGM ≥18dB 낮음, 두 곡 crossfade·SFX 분포 리포트 생성.

게이트 강제·중복 스킬 축소

스토리보드·권리·파일럿 승인 checksum 없이는 Factory job/final render가 생성되지 않게 합니다. 구형 Factory preproduction을 Pulk 호환 래퍼로 전환합니다.

완료 기준
직접 CLI 실행도 승인 누락 시 차단. 수정 피드백은 owning skill 이하만 무효화. 구형 경로와 새 경로의 이중 산출 0개.

1편 파일럿·운영 전환

60초 파일럿 승인 후 한 편 전체를 제작해 네 번의 시청, 모바일, 전체 decode, 권리 자료표, P0=0을 확인합니다.

완료 기준

07 / APPROVAL MODEL

중복을 없앤 6개 승인 게이트

V4의 G0~G5와 현재 Pulk의 strategy/script/storyboard/pilot/final/publish 승인을 아래 6개로 합칩니다.

G0 방향·화면주제, 클릭 약속, 공식 화면 확보 가능성. 화면이 빈약하면 각도 변경.
G1 근거·권리critical claim 근거와 후보 rights 상태. unknown은 파일럿까지만.
G2 원고 잠금제목 약속, hook/build/reveal/punch, CTA, 읽을 원고 확정.
G3 스토리보드비트·샷·출처·자막·모션·사운드 계획과 100% 원고 coverage.
G4 60초 파일럿실제 A-roll/B-roll/자막/원본음/BGM/SFX/출처를 완성 수준으로 승인.
G5 최종 출고P0=0, rights open=0, 전체 decode, 모바일/전체 시청, source sheet 완료.

  • G2 최종 원고
  • G3 디자인·말맛·컷 속도 방향
