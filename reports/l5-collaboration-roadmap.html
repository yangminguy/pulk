L5 — 자율 협업 + 채팅 회의 로드맵

작성 2026-06-02 · 기준점: M6 임원 위임 + 검증 반복 루프 라이브 통과(advance 122s → resolved/round1) · 본 문서는 다음에 만들 것의 계획서

0 한눈에 — 지금 어디고, 어디로 가나

지금까지는 "백그라운드에서" 임원들이 일하고 위임하는 엔진을 만들었다(M1~M6). 다음 목표는 두 방향이다:

DONEM6 — CEO 경유 임원↔임원 위임 + 검증 반복 루프(결정론 컨트롤러). 라이브 1회 통과.
A. 자율화그 위임 루프를 도구를 쥔 채, 스스로 시작하고, 무인으로 돌게(=후속 1·2·3)
B. 가시화임원들이 창업자 채팅에 직접 들어와 회의하고, 합의가 곧 실행으로(=M7 라운드테이블)
오늘: 위임 엔진(보이지 않음)
→
A 자율 위임(도구·자동발화·무인)
→
B 채팅 회의(임원이 대화 참여)
→
회사가 스스로 회의→합의→분담→실행
핵심 한 줄: "창업자가 채팅에 주제를 던지면 → 관련 임원들이 그 채팅에 들어와 토론하고 → CEO가 합의를 정리해 승인을 받고 → 합의가 그대로 위임·실행으로 떨어진다." A는 실행 엔진, B는 그 입구(대화)다.

A 위임 루프 라이브 자율화 (후속 1·2·3) — 신규 마일스톤 M8

M6 엔진은 이미 돈다. 여기서는 "수동·도구없음·1회"였던 3가지 제약을 푼다. 대부분 기존 코드 배선이라 난이도는 중간.

슬라이스지금만들 것재사용공수
M8.1
worker 도구 활성
(후속 1)		 위임받은 임원(CTO)이 L5_EXECUTIVE_TOOLS off라 도구 없이 글만 산출 플래그 on + secondbrain/video transport env 주입 → CTO가 실제 secondbrain.read 등으로 자료 보고 제작. 동기 HTTP가 길어지므로 라운드 타임아웃·도구 수 가드 동반 buildWorkerTools(), M3/M5 transport, MCP-off claude CLI S
M8.2
ask_executive 자동발화
(후속 2)		 위임은 시드(수동)로만 생성. 채팅으로 CMO를 돌려도 스스로 위임 안 함 임원 tool-loop가 "다른 역할 산출물이 필요하면 ask_executive를 부르라"고 유도(프롬프트+도구 노출). CMO가 막히면 자율적으로 CTO에 위임 → awaiting_delegation → advance M6 ask_executive 도구(이미 executeTask에 배선됨), 첫라운드 도구강제 패턴 M
M8.3
무인 트리거(dispatcher)
(후속 3)		 delegation:advance를 사람이 1회 호출해야 루프가 돈다 Hermes cron이 status=open 위임을 폴링해 자동 advance. 장시간 루프는 동기 HTTP에서 분리(비동기 잡 큐). 완료/에스컬레이션 시 채팅·승인큐로 알림 기존 Hermes launchd cron(1분 주기), task dispatcher 패턴 M
의존: M8.1 → M8.2 → M8.3 순. 8.1만 해도 "도구 쥔 위임"이 되고, 8.2까지면 "스스로 위임", 8.3까지면 "완전 무인". 안전: 무인화할수록 예산(max_rounds)·승인 게이트·비용 상한을 반드시 함께. 외부발신/결제 유발 위임은 기존 창업자 승인 모델 유지.

B 채팅 멀티에이전트 라운드테이블 — 임원이 회의에 들어온다 M7

창업자 요청의 본체. 지금 채팅 role은 founder | ceo 1:1 — 임원은 백그라운드 실행자라 대화에 못 들어온다. 이걸 "회의 참여자"로 승격한다.

F 리스크 · 안전 원칙

  • 비용 폭주 — 무인 위임(A)·다발 회의(B)는 LLM 호출이 곱셈으로 늘어남. → 예산(max_rounds·턴 예산) + 월 비용 상한 + Langfuse 추적을 기능보다 먼저.
  • 동기 HTTP 한계 — 현재 advance·executeTask는 동기(수 분). 회의·무인 루프는 비동기 잡 큐/SSE로 옮겨야 UX·안정성 확보. M8.3과 M7.2가 이 인프라를 공유.
  • 승인 게이트 유지 — 자율화해도 외부발신·결제·고위험(D3+)은 창업자 승인 모델 그대로. 위임·회의 합의가 이걸 우회하지 않게.
  • 결정론 우선 — 루프 제어·종료는 코드, LLM은 "제작/발언/채점"에만. M6에서 검증된 원칙을 M7·M8에 그대로 적용 → 무한루프·CEO 비용폭주 차단.
  • PII 분리 — 회의·위임 맥락에 고객 PII 섞이지 않게(기존 governance). 임원 발언에 PII 유입 차단 검사 추가.
